# UI 动效研究：低保真终端式离散动效

调研日期：2026-08-26。本文档是调研记录，不是已落地的表现方案；一旦团队采纳，正式规范应迁移/收敛进
[`docs/effects/`](../effects/README.md)。

## 方向定义

已收集的 moodboard（PSX / CRT / 科研终端类参考图）方向已经很清楚，不应该再往"普通 UI motion
design"（smooth slide、spring、cards floating、glassmorphism）搜索——那套语言会和现有图明显打架。

统一动效方向定义为：

> **Low-fi Terminal Motion / Discrete Retro-Tech Motion**
> 中文内部叫法：**低保真终端式离散动效**

核心不是"卡顿"，而是：所有 UI 像一台老旧科研终端在刷新、切换、锁定、扫描和偶尔失灵。

Moodboard 里最关键的共同点：

- CRT / phosphor glow
- 硬边矩形
- 青绿 / 黄绿 / 红色单色系
- 功能键式布局
- 低信息层级深度
- 没有现代 UI 那种柔顺的空间运动
- 信息像被机器"写到屏幕上"，不是被设计师优雅地"animate in"

这与《Returnal》的 UI 动效原则接近：官方设计访谈提到他们限制效果、几乎不用 directional motion，
大量内容直接 flicker on/off，并避免多层 popup（会显得"技术过于先进"）；环境动效主要服务于 CRT 感。
（[PlayStation Blog, 2021](https://blog.playstation.com/2021/05/11/unpacking-returnals-ux-design-gameplay-first-ui-retro-futuristic-tech-and-accessibility/)）

## 五条 Motion Principles

这五条可以直接作为整个项目的动效规范。

### 1. Discrete，而不是 Smooth（离散，而不是连续丝滑）

现代 UI：`opacity 0→100` + `position x 20→0` + smooth ease-out。

我们：`OFF → brief signal noise → 70% visible → 1-frame correction → 100% locked`。

视觉感觉是机器状态跳变，而不是物体飘进来。关键词：discrete / stepped / quantized / staccato /
frame-stepped / low-FPS / choppy / snapped。最推荐大量使用 **Stepped + Snapped**。

### 2. Abrupt，但不是 Random（突兀，但必须有机械逻辑）

按钮点击不应该"轻轻缩小 → 回弹"（太现代 App）。更像：`IDLE → SNAP DOWN → FLASH → STATE CHANGES`。

例：`[ INVESTIGATE ]` hover 时边框突然亮起（`[▌INVESTIGATE▐]`）；press 时瞬间反白一帧；selected 后
光标/indicator 固定下来（`> INVESTIGATE_`）。

关键词：snap / hard cut / instant state change / binary transition / mechanical / decisive /
no overshoot。

### 3. Flicker，而不是 Fade（这是最重要的一条）

普通 UI 是 `Fade In 0%→100%`；我们是信号先出现、再稳定（先闪烁几帧不稳定的可见度，再锁定）。

适用场景：新 UI 打开、HUD 启动、档案加载、扫描结果出现、通讯建立、警告信息、系统故障。

关键词：flicker-in / signal stabilization / phosphor flicker / CRT flicker / intermittent /
unstable / signal acquisition。

《Alien: Isolation》尤其值得参考：刻意追求 lo-fi、clunky、glitchy、imperfect 的技术感，甚至把部分
画面经过 VHS/CRT 处理获得不稳定的模拟设备质感。
（[PlayStation Blog, 2014](https://blog.playstation.com/archive/2014/03/26/behind-terror-alien-isolation-exclusive-interview)）

### 4. Machine-Driven，不是 UI-Driven

不要想"这个 Panel 怎么 animate"，而要想"这台设备会怎样显示这个 Panel"。

❌ 现代 UI 思维：`Panel slides in from left`

✅ 我们：`TERMINAL SELECTED → screen region activates → horizontal raster sweep → content snaps
into place → minor flicker → stable`

动效动词应该是：boot / initialize / acquire / lock / scan / write / refresh / decode /
synchronize / stabilize / interrupt / drop / reconnect——而不是 float / bounce / drift / morph /
gently reveal。

### 5. Imperfect，但 Controlled

可以有 glitch / jitter / scanline / signal noise / frame skip，但不建议"每个东西都 glitch"，否则
玩家会困惑"这台机器到底什么时候是好的"。

正确的 hierarchy：

| 状态 | 表现 |
|---|---|
| Normal | SNAP + tiny flicker |
| Processing | scan / write / progressive reveal |
| Weak signal | jitter + intermittent disappearance |
| System interference | horizontal displacement + frame tearing |
| Critical failure | hard interruption + signal collapse |

**Glitch 应该表示异常状态，不应该成为默认 transition。** 《Returnal》同样是这个思路：常规界面克制，
只有 damage / critical state 才用 visor crack、digital glitch、warning 等更强反馈。
（[PlayStation Blog, 2021](https://blog.playstation.com/2021/05/11/unpacking-returnals-ux-design-gameplay-first-ui-retro-futuristic-tech-and-accessibility/)）

## 动效语法

### A. Appearance（出现）

**① Snap-on** — 最基础、最常用。`OFF → CONTENT`，可带 1-frame flash。用于 tooltip、interaction
prompt、HUD icon、小提示。关键词：snap-on / hard reveal / instant acquire。

**② Flicker-lock** — 最有代表性的出现方式：屏幕像正在锁定信号，逐步从空白/噪点收敛到完整内容。
用于大页面、terminal、archive、system boot、通讯连接。关键词：flicker-lock / signal lock /
intermittent reveal / stabilization。

**③ Raster reveal** — 横向扫描出现，扫描线过去后内容被"写入"。适合 Official Record、新区域数据、
官方结论、系统加载。关键词：CRT raster sweep / scan reveal / horizontal wipe / electron beam scan。

**④ Terminal write** — 不是 typewriter 的文学感，而是机器写入：`STATUS: → STATUS: ANA →
STATUS: ANALYSING...`。不建议逐字符慢慢出现（太 cliché、太慢），更适合 **character burst /
chunked typing**：一次性跳到一大截文字（如 `ANALYS` → `ANALYSIS COMPLETE`）。适合调查数据、官方结论、
日志、通讯字幕、系统处理。

### B. Disappear（消失）

不要 `Panel → smooth fade → gone`，用以下三种：

- **Hard Cut**（正常关闭）：`CONTENT → OFF`
- **Signal Drop**（信号弱）：`CONTENT → CONTENT broken → horizontal tear → OFF`
- **Collapse**（被打断）：逐帧变成更多噪点方块直至全黑。适合无线电中断、HUD 干扰、生物信号消失、
  污染导致系统故障。

关键词：signal drop / signal collapse / interruption / horizontal tear / frame loss。

### C. 组件级动效（consistency 最关键的地方）

**Button** — Snap + Flash。Hover：边框直接点亮；Pressed：反白/brightness jump 1–2 帧；
Selected：固定 indicator。绝对不要 bouncy / springy / elastic / squishy。

**Tab** — Hard Cursor Jump：indicator 直接跳到新位置，不做 `TAB A ──→ TAB B` 式的平滑滑动，可以带
一点 frame-stepped 的感觉。关键词：cursor jump / hard switch / stepped navigation。

**Progress Bar** — 不要 smooth fill，用逐 block 更新的 quantized progress（`██████████░░░░░░` →
`████████████░░░░` → ...）。非常适合 PSX/终端感。

**Numbers** — 不要平滑滚动，用短暂的 readout jitter（几个不相关的数字跳动）后再 settle 到目标值。
适合污染等级、生物数据、信号强度、环境数值。关键词：readout jitter / value scramble /
data settling / numeric stabilization。

## 调查 UI：项目的 signature motion

调查/扫描植物这类交互可以拥有全项目最强的一套动效，建议作为整个调查系统的标志性动效序列：

```
Acquire → Scan → Fragment → Reconstruct → Stabilize → Lock
```

1. **Acquire** — 扫描框从空到局部填充，突然锁定（Snap / Acquire / Lock）。
2. **Scan** — 横向扫描线（raster scan）从上到下/从左到右扫过目标。
3. **Fragment** — 目标轮廓不是 smooth draw，而是分帧出现/消失/再出现的碎片重建
   （frame 1: 2 段线条 → frame 2: 5 段 → frame 3: 3 段消失 → frame 4: 完整），与"断续墨线"美术方向
   直接呼应。
4. **Stabilize** — 名称/文字从乱码逐步收敛到最终值（`UNKNOWN → UNKN▓WN → UNKNOWN FLORA →
   SPECIMEN F-0284`）。

## 具体游戏 Reference（优先级排序）

**🥇 Returnal — 最值得研究"规则"**：视觉上比我们现代很多，但动效哲学非常接近——功能优先、工业设备、
CRT 影响、克制 motion、flicker on/off、少方向性 movement、glitch 只用于异常。官方说明他们限制效果，
让大部分界面以 flicker/on-off 变化，而不是现代 UI 常见的滑动和层层叠加。**借 Motion Grammar，不借
Visual。**

**🥈 Alien: Isolation — 最值得研究"设备感"**：现在的 moodboard 里已经是最接近的核心参考之一，尤其
研究 Motion Tracker、终端、Hacking UI、系统开启、信息刷新、Signal。核心技术感觉就是
clunky, glitchy, imperfect。游戏明确区分内部 HUD 与可交互的 in-world interface，后者刻意做成
primitive software 的行为方式，而不是现代平滑界面。

**🥉 SIGNALIS — 最值得研究"菜单状态感"**：不一定照抄动效，但值得看选中状态、硬切换、高对比、信息块、
功能导向。"科研档案 + 恐怖感"和它有一定视觉亲缘性。

**第四：Paratopic / Haunted PS1 系方向** — 主要研究 low-fi transition：abrupt cut、
low-resolution interruption、analog degradation、unsettling frame changes。Haunted PS1 系作品
整体是从 PS1 时代的低多边形、低分辨率纹理、雾和技术限制中提取一种"记忆中的 PSX 感"，不一定严格模拟
真实硬件。

## Motion Moodboard 标签

给 UI 美术 / TA / 动效负责人的一句话：

> **Mechanical · Discrete · Intermittent · Low-fi · Signal-driven**
> 中文：机械的、离散的、断续的、低保真的、由信号状态驱动的。

按状态细分：

| 状态 | 关键词 |
|---|---|
| 常态 | Snapped · Stepped · Stable · Restrained |
| 系统处理中 | Scanning · Writing · Refreshing · Quantized |
| 信号不稳定 | Flickering · Jittery · Intermittent · Fragmented |
| 异常 | Tearing · Dropping · Scrambling · Collapsing |

### Blacklist（应避免的形容词）

❌ Smooth ❌ Fluid ❌ Floaty ❌ Bouncy ❌ Springy ❌ Elastic ❌ Playful ❌ Soft ❌ Organic easing
❌ Cinematic swoosh

这些词会把"老旧科研设备 / PSX / CRT / 功能终端"迅速拉成"2026 年设计师做的复古风 UI"——是最应该避免
发生的事。

### 项目动效公式

> **Snap → Flicker → Scan → Stabilize → Lock**
> 跳变 → 闪烁 → 扫描 → 稳定 → 锁定

这五个动作足够构成一个 consistent 的 UI motion system。按钮、HUD、调查、无线电、档案、警告全部从这里
派生，而不是每个页面各自想一套。

## Unity 实现方案调研

结论：**没有找到一个现成 Unity 包可以直接实现上述 12 个语义动效（boot / initialize / acquire /
lock / scan / write / refresh / decode / synchronize / stabilize / interrupt / drop /
reconnect）作为一套统一的"retro terminal motion system"**。不存在类似
`terminal.Boot(); terminal.Scan(); terminal.Lock();` 这样的现成语义 API。

但不需要从零手搓所有视觉效果。合理方案是：**用现成 package 解决"文字 / UI Shader / CRT & glitch /
screen transition"这几层原语，自己只写一个很薄的 `TerminalMotion` 编排层**，把这些效果组合成统一的
语义 API——这比纯 DOTween 从头做，或者去找一个不存在的"一键 retro UI animation package"都更合理。
理由：如果真有这种现成包，它的 glitch rhythm / timing / flicker frequency / easing / scan
behavior 都是包作者定义的，而这个项目需要的是"所有页面最终调用同一套 Boot / Acquire / Scan / Lock /
Drop / Reconnect recipe"，真正决定 consistency 的是这套统一编排层，不是用了哪个插件。

### 四层架构

```
                    TerminalMotion API（自己写，语义编排层）
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
      Text Layer       UI Effect Layer   Screen Layer
          │                │                │
 Easy Text Effects      UIEffect      CRT / Retro shader
          │                │                │
          └────────────────┴────────────────┘
                           ▼
                     DOTween（只负责 orchestration/timing）
```

### 候选包

**① [LeiQiaoZhi/Easy-Text-Effects-for-Unity](https://github.com/LeiQiaoZhi/Easy-Text-Effects-for-Unity)**
（MIT，开源，约 1k star）— TextMeshPro 动画包，ready-to-use samples、实时预览、per-vertex
animation，效果可组合/chaining。负责文字层：write / decode / refresh / stabilize。
适配度：Typewriter/Write ⭐⭐⭐⭐⭐、Jitter/unstable text ⭐⭐⭐⭐⭐、Decode/scramble ⭐⭐⭐⭐、
Stepped animation ⭐⭐⭐⭐；terminal 语义 API 和完整 panel motion 仍需自己封装。

**② [mob-sakai/UIEffect](https://github.com/mob-sakai/UIEffect)** — 开源 Unity UI effect 包，
可对 UI 直接应用效果（Inspector/code 控制），支持 TMP、Shader Graph、Timeline；
`DissolveEffectForUGUI` 已整合进来。作为通用 UI shader/effect infrastructure，避免自己重新造一套。
注意：不建议直接用它自带的 dissolve 当 terminal disappear 效果（太"特效软件"感）——应该做
horizontal corruption / scanline 丢失 / signal collapse，而不是漂亮的 noise dissolve。

**③ CRT / PSX 视觉三选一：**
- [Luci0n/CrowFX-Unity-Image-Effects](https://github.com/Luci0n/CrowFX-Unity-Image-Effects) —
  免费开源 image effects stack，支持 CRT、VHS、glitch、dithering、PSX 风格，含 ghosting、jitter、
  RGB bleed、virtual resolution。**不建议 blanket apply 到整个正式 UI**——应该只用在异常状态
  （interrupt / drop / reconnect），正常 UI 保持基本干净，否则会伤害文字可读性（有开发者实践提到，
  过重的 curvature / chromatic aberration / scanline 会迅速伤害阅读，最终把主 UI 保持较干净、把
  失真放到环境和屏幕边缘）。
- [GlaireDaggers/RetroTVFX](https://github.com/GlaireDaggers/RetroTVFX) — 更专注 CRT/old TV
  （Composite / S-Video / RF / CRT / PSX-style low-res / wobble），有 package.json 可作 Unity
  package 使用，示例里包含把 Unity UI render 到低分辨率 target texture。适合世界内终端/CRT 设备屏幕，
  以及 signal weak/drop/reconnect 这类状态。
- [Cyanilux/URP_RetroCRTShader](https://github.com/Cyanilux/URP_RetroCRTShader) — 若用 URP
  更轻量明确，包含 CRT warping、scanlines、image distortion、static、scrolling glitchy static、
  RGB phosphor stripes，更新到 Unity 2022+ workflow。适合 scan / acquire / drop / reconnect。

**④ 付费选项：[Febucci Text Animator for Unity](https://assetstore.unity.com/packages/tools/gui/text-animator-for-unity-ui-toolkit-and-text-mesh-pro-341308)**
（$65）— 支持 TMP 和 UI Toolkit，typewriter、appearance/disappearance effects、内置+自定义 effect、
事件触发，官方举例可以让效果"laggy、step by step"。如果文本动画很多（无线电、调查、档案、系统日志、
官方报告等大量场景）值得买；如果文本动画只是辅助，用 Easy Text Effects 或自己封装 TMP
`maxVisibleCharacters` 即可。

> **[project decision]** 不采购 Febucci（$65，超出本项目预算）。文本层用 Easy Text Effects
> 或自己封装 TMP `maxVisibleCharacters`；两者都是 TMP 插件，与本项目的 uGUI + TextMeshProUGUI
> 组合直接兼容。

### 12 个语义动词 → 建议底层实现

| 语义动词 | 建议底层实现 |
|---|---|
| `Boot` | 1 帧 flash + scanline sweep + content fragment 出现 + flicker → stable |
| `Acquire` | position snap + UI glow + border flash |
| `Scan` | 自己写的 scan shader（值得投入，是最常用、最有辨识度的效果） |
| `Write` | Easy Text Effects / Febucci / TMP `maxVisibleCharacters` |
| `Decode` | 自己写的 TMP custom effect（random glyphs → 部分正确 → 最终锁定） |
| `Drop` | CRT/glitch shader：jitter → horizontal displacement → partial line loss → OFF |
| `Reconnect` | `Drop` 的反向但不是 smooth reverse：noise → partial data → flicker → lock |

### 建议的工程落地方式

只写一次 `TerminalMotion` 系统（语义 API 层），以后所有 UI（HUD、报告页、按钮……）都调用语义动词，
底下再接上面这几个现成的 text/effect/shader 包——而不是每个页面各自手写一套 DOTween。这是长期成本
最低的方案，也是保持整个项目 motion consistency 的关键：consistency 来自"大家都调用同一套
recipe"，不是"大家都用了某个插件"。

**架构落点提示**（供后续正式方案设计时参考，非本次调研结论）：本项目 UI 层是 uGUI +
TextMeshProUGUI（见 [09-packages-systems.md](../guidelines/09-packages-systems.md#ugui-runtime-ui)），
所以上面列的 TMP / uGUI 系插件（Easy Text Effects、UIEffect）都直接可用，不需要额外的兼容层；
`TerminalMotion` 编排层应该是 presenter 侧的工具类，不直接持有游戏状态；具体挂靠位置和契约需要在
[表现层驱动契约](../architecture/contracts/表现层驱动契约.md)或新的 UI 动效契约里定义，
不在本文档范围内。
