# Model tab Import Settings reference

To open a model’s Import Settings, select the model from the [Project window](https://docs.unity3d.com/6000.3/Documentation/Manual/ProjectView.html). The [Inspector](https://docs.unity3d.com/6000.3/Documentation/Manual/UsingTheInspector.html) then displays the Import Settings for the selected model. You can also control these settings in your scripts with the [`ModelImporter`](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/ModelImporter.html) class.

![The Import Settings window](https://docs.unity3d.com/6000.3/Documentation/uploads/Main/model-import-settings.png)

The Model tab contains the following sections:

<span id="scene"></span>

## Scene

Scene-level properties, such as whether to import lights and cameras, and what scale factor to use.

Unity’s physics system expects 1 m in the game world to be 1 unit in the imported file.</td></tr><tr class="even"><td style="text-align: left;"><strong>Convert Units</strong></td><td style="text-align: left;">Converts the <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/models-preparing.html">model scaling</a> defined in the model file to Unity’s scale.</td></tr><tr class="odd"><td style="text-align: left;"><strong>Bake Axis Conversion</strong></td><td style="text-align: left;">Bakes the results of axis conversion directly into your application’s asset data (for example, vertex or animation data) when you import a model that uses a different axis system than Unity. Disable this property to compensate the Transform component of the root GameObject at runtime to simulate axis conversion.</td></tr><tr class="even"><td style="text-align: left;"><strong>Import BlendShapes</strong></td><td style="text-align: left;">Imports blend shapes with your mesh. For more information, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/ImportingModelFiles.html#importing-blend-shapes">Importing blend shapes</a>.<br />
<br />
<strong>Note</strong>: Importing blend shape normals requires smoothing groups in the FBX file.</td></tr><tr class="odd"><td style="text-align: left;"><strong>Import Deform Percent</strong></td><td style="text-align: left;">Only available when <strong>Import BlendShapes</strong> is enabled. Import the blend shape’s deform percent. Leave disabled to set all values to 0.</td></tr><tr class="even"><td style="text-align: left;"><strong>Import Visibility</strong></td><td style="text-align: left;">Imports the FBX settings that define whether MeshRenderer components are enabled (visible). For more information, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/ImportingModelFiles.html#importing-visibility-properties">Importing visibility properties</a>.</td></tr><tr class="odd"><td style="text-align: left;"><strong>Import Cameras</strong></td><td style="text-align: left;">Imports cameras from your .FBX file. For more information, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/ImportingModelFiles.html#light-support">Camera support</a>.</td></tr><tr class="odd"><td style="text-align: left;"><strong>Preserve Hierarchy</strong></td><td style="text-align: left;">Creates an explicit prefab root, even if this model only has a single root. Normally, the FBX importer strips any empty root nodes from the model to improve performance. However, if you have multiple FBX files with portions of the same hierarchy you can use this option to preserve the original hierarchy.<br />
<br />
For example, <code>file1.fbx</code> contains a rig and a mesh and <code>file2.fbx</code> contains the same rig but only the animation for that rig. If you import <code>file2.fbx</code> without enabling this option, Unity strips the root node, the hierarchies don’t match, and the animation breaks.</td></tr><tr class="even"><td style="text-align: left;"><strong>Sort Hierarchy By Name</strong></td><td style="text-align: left;">Sorts GameObjects by alphabetical order within the hierarchy. Disable this property to preserve the hierarchy order defined in the FBX file.</td></tr></tbody></table>

## Meshes

<table><thead><tr class="header"><th style="text-align: left;"><strong>Property</strong></th><th style="text-align: left;"><strong>Description</strong></th></tr></thead><tbody><tr class="odd"><td style="text-align: left;"><strong>Mesh Compression</strong></td><td style="text-align: left;">Set the level of compression ratio to reduce the file size of the mesh. Increase the compression ratio to lower the precision of the mesh. Unity uses the mesh bounds and a lower bit depth per component to compress the mesh data. This is useful for <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/ReducingFilesize.html">optimizing game size</a>. The following options are available:<ul><li><strong>Off</strong>: Don’t use compression.</li><li><strong>Low</strong>: Use a low compression ratio.</li><li><strong>Medium</strong>: Use a medium compression ratio.</li><li><strong>High</strong>: Use a high compression ratio.</li></ul></td></tr><tr class="even"><td style="text-align: left;"><strong>Read/Write</strong></td><td style="text-align: left;">Allows Unity to access mesh data at runtime, and you to access it from your scripts. Unity uploads the mesh data to GPU-addressable memory, but also keeps it in CPU-addressable memory. For example, you might want to enable this if you’re generating a mesh procedurally, or if you want to copy some data from a mesh.<br />
<br />
When this option is disabled, Unity uploads the mesh data to GPU-addressable memory, and then removes it from CPU-addressable memory.<br />
<br />
By default, this option is disabled. To save runtime memory usage, leave this option disabled. For information on when to enable Read/Write Enabled, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Mesh-isReadable.html"><code>Mesh.isReadable</code></a>.</td></tr><tr class="odd"><td style="text-align: left;"><strong>Optimize Mesh</strong></td><td style="text-align: left;">Set the order in which triangles are listed in the Mesh for better GPU performance. The following options are available:<ul><li><strong>Nothing</strong>: No optimization.</li><li><strong>Everything</strong>: Let Unity reorder the vertices and indices for both polygons and vertices. This is the default.</li><li><strong>Polygon Order</strong>: Reorder only the polygons.</li><li><strong>Vertex Order</strong>: Reorder only the vertices.</li></ul></td></tr><tr class="even"><td style="text-align: left;"><strong>Generate Colliders</strong></td><td style="text-align: left;">Import the mesh with mesh colliders automatically attached. This is useful for quickly generating a collision mesh for environment geometry, but should be avoided for geometry you’re moving.</td></tr></tbody></table>

## Mesh LOD properties section

| **Property**           | **Description**                                                                                                                                                                                                            |
|:-----------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Generate Mesh LODs** | Generates mesh LODs for the asset and its child assets automatically. For more information, refer to [How the Mesh LOD generator works](https://docs.unity3d.com/6000.3/Documentation/Manual/lod/mesh-lod-generator.html). |
| **Discard Odd Levels** | Reduces the number of generated LODs by discarding all LODs with an odd index (LOD1, LOD3, and so on). Using this option can improve performance but it increases the likelihood of visual artifacts.                      |
| **Limit LODs**         | Limits the number of LODs that Unity generates. This ensures that LOD quality does not drop below a certain level, but reduces the potential performance gain.                                                             |
| **Maximum Levels**     | Defines the maximum number of levels to generate.                                                                                                                                                                          |

## Geometry

<table><thead><tr class="header"><th style="text-align: left;"><strong>Property</strong></th><th style="text-align: left;"><strong>Description</strong></th></tr></thead><tbody><tr class="odd"><td style="text-align: left;"><strong>Keep Quads</strong></td><td style="text-align: left;">Prevents Unity from converting polygons that have four vertices to triangles. For example, if you’re using <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/SL-SurfaceShaderTessellation.html">tessellation shaders</a>, you might want to enable this option because tessellating quads can be more efficient than tessellating polygons.<br />
<br />
Unity can import any type of polygon (triangle to N-gon). Polygons that have more than four vertices are always converted to triangles regardless of this setting. However, if a mesh has quads and triangles (or N-gons that get converted to triangles), Unity creates two submeshes to separate quads and triangles. Each submesh contains either triangles only or quads only.<br />
<br />
<strong>Tip:</strong> If you want to import quads into Unity from 3ds Max, you have to export it as an Editable Poly.</td></tr><tr class="even"><td style="text-align: left;"><strong>Weld Vertices</strong></td><td style="text-align: left;">Combine vertices that share the same position in space, if they share all the same properties (including, UVs, Normals, Tangents, and VertexColor).<br />
<br />
This optimizes the vertex count on meshes by reducing their total number. This option is enabled by default.<br />
<br />
Sometimes, you might need to disable this optimization when importing meshes. For example, if you intentionally have duplicate vertices which occupy the same position in your mesh, you might prefer to use scripting to read or manipulate the individual vertex and triangle data.</td></tr><tr class="odd"><td style="text-align: left;"><strong>Index Format</strong></td><td style="text-align: left;">Defines the size of the Mesh index buffer. The following options are available:<ul><li><strong>Auto</strong>: Let Unity decide whether to use 16 or 32 bit indices when importing a mesh, depending on the mesh vertex count. The default setting.</li><li><strong>16 bit</strong>: Use 16 bit indices when importing a mesh. If the mesh is larger, then Unity splits it into &lt;64k vertex chunks.</li><li><strong>32 bit</strong> - Use 32 bit indices when importing a mesh. If you’re using GPU-based rendering pipelines (for example with compute shader triangle culling), using 32 bit indices ensures that all meshes use the same index format. This reduces shader complexity, because they only need to handle one format.</li></ul><br />
<strong>Note:</strong> For bandwidth and memory storage size reasons, it’s best practice to keep the <strong>16 bit</strong> indices as default, and only use <strong>32 bit</strong> when necessary, which is what the <strong>Auto</strong> option uses.</td></tr><tr class="even"><td style="text-align: left;"><strong>Legacy Blend Shape Normals</strong></td><td style="text-align: left;">Computes normals based on the <strong>Smoothing Angle</strong> value.</td></tr><tr class="odd"><td style="text-align: left;"><strong>Normals</strong></td><td style="text-align: left;">Controls how to calculate normals. This is useful for <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/ReducingFilesize.html">optimizing game size</a>. The following options are available:<ul><li><strong>Import</strong>: Import normals from the file. This is the default option. If the file doesn’t contain normals, Unity calculates them.</li><li><strong>Calculate</strong>: Calculate normals based on <strong>Normals Mode</strong>, <strong>Smoothness Source</strong>, and <strong>Smoothing Angle</strong>.</li><li><strong>None</strong>: Disable normals. Use this option if the mesh is neither normal mapped nor affected by real-time lighting.</li></ul></td></tr><tr class="even"><td style="text-align: left;"><strong>Blend Shape Normals</strong></td><td style="text-align: left;">Controls how to calculate normals for blend shapes. This value should match the value for the <strong>Normals</strong> property. This property is only visible when <strong>Legacy Blend Shape Normals</strong> is disabled. The following options are available:<ul><li><strong>Import</strong>: Import normals from the file. If the blend shape doesn’t contain normals, the FBX SDK uses its own method to calculate normals, resulting in normal values that usually differ from the normal values that Unity creates with the <strong>Calculate</strong> option.</li><li><strong>Calculate</strong>: Calculate normals based on <strong>Normals Mode</strong>, <strong>Smoothness Source</strong>, and <strong>Smoothing Angle</strong>.</li><li><strong>None</strong>: The blend shape normals don’t contribute to the base shape.</li></ul></td></tr><tr class="odd"><td style="text-align: left;"><strong>Normals Mode</strong></td><td style="text-align: left;">Define how the normals are calculated by Unity. This is only available when <strong>Normals</strong> is set to <strong>Calculate</strong> or <strong>Import</strong>. The following options are available:<ul><li><strong>Unweighted Legacy</strong>: The legacy method of computing the normals (prior to version 2017.1).</li><li><strong>Unweighted</strong>: The normals aren’t weighted.</li><li><strong>Area Weighted</strong>: The normals are weighted by face area.</li><li><strong>Angle Weighted</strong> : The normals are weighted by the vertex angle on each face.</li><li><strong>Area and Angle Weighted</strong>: The normals are weighted by both the face area and the vertex angle on each face. This is the default option.</li></ul></td></tr><tr class="even"><td style="text-align: left;"><strong>Smoothness Source</strong></td><td style="text-align: left;">Set how to determine the smoothing behavior (which edges should be smooth and which should be hard). This property is only visible when <strong>Legacy Blend Shape Normals</strong> is disabled. The following options are available:<ul><li><strong>Prefer Smoothing Groups</strong>: Use smoothing groups from the model file, where possible.</li><li><strong>From Smoothing Groups</strong>: Use smoothing groups from the model file only.</li><li><strong>From Angle</strong>: Use the <strong>Smoothing Angle</strong> value to determine which edges should be smooth.</li><li><strong>None</strong>: Don’t split any vertices at hard edges.</li></ul></td></tr><tr class="odd"><td style="text-align: left;"><strong>Smoothing Angle</strong></td><td style="text-align: left;">Controls whether vertices are split for hard edges. Typically higher values result in fewer vertices.<br />
<br />
<strong>Note:</strong> Use this setting only on smooth organics or high poly models. For other model types, manually smooth in your 3D modeling software and then import with the <strong>Normals</strong> option set to <strong>Import</strong>. Unity bases hard edges on a single angle so you might end up with smoothing on some parts of the model by mistake.<br />
<br />
Only available if <strong>Normals</strong> is set to <strong>Calculate</strong>.</td></tr><tr class="even"><td style="text-align: left;"><strong>Tangents</strong></td><td style="text-align: left;">Controls how vertex tangents are imported or calculated. This is only available when <strong>Normals</strong> is set to <strong>Calculate</strong> or <strong>Import</strong>. The following options are available:<ul><li><strong>Import</strong>: Import vertex tangents from FBX files if <strong>Normals</strong> is set to <strong>Import</strong>. If the mesh has no tangents, it doesn’t work with normal-mapped shaders.</li><li><strong>Calculate Legacy</strong>: Calculate tangents with the legacy algorithm.</li><li><strong>Calculate Legacy - Split Tangent</strong>: Calculate tangents with the legacy algorithm, with splits across UV charts. Use this if normal map lighting is broken by seams on your mesh. This usually only applies to characters.</li><li><strong>Calculate Mikktspace</strong>: Calculate tangents using <a href="http://www.mikktspace.com/">MikkTSpace</a>. This is the default option if <strong>Normals</strong> is set to <strong>Calculate</strong>.</li><li><strong>None</strong>: Don’t import vertex tangents. The Mesh has no tangents, so this doesn’t work with normal-mapped shaders.</li></ul></td></tr><tr class="odd"><td style="text-align: left;"><strong>Swap UVs</strong></td><td style="text-align: left;">Swap UV channels in the mesh. Use this option if the diffuse Texture uses UVs from the lightmap. Unity supports up to eight UV channels but not all 3D modeling applications export more than two.</td></tr><tr class="even"><td style="text-align: left;"><strong>Generate Lightmap UVs</strong></td><td style="text-align: left;">Creates a second UV channel for the lightmap. For more information, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/LightingGiUvs-GeneratingLightmappingUVs.html">Generate lightmap UVs</a>.</td></tr></tbody></table>
