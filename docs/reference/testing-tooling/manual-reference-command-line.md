# Command-line reference

Unity Test Framework adds the following additional arguments to the regular [Unity Editor command-line arguments](https://docs.unity3d.com/6000.3/Documentation/Manual/EditorCommandLineArguments.html):

<table><thead><tr class="header"><th style="text-align: left;"><strong>Command</strong></th><th style="text-align: left;"><strong>Description</strong></th></tr></thead><tbody><tr class="odd"><td style="text-align: left;"><code>-assemblyNames</code></td><td style="text-align: left;">A semicolon-separated list of test assemblies to include in the run. A semi-colon separated list should be formatted as a string enclosed in quotation marks, e.g. <code>-assemblyNames "firstAssembly;secondAssembly"</code>.</td></tr><tr class="even"><td style="text-align: left;"><code>-forgetProjectPath</code></td><td style="text-align: left;">Prevents Unity saving your current project into the Unity launcher/hub history.</td></tr><tr class="odd"><td style="text-align: left;"><code>-orderedTestListFile</code></td><td style="text-align: left;">Path to a .txt file which contains a list of full test names you want to run in the specified order. There are no restrictions on the file name as long as the format is text. Separate tests by new lines and specify parameters if the tests have them. The following is an example of the content of such a file:<br />
<br />
<code>Unity.Framework.Tests.OrderedTests.NoParameters</code><br />
<code>Unity.Framework.Tests.OrderedTests.ParametrizedTestA(3,2)</code><br />
<code>Unity.Framework.Tests.OrderedTests.ParametrizedTestB("Assets/file.fbx")</code><br />
<code>Unity.Framework.Tests.OrderedTests.ParametrizedTestD(1.0f)</code><br />
<code>Unity.Framework.Tests.OrderedTests.ParametrizedTestE(null)</code><br />
<code>Unity.Framework.Tests.OrderedTests.ParametrizedTestF(False, 1)</code><br />
<code>Unity.Framework.Tests.OrderedTests.ParametrizedTestG(float.NaN)</code><br />
<code>Unity.Framework.Tests.OrderedTests.ParametrizedTestH(SomeEnum)</code></td></tr><tr class="even"><td style="text-align: left;"><code>-playerHeartbeatTimeout</code></td><td style="text-align: left;">Defines the length of time, in seconds, for which the Editor waits for heartbeats after starting a test run on a Player. This defaults to 10 minutes.</td></tr><tr class="odd"><td style="text-align: left;"><code>-randomOrderSeed</code></td><td style="text-align: left;">A non-zero integer representing the seed value to use for randomizing tests in the project, independently from the fixture.<br />
<code># normal order</code><br />
<code>Test_1</code><br />
<code>Test_2</code><br />
<code>Test_3</code><br />
<code>Test_4</code><br />
<code># randomized with seed x</code><br />
<code>Test_3</code><br />
<code>Test_1</code><br />
<code>Test_4</code><br />
<code>Test_2</code><br />
<code># randomized with same seed x and a new test</code><br />
<code>Test_3</code><br />
<code>Test_5</code><br />
<code>Test_1</code><br />
<code>Test_4</code><br />
<code>Test_2</code></td></tr><tr class="even"><td style="text-align: left;"><code>-repeat</code></td><td style="text-align: left;">An integer that sets the repeat count. Successful tests are repeated up to this number of times, or until they fail, whichever happens first.</td></tr><tr class="odd"><td style="text-align: left;"><code>-retry</code></td><td style="text-align: left;">An integer that sets the retry count. Failing tests are retried up to this number of times, or until they succeed, whichever happens first.</td></tr><tr class="even"><td style="text-align: left;"><code>-runSynchronously</code></td><td style="text-align: left;">Supply this argument to run tests synchronously, guaranteeing that all tests run in one Editor update call. This is only supported for Edit mode tests. Tests that take multiple frames, such as <code>[UnityTest]</code> tests, or tests with <code>[UnitySetUp]</code> or <code>[UnityTearDown]</code> scaffolding, are filtered out.</td></tr><tr class="odd"><td style="text-align: left;"><code>-runTests</code></td><td style="text-align: left;">Runs tests in the Project.</td></tr><tr class="even"><td style="text-align: left;"><code>-testCategory</code></td><td style="text-align: left;">A semicolon-separated list of test categories to include in the run, or a regular expression pattern to match category names. A semi-colon separated list should be formatted as a string enclosed in quotation marks, for example <code>-testCategory "firstCategory;secondCategory"</code>. If both <code>-testFilter</code> and <code>-testCategory</code> are provided, only tests that match both are run. This argument supports negation using <code>!</code>. Using <code>!MyCategory</code> excludes tests with the <code>MyCategory</code> category from the run.</td></tr><tr class="odd"><td style="text-align: left;"><code>-testfilter</code></td><td style="text-align: left;">A semicolon-separated list of test names to run, or a regular expression pattern to match tests by their full name. A semi-colon separated list should be formatted as a string enclosed in quotation marks, for example <code>testFilter "Low;Medium"</code>. This argument supports negation using <code>!</code>. The test filter <code>!MyNamespace.Something.MyTest</code> runs all tests except the one called <code>MyNamespace.Something.MyTest</code>. Run a specific variation of a parameterized test as follows: <code>"ClassName\.MethodName\(Param1,Param2\)"</code></td></tr><tr class="even"><td style="text-align: left;"><code>-testPlatform</code></td><td style="text-align: left;">The platform to run tests on. Accepted values:<ul><li><code>EditMode</code>: Edit mode tests. Equivalent to running tests from the EditMode tab of the <strong>Test Runner</strong> window.</li><li><code>PlayMode</code>: Play mode tests that run in the Editor. Equivalent to running tests from the PlayMode tab of the <strong>Test Runner</strong> window.</li><li>Any value from the <a href="https://docs.unity3d.com/ScriptReference/BuildTarget.html">BuildTarget</a> enum. Play mode tests that run on a Player built for the specified platform. Equivalent to using the Run All option in the Player tab of the Test Runner window.</li></ul><strong>Note</strong>: If no value is specified for this argument, tests run in Edit mode.</td></tr><tr class="odd"><td style="text-align: left;"><code>-testResults</code></td><td style="text-align: left;">Specifies a path to which Unity saves the test result file. By default, Unity saves the file in the project’s root folder. Test results follow the XML format as defined by NUnit, for more information refer to <a href="https://docs.nunit.org/articles/nunit/technical-notes/usage/Test-Result-XML-Format.html">Test Result XML Format</a>. There is currently no common definition for exit codes reported by individual Unity components under test. The best way to understand the source of a problem is the content of error messages and stack traces.</td></tr><tr class="even"><td style="text-align: left;"><code>-testSettingsFile</code></td><td style="text-align: left;">Path to a <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/test-framework/reference-command-line.html#test-settings">TestSettings.json</a> file.</td></tr></tbody></table>

**Note**: The Editor’s regular `-quit` command-line argument is not supported while tests are running.

## Test settings reference

You can define options for a test run in a `TestSettings.json` file. You can specify the location of this file using the `-testSettingsFile` command line argument.

The following example illustrates the content of a typical `TestSettings.json` file:

``` lang-json
}
```
