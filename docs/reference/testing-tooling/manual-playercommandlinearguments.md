# Unity Player command line arguments reference

You can launch Unity Players from the command line and pass in arguments to change how the Player executes.

These arguments work on all standalone platforms except for the [Web platform](https://docs.unity3d.com/6000.3/Documentation/Manual/webgl.html). The following table specifies any additional platform requirements.

For more information on launching Unity from the command line, refer to [Run Unity from a command-line interface](https://docs.unity3d.com/6000.3/Documentation/Manual/command-line-run-unity.html).

In this mode, the application doesn’t display anything or accept user input.</td></tr><tr class="even"><td style="text-align: left;"><code>-disable-gpu-skinning</code></td><td style="text-align: left;">Disables Graphics Processing Unit (GPU) skinning at startup.</td></tr><tr class="odd"><td style="text-align: left;"><code>-dontConnectAcceleratorEvent</code> (UWP only)</td><td style="text-align: left;">Disable connecting to AcceleratorKeyEvent. This might help if you have issues with input in XAML elements.<br />
<strong>Note:</strong> Unity can’t handle some keyboard keys, such as F10, Ctrl, Alt, and Tab.</td></tr><tr class="even"><td style="text-align: left;"><code>-force-clamped</code></td><td style="text-align: left;">Use this together with <code>-force-glcoreXY</code> to prevent checks for additional OpenGL extensions, allowing the application to run between platforms with the same code paths.</td></tr><tr class="odd"><td style="text-align: left;"><code>-force-d3d11</code> (Windows only)</td><td style="text-align: left;">Force the application to use Direct3D 11 for rendering.</td></tr><tr class="even"><td style="text-align: left;"><code>-force-d3d11-bitblt-model</code> (Windows only)</td><td style="text-align: left;">Force the application to use DXGI BitBlt model swapchain when using Direct3D 11. For more information, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/ScriptReference/PlayerSettings-useFlipModelSwapchain.html"><code>PlayerSettings.useFlipModelSwapchain</code></a>.</td></tr><tr class="odd"><td style="text-align: left;"><code>-force-d3d11-flip-model</code> (Windows only)</td><td style="text-align: left;">Force the application to use DXGI flip model swapchain when using Direct3D 11. For more information, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/ScriptReference/PlayerSettings-useFlipModelSwapchain.html"><code>PlayerSettings.useFlipModelSwapchain</code></a>.</td></tr><tr class="even"><td style="text-align: left;"><code>-force-d3d11-no-singlethreaded</code> (Windows and UWP only)</td><td style="text-align: left;">Force DirectX 11.0 to be created without a <code>D3D11_CREATE_DEVICE_SINGLETHREADED</code> flag.</td></tr><tr class="odd"><td style="text-align: left;"><code>-force-d3d11-singlethreaded</code> (Windows and UWP only)</td><td style="text-align: left;">Force DirectX 11.0 to be created with a <code>D3D11_CREATE_DEVICE_SINGLETHREADED</code> flag.</td></tr><tr class="even"><td style="text-align: left;"><code>-force-d3d12</code> (Windows only)</td><td style="text-align: left;">Force the application to use Direct3D 12 for rendering.</td></tr><tr class="odd"><td style="text-align: left;"><code>-force-device-index</code></td><td style="text-align: left;">Make the Standalone Player use a specific GPU device by passing it the index of that GPU. This option is supported for D3D11, D3D12, Metal, and Vulkan graphics APIs, but isn’t supported for OpenGL.</td></tr><tr class="even"><td style="text-align: left;"><code>-force-driver-type-warp</code> (Windows and UWP only)</td><td style="text-align: left;">Force the DirectX 11.0 driver type WARP device. For more information, refer to Microsoft’s documentation on <a href="https://docs.microsoft.com/en-gb/windows/win32/direct3darticles/directx-warp?redirectedfrom=MSDN">Windows Advanced Rasterization Platform</a>.</td></tr><tr class="odd"><td style="text-align: left;"><code>-force-feature-level-10-0</code> (Windows and UWP only)</td><td style="text-align: left;">Force DirectX 11.0 feature level 10.0.</td></tr><tr class="even"><td style="text-align: left;"><code>-force-feature-level-10-1</code> (Windows and UWP only)</td><td style="text-align: left;">Force DirectX 11.0 feature level 10.1.</td></tr><tr class="odd"><td style="text-align: left;"><code>-force-feature-level-11-0</code> (Windows and UWP only)</td><td style="text-align: left;">Force DirectX 11.0 feature level 11.0.</td></tr><tr class="even"><td style="text-align: left;"><code>-force-gfx-direct</code></td><td style="text-align: left;">Force single threaded rendering.</td></tr><tr class="odd"><td style="text-align: left;"><code>-force-glcore</code></td><td style="text-align: left;">Force the application to use the OpenGL core profile for rendering. Unity uses Direct3D if the platform doesn’t support OpenGL.</td></tr><tr class="even"><td style="text-align: left;"><code>-force-glcoreXY</code></td><td style="text-align: left;">Similar to <code>-force-glcore</code>, but requests a specific OpenGL context version. This implementation allows switching to different implementations, in case there are issues with the default.<br />
<br />
<strong>Note:</strong> This implementation has an effect only on UWP XAML applications.</td></tr><tr class="even"><td style="text-align: left;"><code>-force-vulkan</code></td><td style="text-align: left;">Force the application to use Vulkan for rendering.</td></tr><tr class="odd"><td style="text-align: left;"><code>-force-wayland</code> (Linux only)</td><td style="text-align: left;">Activate experimental Wayland support when running a Linux player.</td></tr><tr class="even"><td style="text-align: left;"><code>-logFile &lt;pathname&gt;</code></td><td style="text-align: left;">Specifies a file path location to which Unity writes the standalone Player log file. For more information on the default location of the log file when this argument is not provided, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/log-files.html">Log files reference</a>. To output to the console, specify <code>-</code> for the path name. On Windows you can use <code>-logFile</code> to direct the output to <a href="https://learn.microsoft.com/en-us/cpp/c-runtime-library/stdin-stdout-stderr?view=msvc-170"><code>stdout</code></a>, which by default is not the console. If the path contains spaces, wrap it in double quotes. Some command-line interfaces might require quoting the path even if the path contains no spaces.<br />
<br />
Example (Windows):<br />
<code>"C:\Users\me\Builds\MyGame\MyGame.exe" -logFile "C:\Logs\Player.log"</code><br />
Example (macOS):<br />
<code>"/Users/me/Builds/MyGame.app/Contents/MacOS/MyGame" -logFile "/Users/me/Logs/Player.log"</code><br />
Example (Linux):<br />
<code>"/home/me/Builds/MyGame/MyGame" -logFile "/home/me/logs/Player.log"</code></td></tr><tr class="odd"><td style="text-align: left;"><code>-log-memory-performance-stats</code></td><td style="text-align: left;">Adds a detailed memory report to the Player log file when closing the Player.</td></tr><tr class="even"><td style="text-align: left;"><code>-max-async-pso-job-count</code></td><td style="text-align: left;">Set the number of parallel threads Unity uses to create pipeline state objects (PSOs) when you use <a href="https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Experimental.Rendering.ShaderWarmup.html"><code>Experimental.Rendering.ShaderWarmup</code></a> to prewarm shader variants. This only has an effect if your application runs on a platform that uses the DirectX 12, Metal, or Vulkan graphics API.</td></tr><tr class="odd"><td style="text-align: left;"><code>-monitor N</code></td><td style="text-align: left;">Run Standalone Player on the specified monitor, indicated by a 1-based index number.</td></tr><tr class="even"><td style="text-align: left;"><code>-nographics</code></td><td style="text-align: left;">When you use this argument in batch mode, Unity doesn’t initialize a graphics device. This makes it possible to run your automated workflows on machines that don’t have a GPU.<br />
<strong>Note</strong>: Output logs are turned off in this mode.</td></tr><tr class="odd"><td style="text-align: left;"><code>-nolog</code></td><td style="text-align: left;">Disables Player logging. For more information on the content and location of Player logs, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/log-files.html">Log files reference</a> folder.</td></tr><tr class="even"><td style="text-align: left;"><code>-no-stereo-rendering</code></td><td style="text-align: left;">Turn off stereo rendering.</td></tr><tr class="odd"><td style="text-align: left;"><code>-parentHWND &lt;HWND&gt; delayed</code> (Windows only)</td><td style="text-align: left;">Embed the Windows Standalone application into another application. When you use this argument, you need to pass the parent application’s window handle (‘HWND’) to the Windows Standalone application.<br />
<br />
When you pass <code>-parentHWND 'HWND' delayed</code>, the Unity application is hidden while it runs. You must also call <a href="https://docs.microsoft.com/en-gb/windows/win32/api/winuser/nf-winuser-setparent?redirectedfrom=MSDN">SetParent</a> from the <a href="https://docs.microsoft.com/en-gb/">Microsoft Developer library</a> for Unity in the application. Microsoft’s <code>SetParent</code> embeds the Unity window. When it creates Unity processes, the Unity window respects the position and size provided as part of Microsoft’s <a href="https://docs.microsoft.com/en-gb/windows/win32/api/processthreadsapi/ns-processthreadsapi-startupinfoa?redirectedfrom=MSDN">STARTUPINFO</a> structure.<br />
<br />
To resize the Unity window, check its <a href="https://docs.microsoft.com/en-gb/windows/win32/api/winuser/nf-winuser-getwindowlongptra?redirectedfrom=MSDN">GWLP_USERDATA</a> in Microsoft’s <code>GetWindowLongPtr</code> function. Its lowest bit is set to 1 when the graphics initialize and it’s safe to resize. Its second lowest bit is set to 1 after the Unity splash screen finishes displaying.<br />
<br />
For more information, see this downloadable example: <a href="https://docs.unity3d.com/6000.3/Documentation/uploads/Examples/EmbeddedWindow.zip">EmbeddedWindow.zip</a></td></tr><tr class="even"><td style="text-align: left;"><code>-popupwindow</code></td><td style="text-align: left;">Create the window as a dialog window, without a frame. This command isn’t supported on macOS.</td></tr><tr class="odd"><td style="text-align: left;"><code>-screen-fullscreen</code></td><td style="text-align: left;">Override the default full-screen state. This must be 0 or 1.</td></tr><tr class="even"><td style="text-align: left;"><code>-screen-height</code></td><td style="text-align: left;">Override the default screen height. This must be an integer from a supported resolution.</td></tr><tr class="odd"><td style="text-align: left;"><code>-screen-quality</code></td><td style="text-align: left;">Override the default screen quality. Example usage would be: <code>/path/to/myGame -screen-quality Beautiful</code>. The supported options match the <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/class-QualitySettings.html">Quality Settings</a> names.</td></tr><tr class="even"><td style="text-align: left;"><code>-screen-width</code></td><td style="text-align: left;">Override the default screen width. This width value must be an integer from a supported resolution.</td></tr><tr class="odd"><td style="text-align: left;"><code>-single-instance</code> (Linux and Windows only)</td><td style="text-align: left;">Run only one instance of the application at the time. If another instance is already running then launching the application again with <code>-single-instance</code> focuses the existing one.</td></tr><tr class="even"><td style="text-align: left;"><code>-systemallocator</code></td><td style="text-align: left;">Forces the platform to use the system allocator. This can be useful if you want to use tools like address sanitizers to debug memory issues. You should only use this option for debugging purposes.</td></tr><tr class="odd"><td style="text-align: left;"><code>-timestamps</code></td><td style="text-align: left;">Prefixes every <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/log-files.html">Player log</a> message with the current timestamp and thread ID.</td></tr><tr class="even"><td style="text-align: left;"><code>-wait-for-managed-debugger</code></td><td style="text-align: left;">Makes the Player wait for a managed debugger to attach before launching. Generates a dialog that displays the Player’s process ID. For more information on managed debugging, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/managed-code-debugging.html#DebugInEditor">Debug C# code in Unity</a>.</td></tr><tr class="odd"><td style="text-align: left;"><code>-wait-for-native-debugger</code></td><td style="text-align: left;">Makes the Player wait for a native debugger to attach before launching. Generates a dialog that displays the Player’s process ID.</td></tr><tr class="even"><td style="text-align: left;"><code>-window-mode</code> (Windows only)</td><td style="text-align: left;">Override full screen windowed mode. Accepted values are <code>exclusive</code> or <code>borderless</code>. For more information, refer to <a href="https://docs.unity3d.com/6000.3/Documentation/Manual/class-PlayerSettings.html">Player settings</a>.</td></tr></tbody></table>
