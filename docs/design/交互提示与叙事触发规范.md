# 交互提示与叙事触发规范

全游戏 HUD 提示、交互点文案和叙事触发的行为真源。分两层：**规则**（所有新增交互必须遵守）和**交互点清单**（每个交互点的 intended 行为；`当前` 列与 intended 不一致的就是 bug）。改交互行为先改这里，再改实现。

## 提示管线规则

1. **一条线，一个仲裁者。** 所有 HUD 提示走 `InteractionPrompts.Set/Clear`（`Data/Events/PromptChanged` 通道），按声明的 priority 仲裁，谁都不许直接 raise 通道。
2. **有交互的提示必须带按键，没有交互的不出现在提示位。** 按键写在每条文案本身里（`[E]`/`[J]`/`[F]`/`[G]`…各用自己真实的键），管线原样透传、不加工。没有统一格式模板，每条文案逐条定。**未扫描的对象不在提示里报物种名**（写"植物/藻类"这类泛称，全名进报告）。**模式内同样适用**：玩家被扣在一个模式里（端详档案、扫描报告、循环终端、密码锁读入、无录音的对话）时，提示位必须列出该模式下**全部**有效的键（例：`[E] 放回  [W/S] 凑近/拉远  [鼠标] 转动`）；模式行以 `InteractionPrompts.k_ModePriority` 上线，压过所有接近提示、让位给追逐提示。手电 `[F]` 教学和"太暗"说明要并入模式行，不许各自抢线。
3. **状态描述不冒充动作提示。** 观察结果属于对话/独白/告示内容；动作提示位只出现玩家现在能做的事。
4. **阻塞要么说清缺什么，要么是记录在案的有意沉默。** blocked 文案非空时说清缺什么（例：`需要先拿着手电筒`）；有意沉默（如符文墙未持瓶、持流程必需品时的换持提示）必须写进本清单，否则空 blocked = bug。
5. **每个按键第一次可用时必须教学。** 新按键（F 手电、G 放下、J 扫描、E 交互）在首次可用的场景里要有一次性提示；"玩家拿着手电却不知道要按 F"就是违反本条的实例。
6. **提示与交互条件一致：够近 + 部分入画**，无准星、无瞄准。任何交互不得要求把屏幕中心对准物体。

## 叙事触发规则

1. **占位文案统一为「啦啦啦啦啦啦」**（英文侧带 `(placeholder)` + 资产 id）。它表示"beat 已接线、文案未写"，不是触发 bug；写入正文即自动消失。禁止使用其他占位串。
2. **删内容必须删干净：** 删除一个 DialogueSO / 交互点时，同一提交里删掉引用它的场景触发器和 prefab；场景里指向已删资产的 DialogueTrigger（提示照常显示、按下无反应）= bug。
3. **flag 种入（checkpoint seed / rescue）是静默快照。** 需要在 flag 已种状态下补播的演出必须实现 `IRescueStateRestoredParticipant`（`CueSequence` 已实现：种入了 `m_startOnFlag` 就会补播）。因此**测试档/checkpoint 里绝不许携带结局分支 flag**（`flow.circulation_core/ring/outer`、`flow.chase_started`），否则入场即触发结局演出。
4. **对话资产一次只播一遍**由 `DialogueSO.m_playsOnce` 管；触发器只管"这次触发算不算数"（`m_fireOnce`）。两者语义不许混用。

## 文案位规范

| 位 | 载体 | 规则 |
|---|---|---|
| HUD 交互提示 | PromptChanged 通道 | 上面管线规则 2–4 |
| 头盔 HUD 通知 | HelmetNotice | 系统语气（"外部污染浓度…"），不带按键；伴随的动作提示单独一条 |
| 对话字幕 | DialogueScreen | 说话人：我 / 小花 / 设备；无录音的台词在面板右上角显示 `[E] 下一句`，有录音的不可跳过、不显示 |
| 无线电 | RadioSequence | 只在 00 章外部通讯有效期内 |
| 报告 toast | `官方探索报告已更新` + 计数 | 只在记录实际入库时弹 |
