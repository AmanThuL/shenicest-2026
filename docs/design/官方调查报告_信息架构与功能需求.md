# 官方调查报告：信息架构与功能需求

> 文档类型: 系统需求（UI + 数据结构）
> 来源: 主策划《官方调查报告 UI 与功能结构需求》
> 状态: 已入库。一级栏目视为锁定，后续章节只增加条目。
> 工程现状: `ReportCategory` / `ReportEntry` / `ScannerReportSectionSO` 已落地，
> 见 [运行时架构说明书](../architecture/运行时架构说明书.md) 与
> [UI与前端契约](../architecture/contracts/UI与前端契约.md)。

## 1. 系统定位

名称暂定：

- 遗迹环境与资源调查报告
- RUINS ENVIRONMENTAL & RESOURCE SURVEY REPORT

该报告是主角执行本次遗迹调查任务时使用的官方记录系统。报告中的大部分内容不需要玩家主动填写，
而是在玩家完成识别、采样、环境调查或关键设施调查后自动更新。

报告的作用：

1. 保存玩家已经获得的官方调查数据；
2. 让玩家查看已发现的植物、环境和设施信息；
3. 将探索过程中发现的异常生态现象记录为独立调查条目；
4. 随主线推进逐渐形成完整的调查结果；
5. 在游戏后期作为是否提交调查成果的对象。

## 2. 总体结构

采用固定主界面：左侧或顶部为一级分类导航，右侧为当前页面内容。

```
遗迹环境与资源调查报告
│
├── 01 调查概况
├── 02 环境记录
├── 03 生物记录
├── 04 设施档案
├── 05 异常记录
└── 06 调查结论
```

这是最终一级结构。后续章节只增加内容，不新增一级 UI 分类。

## 3. 01｜调查概况

展示本次调查任务的基础信息和整体完成状态，固定显示四项：调查编号、调查区域、调查状态、调查进度。

00 章结束后：

```
调查编号：RS-00-237      SURVEY ID: RS-00-237
调查区域：生态研究设施遗址  SURVEY AREA: Ecological Research Facility Ruins
调查状态：进行中          SURVEY STATUS: In Progress
调查进度：05%            SURVEY PROGRESS: 05%
```

UI 需求：作为报告打开后的默认首页，不需要复杂交互。美术重点是建立官方设备界面的视觉基调。
程序需求仅为读取任务基础数据及各模块完成状态。

## 4. 02｜环境记录

二级分类：区域环境、土壤采样、水源采样、污染监测。每完成一次环境调查即增加或更新一条记录。

### 4.1 区域环境

```
区域：遗迹最外部低污染区   LOCATION: Outer Low-Contamination Zone, Ruins
污染等级：低              CONTAMINATION LEVEL: Low
环境状态：稳定            ENVIRONMENTAL STATUS: Stable
```

### 4.2 土壤采样

00 章土壤采样后，类目旁更新为 `土壤样本：01 / SOIL SAMPLES: 01`；点击进入第二层：

```
样本编号：SO-001          SAMPLE ID: SO-001
样本类型：土壤            SAMPLE TYPE: Soil
区域：遗迹最外部低污染区   LOCATION: Outer Low-Contamination Zone, Ruins
污染浓度：低于安全阈值     CONTAMINATION LEVEL: Below Safety Threshold
状态：稳定               STATUS: Stable
```

### 4.3 UI 需求

`左侧 / 上方调查条目列表 → 点击条目 → 右侧显示详细调查数据`。
程序需要支持同一区域或不同区域增加多个环境调查条目。

## 5. 03｜生物记录

二级分类：已确认物种、待确认物种、异常生物。分类依据是**当前数据库匹配状态**，不是玩家发现顺序。

### 5.1 已确认物种

每个条目至少包含：数据库索引、名称、类别、数据库匹配、生长状态、区域、建议。

毯茅采样后类目旁更新为 `已确认物种：01 / CONFIRMED SPECIES: 01`，点击后：

```
数据库索引：BOT-FL-041     DATABASE INDEX: BOT-FL-041
名称：毯茅                NAME: Carpet Fescue (Festuca axonopoda)
类别：草本植物             CLASSIFICATION: Herbaceous Plant
数据库匹配：已确认         DATABASE MATCH: Confirmed
生长状态：稳定             GROWTH STATUS: Stable
区域：遗迹最外部低污染区    LOCATION: Outer Low-Contamination Zone, Ruins
建议：无需采样             RECOMMENDATION: Sampling Not Required
```

### 5.2 待确认物种

保存无法匹配现有数据库的植物，例如：数据库索引「未建立」、名称「未知」、类别「无法确认」、
数据库匹配「未确认」、生长状态「稳定」。

### 5.3 异常生物

保存虽能确认类别、但存在明显异常状态的对象，数据库匹配记为「已确认-低匹配」，生长状态记为「异常」，
建议记为「采样」。

> **待确认**：一级信息架构中「异常生物」的英文标签在原始需求里写作 `UNCONFIRMED SPECIES`，
> 与「待确认物种」重复。落 UI 前需由文案确认，建议改为 `ANOMALOUS SPECIES`。

### 5.4 UI 需求

物种列表 + 详情页。00 章结束后列表包括：毯茅、灰叶藤、细脉藤，以及一个未发现条目。
未发现条目不显示完整名称，可以不显示或显示空白数据块。

程序需要保证：同一种植物无论玩家扫描多少次，只生成一个物种档案。

## 6. 04｜设施档案

保存玩家在遗迹中发现的人工建筑、研究设施和历史资料。二级分类：区域结构、设施记录、历史档案。

- **区域结构**：只记录具有探索意义的空间结构，不记录所有建筑细节。
  00 章外部探索结束后：研究设施外围，已发现结构为主入口与检修入口，当前状态为检修入口可进入。
- **设施记录**：具体设施或房间，每条包含名称、原始功能、当前状态、已发现信息。
  00 章之后可预期的条目：植物研究室、样本储藏区、温室、检修通道。
- **历史档案**：来自海报、旧文件、录音、研究记录、标识的正式历史信息，每条包含信息来源、内容状态、
  可恢复信息。发现植物所海报后：

```
信息来源：研究所宣传资料    SOURCE: Research Institute Promotional Materials
内容状态：部分损毁         CONTENT STATUS: Partially Damaged
可恢复信息：特殊植物收藏与培育项目
RECOVERABLE INFORMATION: Special Plant Collections and Cultivation Programs
```

官方报告不逐字复制环境文本。只有与调查任务相关、或能够作为正式调查证据的信息才进入报告。

## 7. 05｜异常记录

保存无法直接归类为普通环境、生物或设施信息的异常生态现象，例如：不符合普通植物生长规律的植物分布、
周期性变化的环境边界、不同区域生态状态的异常一致性、特殊真菌或植物结构、设施与生态系统之间的异常关联。

统一格式：异常编号、发现区域、发现时间 / 调查阶段、异常类型、当前状态、相关记录。

00 章结束后：

```
异常编号：ANM-001         ANOMALY ID: ANM-001
发现区域：研究设施最外围低污染区
DISCOVERY LOCATION: Outermost Low-Contamination Zone, Research Facility
异常类型：植物形态、分布异常
ANOMALY TYPE: Botanical Morphology and Distribution Anomaly
当前状态：待进一步调查     CURRENT STATUS: Pending Further Investigation
相关记录：BOT-FL-041      RELATED RECORD: BOT-FL-041
```

关联是双向可读的：查看毯茅时显示「关联异常记录：ANM-001」，点击进入异常现象详情。

UI 需求为「异常记录列表 → 选择一条 → 显示异常基本描述 → 显示关联区域 / 生物 / 设施」，
不做成复杂推理板。程序层面只需支持 `Anomaly_ID`、`Location`、`Type`、`Status`、`Related_Records`。

## 8. 06｜调查结论

与其他模块不同，这一部分不由单次调查行为直接产生，而是随玩家完成的关键剧情节点自动更新。
结构为：当前结论、报告状态。

游戏初期：

```
当前结论：数据不足，无法形成有效判断。
CURRENT FINDINGS: Insufficient Data. No Valid Conclusion Can Be Reached.
```

调查结论不等于玩家最终掌握的全部真相，措辞保持正式、谨慎、基于证据的调查语言。

最终 `报告状态：待提交`，玩家可选择【提交调查报告】/ [SUBMIT SURVEY REPORT]
或【暂不提交】/ [NOT YET]。

## 9. 最终 UI 信息架构

```
遗迹环境与资源调查报告 RUINS ENVIRONMENTAL & RESOURCE SURVEY REPORT
│
├── 01 调查概况 SURVEY OVERVIEW
│   ├── 调查编号 SURVEY ID
│   ├── 调查区域 SURVEY AREA
│   ├── 调查状态 SURVEY STATUS
│   └── 调查进度 SURVEY PROGRESS
│
├── 02 环境记录 ENVIRONMENTAL RECORDS
│   ├── 区域环境 REGIONAL ENVIRONMENT
│   ├── 土壤采样 SOIL SAMPLES
│   ├── 水源采样 WATER SAMPLES
│   └── 污染监测 CONTAMINATION MONITORING
│
├── 03 生物记录 BIOLOGICAL RECORDS
│   ├── 已确认物种 CONFIRMED SPECIES
│   ├── 待确认物种 UNCONFIRMED SPECIES
│   └── 异常生物 ANOMALOUS SPECIES（英文标签待文案确认，见 §5.3）
│
├── 04 设施档案 FACILITY ARCHIVES
│   ├── 区域结构 AREA STRUCTURE
│   ├── 设施记录 FACILITY RECORDS
│   └── 历史档案 HISTORICAL ARCHIVES
│
├── 05 异常记录 ANOMALY RECORDS
│   ├── 异常现象 ANOMALOUS PHENOMENA
│   ├── 当前状态 CURRENT STATUS
│   └── 关联记录 RELATED RECORDS
│
└── 06 调查结论 SURVEY CONCLUSIONS
    ├── 当前结论 CURRENT FINDINGS
    └── 报告状态 REPORT STATUS
```

## 10. 给美术和程序的三条原则

1. **所有一级栏目固定。** 后续章节只能向现有栏目增加条目，原则上不新增一级栏目，
   美术只需要完成一次报告框架。
2. **所有记录采用「列表页 → 详情页」的统一交互。** 植物、样本、设施、异常记录共用同一套基本 UI 逻辑。
3. **报告数据必须支持关联跳转。** 一条异常记录可以关联灰叶藤、细脉藤和研究设施；
   可以先不做可视化连线，但数据结构必须预留 `Related_Records`。

## 11. 00 章的最小内容集

00 章只需要实现完整框架，并填充：

```
01 调查概况 └── 当前任务信息
02 环境记录 └── 异色草带边缘土壤采样
03 生物记录 ├── 毯茅 ├── 灰叶藤 └── 细脉藤
04 设施档案 └── 原始生态研究设施 └── 检修入口 / 研究所相关线索
05 异常记录 └── 异色草带
06 调查结论 └── 数据不足
```

后续关卡只需要不断向环境、生物、设施、异常和结论五个核心数据库中填入新的记录。
