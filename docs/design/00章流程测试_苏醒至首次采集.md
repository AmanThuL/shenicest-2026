> 文档类型: Flow Design / 阶段验收
> 来源: 主策划流程总览（飞书同步文档，见 §1.1）
> 状态: 已入库，作为程序、美术、音频与文案的共同施工依据

## 1. 阶段目的

这一阶段不是内容量的目标，而是一次**生产流程的实测**：让团队从策划、文案、美术、技术走到一段实际可玩的内容，
并以此估算后续关卡的开发效率。

流程切片为：

```
黑屏苏醒 → 第一人称移动 → 污染区探索 → 无线电引导 → 接近异色草带
→ 信号消失 → 摘下头盔 → 进入低污染区 → 使用调查工具
→ 完成第一次植物 / 土壤采集 → 官方探索报告更新
```

需要验证的核心问题：

1. 第一人称 3D 探索的基础手感；
2. 环境能否自然引导玩家前进；
3. 无线电与环境叙事能否自然交代背景；
4. 摘下头盔能否形成明确的环境转换；
5. 第一次调查工具教学是否清晰；
6. “调查—识别—官方记录”能否形成完整反馈闭环；
7. 团队完成这样一个基础流程实际需要多少工时。

## 4. 验收标准

### 4.1 玩家体验

- 玩家能够自然知道往哪里走；
- 玩家不会在起始区域长时间迷失；
- 玩家能够理解无线电提供的信息；
- 玩家能够自然发现异色草带；
- 玩家能够理解为什么需要摘头盔；
- 玩家能够成功完成第一次调查；
- 玩家理解调查结果进入了官方记录。

### 4.2 技术

- 从开场到调查完成可以完整运行；
- 不需要通过编辑器手动推进；
- 所有 Trigger 正常工作；
- 无关键流程阻塞；
- 调查完成后报告状态正确更新。

### 4.3 场景

- 污染区、过渡区、异色草带具有明确视觉区别；
- 玩家能够从环境判断前进方向；
- 异色草带能够作为明显视觉目标；
- 摘头盔前后具有明显感官差异。

### 4.4 最终测试闭环

玩家需要能够完整经历：

> 在污染区醒来 → 知道自己需要向前进入遗迹 → 通过环境变化确认正在接近目标 → 失去外部通讯
> → 进入一个安全但未知的生态区域 → 第一次使用自己的调查能力 → 得到关于这个世界的第一条正式记录。

只要这个闭环在实际游戏中顺畅运行，00 章第一阶段流程测试即完成。
此后团队以这一阶段的实际工时为基准，估算后续解谜点和场景的开发成本。
