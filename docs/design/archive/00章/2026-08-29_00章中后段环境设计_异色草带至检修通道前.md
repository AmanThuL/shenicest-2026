# 《Where the Roots Dance》00章中后段环境设计

> 范围: 异色草带、第一次调查、研究设施揭示、正门受阻、设施外围线索、检修入口外部，止于进入检修通道之前  
> 目标场景: `Main_Environment.unity` 与 `Main_Gameplay.unity`  
> 审核基线: `origin/develop@ada1ea6`，2026-08-29  
> 状态: 本轮关卡设计锁定，实施与验证记录见同目录实现记录

## 1. 范围与设计决定

本段从玩家已经安全进入异色草带开始。前段植物释放的绿色“污染”粒子及玩家路线避让问题，归 `00章前段环境设计_起始点至异色草带.md` 负责，本文不移动、不改名、不重做该段 emitter，也不改变前段路线。

本轮采用以下决定:

1. 所有空间先服务策划 checkpoint，再服务景观填充。每个 checkpoint 都必须对应一个明确的观察、交互或理解动作。
2. 保留 `ResearchFacility_GaiaV7` 内温室、植物研究楼和走廊的相对位置、相对朝向与连接关系。本文也不移动设施组根，改 Terrain 台地、接近路线、外围收口和检修入口来适配它。
3. 旧 V3 台地和旧东侧检修坑已经与最新 Gaia 设施错位，不能继续作为后段空间依据。
4. 主路线只到受阻正门。指示牌与海报形成一条短叙事支路，藤本与检修入口形成一条解谜支路；两条支路都从正门失败后开始。
5. 检修入口不再使用旧 `(52,108)` 坑。入口落在 Greenhouse `Door12` 下方的挡土与基础空间，独立 service landing 中心为 `(21.8,137.5)`、地面高 `Y=5`。
6. 不以 performance 预算限制本轮资产丰富度。可以大量使用与风格匹配的 prefab、pure mesh、材质 tint 和共享变体，但不能牺牲可走性、checkpoint 可读性、碰撞正确性与许可合规。
7. 所有可见环境 props 都是实际 prefab instance，并位于 Main Environment 的 `Prefab World Builder/<Palette>/PIN/`。Terrain 和设施固定壳属于 `_Geometry`，灯光与 Volume 属于 `_Lighting`，Gameplay trigger 和状态代理属于 `Main_Gameplay`。

## 2. 核对后的空间基线

### 2.1 最新设施组

最新 Main Environment 已不再以旧 `LabBlockout` 为设计基线。当前固定设施组为 `_Geometry/ResearchFacility_GaiaV7`，包含:

- `Briggs_Greenhouse.fbx`
- `Briggs_PlantResearchLab.fbx`
- `Briggs_LabCorridor01.fbx`
- `Briggs_LabCorridor02.fbx`

设施组根约为 `(0.928,5.596,61.911)`，yaw 约 `-24.47°`；组合世界包围范围约为 `X[-40.18,40.19]`、`Z[99.04,152.96]`、`Y[7.0,35.3]`。这四部分是一个整体，禁止独立挪动其中一栋楼、单独旋转温室或改变走廊连接。

当前 Terrain 台地仍是旧配置: 中心 `(0,126)`、yaw `-45°`、半尺寸约 `(38.87,27.90)`。设施最外侧相对台地最多溢出约 `12.3 m`。所以看似“建筑压住地形”的问题来自台地过小和角度过期，不是设施相对布局错误。

本轮台地锁定为:

| 参数 | 目标值 |
|---|---:|
| 中心 | `(0,126)` |
| yaw | `0°` |
| 最小半尺寸 | `(44.5,31.5)` |
| 平台高 | `Y=7` |
| 外缘过渡 | `8 m`，局部由挡土、排水和植物遮断规则轮廓 |

台地仍是 Terrain 连续可走面。挡土墙、基础、门斗、排水沟和硬边使用独立结构或 props 表达，不能靠 Terrain 做垂直墙。

### 2.2 旧路线为何必须废弃

旧主路在 `(24,106)` 结束，旧侧路从 `(9,87)` 提前分叉到 `(52,108)`。它有三个问题:

- 玩家尚未确认正门受阻，就能绕进检修支路。
- 正门、标牌、海报和藤本 checkpoint 与最新建筑立面没有形成顺序。
- 旧坑远离最新温室下方的真实基础关系，像独立挖出的任务坑。

旧 `(24,106)` 终点、旧 `(9,87) → (52,108)` 侧路和旧 `(52,108,Y=4)` flat spot 均不再使用。

## 3. 以 checkpoint 为骨架的三条路线

### 3.1 主体验线

主体验线承接前段既有路线，到设施揭示后只抵达受阻正门:

`(-12,39) → (-6,52) → (0,66) → 00-08 (1.5,73.5) → (4,88) → (7,103) → 00-09 (9.505,118.941)`

- `00-07` 是近水平调查平台。毯茅和土壤是两个可辨对象，玩家站位中心至少留出 `2.5 m × 2.5 m` 无碰撞负空间。
- `00-08` 是设施首次稳定揭示。树干、土肩和植物先遮住建筑底部，只让温室玻璃与上层轮廓逐步显露。
- `00-09` 是正门失败。远处先读到原入口，近处再读到粗根、灰叶藤、坍塌件与破门框形成的真实阻挡。

### 3.2 叙事短支路

叙事支路从正门返回少量距离，经过指示牌，到西侧旧海报:

`00-09 (9.505,118.941) → 00-10 (7.030,115.759) → (1,113.8) → 00-11 (-4.637,114.699)`

它负责解释“这里曾是什么”和“维护空间在下方”，不直接给出检修入口答案。海报需要位于真实可接近外墙或独立公告板上，不可再落进建筑投影内部。

### 3.3 解谜支路

解谜支路也只从正门失败处开始:

`00-09 → 00-12 (12.334,123.184) → 00-13 (15,127.8) → 00-14 (19.435,133.774) → 00-15/16 (20.7,135.8) → service landing (21.8,137.5)`

地面从台地向入口基础逐步下降，最终 service landing 用 radius `3 m`、blend `6 m` 的局部 flat spot 收到 `Y=5`。下降由挡土、基础、管线和排水说明，不做突然的任务坡。

原 `00-12` 与 `00-13` 只有约 `2.06 m`，在 Scanner `3 m` 选择半径内会让两个目标竞争。把 `00-13` 移到 `(15,127.8)` 后，两种藤本先后可读，玩家不会一次瞄准两个目标。

## 4. checkpoint 位置与状态设计

统一采用 Pre 语义: 进入某 checkpoint 时只预置此前完成的内容，不提前完成当前节点。坐标是玩家安全站位，不是 prop pivot。Y 由最终 Terrain/平台确定；`00-15` 和 `00-16` 必须使用显式高度，禁止向下 raycast 到设施 collider。

| checkpoint | X/Z | 建议 yaw | 进入时已有状态 | 当前节点职责 |
|---|---:|---:|---|---|
| `00-07_FirstToolUse` | `(-12,39)` | `20°` | 已摘头盔、已进入草带；无调查记录 | 测试毯茅与土壤调查本身 |
| `00-08_ResearchFacilityView` | `(1.5,73.5)` | `10°` | 第一次调查完成；报告顺序 `BOT-FL-041` 后 `SO-001` | 设施揭示与后段起点 |
| `00-09_BlockedMainEntrance` | `(9.505,118.941)` | `0°` | 同 00-08；正门尚未判定受阻 | 观察并确认正门失败 |
| `00-10_MainEntranceSign` | `(7.030,115.759)` | `0°` | 加 `flow.main_entrance_blocked` | 读取向下指示牌 |
| `00-11_ResearchFacilityPoster` | `(-4.637,114.699)` | `0°` | 再加 `flow.main_entrance_sign_read` | 阅读旧研究海报 |
| `00-12_AshleafVine` | `(12.334,123.184)` | `16°` | 再加 `flow.research_facility_poster_read` | 第一次稳定识别灰叶藤 |
| `00-13_FineVeinedVine` | `(15,127.8)` | `24°` | 再加灰叶藤扫描记录与 `flow.ashleaf_vine_scanned` | 识别细脉藤差异 |
| `00-14_VineGrowthDirection` | `(19.435,133.774)` | `34°` | 再加细脉藤扫描记录与 `flow.fine_veined_vine_scanned` | 从藤、管线和风扇判断方向 |
| `00-15_ClearAshleafVine` | `(20.7,135.8)` | `32°` | 再加 `flow.vine_growth_direction_observed`；入口尚未显露 | 安全观察位，测试拨开覆盖层 |
| `00-16_MaintenanceEntrance` | `(20.7,135.8)` | `32°` | 再加 `flow.maintenance_entrance_revealed` | 同一安全观察位，测试显露后状态，止于入内前 |

现有 `00-15/16` 使用 `snapToGround` 时会命中建筑屋顶，玩家落到约 `Y=20.1/21.1`，而附近 Terrain 约为 `Y=5..7`。两点应关闭自动吸附，使用基于入口外部平台的明确 Y 与 clearance。`00-15` 和 `00-16` 可以在同一安全平台以覆盖前/覆盖后状态区分，不必为显示节点进度强迫玩家换到屋顶下方的另一个危险点。

`00-07` 不能预置 `flow.first_investigation_done` 或调查记录。`00-08` 之后记录顺序必须是毯茅后土壤，毯茅 ID 从旧 `FL-001` 迁移到策划编号 `BOT-FL-041`。灰叶藤与细脉藤建议分别使用稳定 ID `BOT-FL-118` 与 `BOT-FL-203`。

## 5. 大型建筑与检修入口设计

### 5.1 不移动建筑，重做接线

保留 Gaia 设施组根与内部布局。通过以下三层让建筑落地:

1. Terrain 台地覆盖整个设施投影，并给南侧主门、海报外墙与东侧解谜支路留出可走边。
2. `_Geometry` 提供必要的基础和地形硬边；它们是固定结构，不作为散摆 props。
3. `ResearchWayfinding`、`ExteriorVineClues` 与 `ServiceApproach` PWB palette 提供可见的挡土、排水、管道、格栅、灯具、门斗、碎件与植物侵入。

设施 FBX 已有 collider。入口、主门和外围路线完成后必须实际检查 player capsule，防止透明玻璃、屋顶或隐藏大 collider 切断地面路线。

### 5.2 检修入口落点

Greenhouse `Door12` 平面中心约为 `(22.04,137.94)`，底边约 `Y=9.5`。它适合提供“上方原设施门”的结构依据，但不能让玩家直接爬到高门。

检修入口设为 Door12 下方基础层的独立低位舱门:

- service landing 中心为 `(21.8,137.5,Y=5)`，radius `3 m`、blend `6 m`。
- 挡土和基础解释约 `4.5 m` 高差。
- 短踏步、排水槽、管线和门斗把细脉藤方向收束到门。
- Covered 与 Revealed 使用同一门框、平台、玩家站位和固定碰撞基准。
- 拨开后只切换覆盖藤、阻挡与交互状态，不让整片藤瞬间消失，不改变 Terrain。

## 6. 分区环境设计

| 分区 | 体验职责 | 资产与构图 |
|---|---|---|
| 异色草入口与 `00-07` | 从安全进入转为主动调查 | 银灰绿主色，紫青与褪粉以植物簇聚合；调查平台中部留白 |
| `00-07 → 00-08` | 异常群落逐步变完整，建筑首次显露 | 无碰撞草、蕨、Ivy、苔藓、根石；用高低层次遮建筑底部 |
| `00-08 → 00-09` | 把设施变成稳定远景锚点 | 研究花圃残边、排水石、失控灌木；地面不画连续任务路 |
| 正门前庭 | 让失败可信并形成两个后续方向 | 粗根、破门框、坍塌件、弯栏杆、广泛灰叶藤；中央仍保留读门站位 |
| 叙事支路 | 提供空间和历史信息 | 向下指示牌、旧公告板、少量实验室小件，不做藏宝角 |
| 解谜支路 | 让植物解释人工结构 | 灰叶藤广布，细脉藤少量沿墙缝、管道、风扇和排水连续出现 |
| 检修平台 | 完成发现并建立入内前停顿 | 门斗、格栅、管线、低频风扇、覆盖 A/B、室内暗部与声景 |

异色草带追求色彩 variety，但不是逐株随机彩虹。建议五组共享色系: 银灰绿约 `45%`、冷青绿约 `25%`、暗紫约 `12%`、褪粉约 `10%`、冷黄绿约 `8%`。颜色按局部簇聚合，所有变化保持低饱和、非发光。

### 7.2 暂不采用

- 同步期间新增的 mutant plant boss 模型、贴图与 `BossPulse` shader 服务后续 Boss 内容，与本段 checkpoint、设施外部和草带生态无直接关系，本轮不挪作环境 prop。
- 新增 `SourceArt/Blender/蘑菇簇/...fbx` 形体适合异色草带，但目前没有 Unity prefab、`.meta` 或可核对的来源与许可记录，并含默认 Cube、Light、Camera。许可补齐前不导入可发布的 `Assets/`。
- `BandPoster` 与 `SHA2017Poster` 有现实乐队或拼贴素材，未见发布许可，不用于 Briggs 海报。
- `RuneKeypad` 有许可，但当前节点没有密码锁或键盘交互，不应为了已有模型改写玩法。
- 更多 LabDressing 仪器只作少量叙事陈设，不把室内实验室搬到户外。
- 第四轮候选中的 `Jelly_Mushroom` 仍可作为高模参考，但减面、署名和风格改造成本高；本轮已有足够植被基底，不是执行阻塞项。

### 7.3 仍缺合适成品模型

以下 props 没有真正贴合玩法的现成模型，可由用户继续寻找，也可由项目 pure mesh 加自有材质制作:

- 灰叶藤模块: 小型附着、中型覆盖、正门覆盖、入口覆盖。
- 细脉藤模块: 墙缝、管线、风扇和门缝四种方向性版本。
- Covered/Revealed 同基准入口覆盖。
- 低矮锈蚀检修舱门、短踏步、排水格栅、线缆桥架。
- 户外防水壁灯、旧对讲或接线盒、检修警示牌。
- 慢转换气扇与可靠轴心外壳。
- 毯茅调查英雄簇与少量户外科研样方 props。

这些缺口不阻止本轮先用现有 mesh 拼装和 greybox prefab 执行。灰叶藤、细脉藤和毯茅因承担识别语义，最终仍需要项目专用轮廓，不能只靠 tint 区分。

```text

├── _Geometry

│   └── ResearchFacility_GaiaV7
```

强制规则:

- 植物、岩石、碎件、挡板、标牌、海报板、风扇、管线、门、门斗和可见灯具模型全部在 PWB 下。
- 新增 palette 的 `PIN` 只由本段 builder 清理和重建，不触碰前段 palette 或手调设施组。
- Terrain 和四件建筑固定壳不迁入 PWB。
- 实际 Light、Volume 与 Probe 不伪装成 props；Gameplay trigger、扫描代理和 WorldState 逻辑不放到 Environment 可见层级。
- 需要逻辑的可见 prefab 仍留在 PWB，并通过稳定 ID、组件或锚点与 Gameplay 状态连接。

## 9. Shader、VFX 与后处理边界

### 9.1 材质与 tint

- 可以只使用模型 pure mesh，保留或放弃原纹理，再创建 RootsDance 自有 Shader 与 Material。
- Niwl/TVE 植被优先使用共享 Material Variant，调整 `_MainColor`、tint mask、AO 与风动；不在运行时调用 `Renderer.material` 制造逐实例材质。
- 同一 mesh 可以有多种固定 prefab variant，但颜色由分区权重和簇决定。
- 灰叶藤与细脉藤除颜色外，必须在叶形、茎粗、分枝和分布规律上可区分。
- 异色植物、藤和入口提示均保持非发光。Emission 只用于已有设施微弱设备状态，不用于给答案描边。

### 9.2 VFX

- 拨藤只使用少量叶片、尘屑和形变过渡，颜色接近原植物，不产生绿色孢子喷发。
- 慢转风扇的运动和低频声是空间证据，不是可操作机关。
- 可以用 `FluorescentReveal` 做近距离、断续、磨损的维护痕迹，但玩家不使用手电也应能靠环境找到入口。
- 本段不修改前段污染粒子系统，不复用污染绿色作为安全引导。

### 9.3 后处理

维持全局 HDRP/PSX 基线，不另造一套时间系统。若需要局部气氛，只增加 GrassBand 与 FacilityExterior 两个柔和 Box Volume，控制雾、色调和极轻的 vignette，并与 Night profile 正确叠加。局部 Volume 不改变像素缩放、色阶或曝光体系，不使用强 Bloom、现代霓虹或屏幕提示代替场景构图。
