# 00章中后段环境实现记录: 异色草带至检修通道前

> 设计依据: [00章中后段环境设计_异色草带至检修通道前.md](./00章中后段环境设计_异色草带至检修通道前.md)

> 边界: 不包含前段绿色污染粒子与安全路线修正  
> 用途: 本轮 Unity 执行合同、可重复生成约束与验证回填

## 1. 本轮实现目标

本轮不只是给旧场景增加植物，而是把 Terrain、最新 Gaia 设施、00-07 至 00-16 checkpoints、外围玩法状态和 PWB 布景统一到同一坐标体系。

必须同时完成以下五件事:

1. 将工作树同步到最新 `develop`，保留 Gaia 设施组四件建筑的相对布局。
2. 修正旧台地、旧正门终点、提前分叉的检修侧路和旧 `(52,108)` 坑。
3. 按策划节点重绑 `00-07..00-16` anchors、checkpoint yaws、Pre 状态与调查记录。
4. 在 Main Environment 的 PWB 根下完成异色草带、正门、叙事支路、藤本线索链和低位检修入口外部布景。
5. 用 Unity Editor/batch builder 保存资产和场景，运行测试与场景审计后才合入 remote `develop`。

本文中的 checkbox 是验证记录，不是仅凭设计意图自动完成。执行者必须以 Unity 输出、场景序列化结果和测试日志为证据回填。

## 3. Terrain 实现

### 3.1 固定参数

| 项目 | 实现值 |
|---|---:|
| 设施台地 | center `(0,126)`，yaw `0°`，half extents `(44.5,31.5)`，height `7` |
| 检修 service landing | center `(21.8,137.5)`，radius `3`，blend `6`，height `5` |
| 主路线末端 | `00-09 (9.505,118.941)` |
| 叙事支路末端 | `00-11 (-4.637,114.699)` |
| 解谜 checkpoint 安全观察位 | `00-15/16 (20.7,135.8)`，yaw `32°`，`snapToGround=false` |
| 主路线中段 | `(0,66) → 00-08 (1.5,73.5) → (4,88) → (7,103) → 00-09` |

主路线在 `(0,66)` 以前保持既有参数，不让中后段修正无意改变前段地形。新路线参数由 `TerrainGreyboxParams.CreateDefault()` 和 `TerrainGreyboxConfig.asset` 双向保持一致。

当前 builder 在发现 Gaia 设施组后会保留建筑并提前返回，不能继续用“从旧 LabBlockout bounds 自动推导台地”的逻辑。实现必须显式使用上述台地参数，或更新推导规则使结果完全一致。

### 3.2 收口

- Terrain 负责连续地面与高度下降。
- 建筑基础与确有必要的硬结构留在 `_Geometry`。
- 所有可见门斗、挡土表面、格栅、管线、踏步、标牌、碎件和覆盖植物进入 PWB。
- `TL_Trail` 不在草带和稳定区形成可从远处连续追踪的任务道路。设施近侧只保留被植物和破损打断的维护表面。

## 4. checkpoint 与状态迁移

### 4.1 迁移原则

- `DevCheckpointDefaults.CreateMissing()` 不会覆盖已有资产，因此必须显式迁移并保存已提交 checkpoint。
- 所有 checkpoint 使用 Pre 语义。
- `00-15/16` 关闭 `snapToGround`，使用安全平台的明确高度，避免 raycast 命中设施屋顶。
- 玩家位置、可见 prop pivot、扫描 aim point 和墙挂物位置分别建锚点，不能共用一个 exact point。
- checkpoint yaw 写入 `.asset`，不能只旋转 Environment anchor。

### 4.2 状态顺序

| checkpoint | flags/records 增量 |
|---|---|
| `00-07` | `afterHelmet`，无调查记录，不含 `first_investigation_done` |
| `00-08/09` | `first_investigation_done`；records 为 `BOT-FL-041`、`SO-001` |
| `00-10` | 加 `flow.main_entrance_blocked` |
| `00-11` | 加 `flow.main_entrance_sign_read` |
| `00-12` | 加 `flow.research_facility_poster_read` |
| `00-13` | 加 `BOT-FL-118` 与 `flow.ashleaf_vine_scanned` |
| `00-14` | 加 `BOT-FL-203` 与 `flow.fine_veined_vine_scanned` |
| `00-15` | 加 `flow.vine_growth_direction_observed` |
| `00-16` | 加 `flow.maintenance_entrance_revealed` |

调查 ID 校验应接受项目的 `BOT-FL-041` 一类 compound ID，但仍拒绝空段、重复分隔符和非规范格式。

## 5. Main Gameplay 实现

### 5.1 调查平台

- GrassBelt trigger 与实际入口路径相交，不再留在旧 `(0,32)` 直线路线。
- GrassClump 移到 `00-07` 平台的一侧，作为可辨毯茅英雄簇。
- SoilPatch 移到草带与土壤咬合边缘。
- 两个调查 collider 不重叠，也不与出生 capsule 重叠。

### 5.2 后段交互

- 正门确认、指示牌和旧海报分别写入稳定 WorldState flag。
- 灰叶藤与细脉藤各绑定一个 `ScannableTarget`，扫描完成时写入相应报告和 flag。
- 两个 target 的有效站位不同时落入 Scanner `3 m` 最近目标范围。
- 检修覆盖交互要求细脉藤线索已完成；完成后切换覆盖可见状态、阻挡与 `maintenance_entrance_revealed`。
- 扫描增强理解，但不生成道路、不移动 Terrain、不凭空点亮检修门。

## 6. PWB 布景实现

### 6.1 builder ownership

本段 builder 只拥有以下节点:

```text
Prefab World Builder
├── AnomalousGrassBand/PIN
├── FacilityExteriorEcology/PIN
├── ResearchWayfinding/PIN
├── ExteriorVineClues/PIN
└── ServiceApproach/PIN
```

重复运行时只删除并重建这些 `PIN` 内的实例。现有 `DeadTree_Sparse`、`RootRock_Clutter`、`DryLowGrowth`、`Transition_Growth`、`BrokenBoundary`、`CampEvidence` 与 Gaia 设施组不由本 builder 清理。

### 6.2 放置纪律

- 每个可见对象必须是 prefab instance。
- checkpoint 周围优先保留观察锥、交互距离和 player capsule clearance，再增加密度。
- 通用无碰撞草、蕨、Ivy 与苔藓可以高密度使用；可阻挡大件只放在路线外缘或明确关卡边界。
- 正门阻挡必须有一件远距可读的大轮廓，不能只堆小石头和小藤。
- 灰叶藤在外围多处出现，细脉藤只沿人工缝隙、排水、管线和风扇形成方向。
- 检修入口必须从 `(19.435,133.774)` 的风扇/方向站位开始可推断，但在此前视角不直接露出完整门。

## 7. 资产与材质执行

### 7.1 直接使用

- Gaia 温室、研究楼和两段走廊及其完成材质。
- `GreenHouseStained` 作为远景色块，不把整座设施染成高饱和玻璃。
- `LabNoticeBoard.prefab` 作为 00-11 公告板底盘。
- `LabDressingVariants` 无碰撞植物、根与岩石。
- corridor column/panel、rust 与 ImportedLab 材质组合低位入口。

### 7.2 项目自有派生

- 创建固定的银灰绿、冷青绿、暗紫、褪粉、冷黄绿共享材质变体。
- 若原纹理不适合，可以只保留 pure mesh，使用项目 shader、AO、vertex color 或新 mask。
- tint 不写回 vendor 材质，不创建逐实例 runtime material。
- 组合 prefab 的 collider 只覆盖真实阻挡面，不给 Ivy、草叶或视觉碎件增加复杂 MeshCollider。

### 7.3 暂停项

`SourceArt/Blender/蘑菇簇` 在来源与许可补齐前不进入本轮可发布资产。它不是本轮布景阻塞项。

## 8. Shader、VFX 与气氛实现

- 植物材质风动保持现有项目节奏，tint 非发光。
- `FluorescentReveal` 最多用于少量破损维护标记，并保持不扫描也可读。
- 拨藤 VFX 不使用绿色孢子，不与前段污染语义混淆。
- 风扇使用慢速稳定旋转和低频声，不增加机关状态。
- 如增加局部 Volume，只调整草带和设施外部的雾与色调，保持 Night 与全局 PSX profile 权威。
