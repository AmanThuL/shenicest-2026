接手前先读这一页。温室(GreenHouse1)的玻璃、门窗经过多轮返工,踩过的坑绝大多数不是
建模问题而是**测量问题**:看着对、报告成对、其实错。下面按「现在在哪 / 下一步做什么 /
哪些坑一定会再踩」组织。

## 2. 回填:标准答案已进三份源档

`adopt_ground_truth.py` 跑完后,主档 17 个、玻璃档 1 个、装配档 20 个物件与标准答案
**面面相同**。三份合计 97,202 个存活面的 UV 一个都没被改写,新增的 153 个面
(主档 72、装配档 81)带的是标准答案自己的 UV。

**「多删 8 个」不是浮点误差。** 双开门那一步把每面下层墙的 16 个面(4 个 10.29 m²
窗格 + 12 个中梃面)换成了 8 个重建的洞口侧壁;两组面质心相距 0.8–2.1 m、面积差
到 1472%、连顶点数都从 4 变 3。放宽坐标容差到 1 mm 或改用「面积 + 质心」配对都
够不着这个量级——**只删面永远到不了面数相等,必须同时补面**。

补面只给新面写 UV,不碰其余面的 UV,所以 §3.9「不重建网格」的约束依然成立。

工具的三条保护:

- **重叠率闸门** —— 与标准答案匹配率低于 50% 的物件不动,只报告。`--min-overlap`
  可调,`--replace <物件名>` 强制整体替换。
- **每个 mesh 只改一次** —— 见坑 §3.12。
- **自带验收** —— 跑完逐物件比对面数与面集,任一不等则非零退出。验收标准仍然是
  面数**完全相等**,不是「跑通了」。

仍未回填的三类:

| 对象 | 为什么不动 |
|---|---|
| 19 个 `*-GLASS`(破损版) | 破损链条的产物,与整片玻璃是两种网格,重叠仅 6–34% |
| `B-COLUMN1_T` / `B-WINCOLUMN1_T` | 441 = 441,只是坐标系不同,本来就不用改 |
| `STAIR` | 目标 6,905 面 / 标准答案 782 面,零重叠,整体替换需先定夺 |

## 3. 一定会再踩的坑

### 3.1 `hide_viewport = True` 让物体从依赖图里消失

被这个标志关掉的物体:`matrix_world` 永远不求值、父子关系和 `location` 赋值
**静默失效**、而且**连渲染都不出**。楼梯卡在原点、室内渲染一片空白,都是它。

**处理:任何脚本在读 `matrix_world` 或渲染之前,先把相关物体的 `hide_viewport` 清零。**

### 3.2 集合没链进场景 = 同样的症状

`Goddess` 集合不在场景里,所以给里面的物体设 `scale` 完全无效(重开文件还是 1.0)。
低模女神像最后是把变换**烘进顶点**才对的。

### 3.3 面积是局部坐标的

`polygon.area` 和 `bmesh` 的 `calc_area()` 返回**局部空间**面积。玻璃物件带 2.649 缩放,
世界面积 = 局部面积 × 缩放²。

这个坑造成过一次错误汇报:门叶明明有 22.49 m²,查出来是 3.21(局部值),被 5 m²
的阈值滤掉,于是报告「门叶没建出来」——其实一直都在。

**处理:凡是判断尺寸,一律换算成世界面积。**

### 3.4 正交渲染的左右和坐标是反的

相机的 +x 方向是 `(-normal) × Z = -across`,所以**图像向右 = lat 递减**。
曾据此把左右看反、追错目标好几轮。

**处理:定位问题用几何坐标,不要用截图里的左右。**

### 3.5 镜像配对只看质心会漏

一片漏删的玻璃(0.0162 m²)压在一片正常玻璃(0.0084 m²)上,它的镜像落在后者
质心 1 mm 内,于是被判定「有对称伙伴」而逃过删除。反复修不掉的那个 bug 就是它。

**处理:配对必须同时要求质心接近 + 面积匹配(±30%)。**

### 3.6 逐格投票 + 迭代会级联误删

按网格单元投票删面并反复迭代,会把一块板从 1430 面删到 1289 面还不收敛:
每删一个面,它的位置就变成「空」,下一轮就去删对面的面。

**处理:整面判定(一个面 80% 以上压在对侧的空处才删)、单轮不迭代。**

### 3.7 `subdivide_edges` 不切 n-gon

它给边加切点但面本身不分割,所以 14 m² 的整片玻璃会原样穿过「切格」步骤。
要真正切开用 `bmesh.ops.bisect_plane`。

### 3.8 `audit_glass_coverage.py` 有盲区

它把「离框架 0.35 m 以外的漏光」当作板轮廓外部丢弃,所以**整片开着的窗洞报不出来**。

**处理:查对称性和覆盖用 `audit_panel_symmetry.py`(3 cm 网格,逐格标记
铁/玻璃/空,与镜像格对比)。**

### 3.9 `from_pydata` 重建网格会丢 UV

模块贴图是按 UV 烘的,重建网格 UV 就没了,贴图全部错位。
**删面不改其余面的 UV**,所以回填只能删面。

### 3.10 预览档是生成物

`make_glass_preview.py` 会覆盖两份预览档。手工改动必须先提交或先回填。

### 3.11 磁盘满会把 LFS 文件写成 0 字节

发生过一次:合并时磁盘剩 242 MB,两个文件被截断,其中一个是未提交的改动,
内容无法恢复。

**处理:合并或跑链条前 `df -h`,少于 8 GB 先清理。**
可回收:闲置 worktree 的 `Library/`(各约 4 GB,可重新生成)、
`~/Library/Unity/cache/`(约 6.8 GB,按需重新下载)。

### 3.12 装配档是实例化的,一个 mesh 挂着八个物件

`GreenHouse1_Assembled.blend` 里 8 个 `*-W*_T` 共用同一个 `GreenHouse1Wall`,
8 个 `*-WIN*_T` 共用 `GreenHouse1Window`,柱子和楼梯同理 —— 51 个 mesh 撑起
81 个物件。

按物件名遍历去改 mesh,等于对同一份数据改八遍:第一个物件把它改成标准答案里
`L-W1` 的样子,后面七个再拿 `L-W2`、`M-W1`…… 去比,自然一个面都对不上。
**哪个物件先被迭代到,就静默决定了整个模块拿谁当标准答案。**

**处理:改 mesh 前按 `mesh.name` 去重,一个数据块只改一次。**

## 6. 工作方式

这条线上返工最多的根源是**报告了没有验证的结论**。约束:

- 改完必须用数字验收,不能只看渲染图「像是对的」
- 每种判据先在副本上试跑,看清删/改的数量级再落盘
- 判据要能自证:`audit_panel_symmetry.py` 输出的百分比是测出来的,不是声称的
- 拿不准某个面该删还是该补时,先问,不要挑一个方向做完再说

## 7. 改了面的模块必须连贴图一起重烘

**`uv.mode = unwrap` 的模块,改动面集就等于换掉整张 UV。** `uv_prepare --mode unwrap`
跑的是 Smart UV Project(角度阈值 66°,margin 8/1024),它按当前几何重新排布所有
island。实测:墙体旧版 1,428 面、新版 1,420 面,两版共有的 1,412 个面里
**没有一个 UV 保持不动**,全部位移。烘好的贴图对的是旧排布,几何一变就整体错位。

所以「删面不动 UV,贴图不用重烘」只对 `uv.mode = preserve` 成立。17 个温室模块里
**10 个是 unwrap** —— Column、Floor1、Floor2、Ground、Stair、SpiralStair、Top、Wall、
WinColumn、Window。除 SpiralStair 外都取自 `GreenHouse1.blend`;SpiralStair 取自标准
答案 `GreenHouse1Glass_Preview_Whole.blend`,因为只有那里的 `STAIR` 是新旋梯;另外 7 个 `preserve` 的是 `_TilingJigs` 里的
平面贴图源(四种玻璃、GroundBroken、GroundTile、IronTile),与主档几何无关。

标准答案回填只动了三个模块的源物件:

| 模块 | 源物件 | 面数 | 状态 |
|---|---|---|---|
| `GreenHouse1Wall` | `L-W1` | 1,428 → 1,420 | 已重导 + 重烘 |
| `GreenHouse1Floor2` | `2F` | 363 → 339 | 已重导 + 重烘 |
| `GreenHouse1Window` | `L-WIN1` | 1,430 → 1,427 | **按要求沿用现有贴图,未重做** |

其余 13 个模块的源物件没被回填碰过,不受影响。

`GreenHouse1Window` 因此是有意的例外:Unity 里的 FBX 仍是 1,434 面的旧版,与它现有的
贴图配套、自洽;但它**与源档里 1,427 面的 `L-WIN1` 已经对不上**。谁要重跑这个模块,
必须连三张贴图一起重烘,不能只 `--only export_mesh`。

跑法(Painter 需先带 `--enable-remote-scripting` 启动):

```bash
python3 Tools/pipeline/run_asset.py Tools/pipeline/assets/GreenHouse1Wall.json
```

`asset_inspect_source` 报错是正常的 —— 它读的是原始 SketchUp box mapping,UV 全在
0–1 之外,这正是该模块设成 `unwrap` 的原因。往后每一个 stage 都必须 `ok=true`。

**窗框不应整件隐藏。** Blender MCP 在独立后台场景导入当前建筑
[`GreenHouse1_Textured.fbx`](../../Assets/RootsDance/Meshes/Environment/GAIA1/Buildings/GreenHouse1_Textured.fbx),
核对 8 个 `*-WIN*_T`:每件 1,135 顶点、1,427 多边形、1,996 三角形,本地顶点与
Preview_Whole 的 `L-WIN1` 相同,忽略绕序后的面集也完全相同,没有新增遮挡面。

记录的独立 Window 模块旧面数。

材质源文件使用 `BaseMap RGB → Base Color`、`BaseMap Alpha → Alpha`、
`1 - Mask Alpha → Roughness`,没有 Transmission;法线强度为 0.5。
Dirty/Cracked/Shattered 贴图平均 Alpha 分别约 0.601/0.615/0.613;源作本来就有
灰绿色污垢、雾面和竖纹,不是所有窗格都清澈或有明显染色。GAIA1_v9 中没有分配
Stained 状态。本机纹理路径重连和参考渲染仅发生在后台内存,没有保存源 blend。

[`GreenHouse1TexturedInstaller`](../../Assets/RootsDance/Scripts/Editor/Environment/GreenHouse1TexturedInstaller.cs)
只在 `GreenhouseInterior_Environment` 分配 `GreenhouseInterior/` 下的材质变体,
保留外景父材质:

- 玻璃 `_BaseColor.a = 1`,保留贴图 Alpha 原值,并非改成不透明;关闭 HDRP Refraction,
  使用 Alpha 混合,避免屏幕空间折射设置改变通透表现。
- Smoothness Remap 归一到 `[0, 1]`,让 Mask Alpha 直接决定光滑度,对应 Blender 的
  `Roughness = 1 - Mask Alpha`;法线强度设为 0.5。
- 世界贴图尺度按 `0.5 / (FBX globalScale × prefab root lossyScale.x)` 换算,
  当前约 0.6905005;FBX 厘米转换已由 `useFileScale` 抵消,不要重复乘 100。
- 玻璃双面,关闭额外透明背面 pass;Wall/Window 框架也使用双面变体,使室内能看到
  框架背面。安装器恢复先前被隐藏的上层窗框,重复运行保留已有实例。
- 20 个普通玻璃 Renderer(模型内 18 个、门 2 个)关闭 `shadowCastingMode`,避免 Alpha
  混合表面在光栅阴影中按整面不透明遮光。窗框、植物和 Stained 玻璃继续投影。
  这是实时渲染近似,不等价于 Blender 的物理透射阴影。

本轮未改 mesh、UV、贴图或源 blend。目标是保留原有风化灰绿外观并对齐材质语义;
