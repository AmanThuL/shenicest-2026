## D14 —— 导出轴向与单位 ⚠️ 导出侧已定，Unity 侧待确认

Blender 是 Z-up、Unity 是 Y-up，默认导出会让模型在 Unity 里带着 `scale=100` 或 `rotation=-90` 进来。

**三选一，全队只用一种，选完把结论写回本节**：

1. Blender 里导出前 `Object > Apply > All Transforms`，FBX 导出勾 **Apply Transform**；
2. 导出前把物体 X 旋转设为 `-90` 再导；
3. 用 `darktable/blender-to-unity-fbx-exporter` 这类专用导出脚本。

Maya 用户：直接按 cm 单位导 FBX，Unity 侧 Scale Factor 保持 1。

**验收**：模型拖进场景，Transform 是 **position 0 / rotation 0 / scale 1**，且尺寸与真实世界一致（**1 unit = 1 米**）。做不到就是导出错了——**不要在 Unity 侧用父物体套一层旋转去凑**，那会让所有后续的朝向计算都带一个隐藏偏移。

定不下来的代价是整批返工，所以这条排在所有美术工作之前。

> **补充（2026-08-26）：上面三个选项是按静态道具写的，不覆盖蒙皮 + 动画资产。**
>
> **已定（导出侧）**：带骨骼的资产**不得使用选项 1**。「Apply Transform」在 Blender API 里是
> `bake_space_transform`，其官方说明自带 *"known to be broken with armatures/animations"*。
> 管线的两个导出 profile 均写死 `bake_space_transform: false`。
>
> **待定（Unity 侧）**：建议作为**选项 4** 采用 Unity 的 **Bake Axis Conversion**——官方文档中唯一
> 明说会处理 animation data 的路径。管线现状即按此配置（`bakeAxisConversion = true`、Scale Factor `1`、
> Convert Units 开），并已实测：导入后根 Transform 为 position `0` / rotation `0` / scale `1`，
> 眼高 **1.7432 m**，即 1 unit = 1 米。**技术美术确认后把结论写回本节。**
>
> 逐项设置与实测数据见 [Blender → Unity 导出管线](../tooling/Blender到Unity导出管线.md)。

## D15 —— pivot 与朝向 ⚠️ 对第一人称蒙皮资产不成立

**静态道具**：pivot 放在物体的**接地点**（树、石头、设备的底部中心），正面朝 **+Z**。

**第一人称 / 蒙皮资产：本条按原文不适用，待技术美术补一条专门规则。**

第一人称手臂既没有接地点，也没有通常意义的「正面」——它的参照物是相机而不是地面。
现有 `Arms.fbx` 实测（6000.3.22f1，2026-08-26）：

| 检查项 | 实测值 |
|---|---|
| `camera` 骨世界位置 | `(0, 1.743, 0)` |
| 双手世界位置 | `z = −0.246`（在相机**前方**，沿 `−Z`） |
| 网格 Z 范围 | `−0.458 .. 0.119` |
| 右手 X | `−0.307`（在 `−X` 侧） |

即**资产正面朝 `−Z`**，与本条要求的 `+Z` 相反。

**两个选项，二选一**：把源 `.blend` 整体绕 Z 转 180° 后重导；或在本条为第一人称/蒙皮资产单列
「以相机骨为参照、朝 `−Z`」的规则。**在定下来之前，不要为了「凑 +Z」在 Unity 侧给根物体套一层旋转**——
那正是 D14 要避免的隐藏偏移。

## D16 —— 碰撞体由 gameplay 程序加，不用 `Generate Colliders`

FBX 导入设置里的 `Generate Colliders` 会给每个 mesh 挂凹面 `MeshCollider`——行走判定不稳、性能差、且美术每次重导都会被重置。

**定案：美术交纯外观 prefab；gameplay 程序把它做成 prefab variant，在 variant 上手加 `BoxCollider` / `CapsuleCollider` / 凸包。**

**已实测通过**（2026-08-26）：`Arms.fbx` 导入后 `Collider` 数为 **0**；管线的导入 profile 把 `addCollider` 写死为关。

好处是**美术改外观不影响 gameplay 程序的碰撞与交互组件**，这是整个交接里最省事的一条。

唯一例外：地形本体可以用 Terrain Collider，或美术单独出一份低模碰撞网格。
