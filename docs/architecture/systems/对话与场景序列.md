# 对话与场景序列

> **目标**：让 02 章「通道与温室入口」的**每一句台词、每一个选项、每一段结局演出**都变成资产和 Inspector 里的一行，而不是脚本里的一段代码。
> **适用角色**：gameplay 程序（触发接线）、前端工程师（对话界面）、策划（文案与分支）、场景美术（引导路线与演出）。
> **上层规范**：[表现层驱动契约](../contracts/表现层驱动契约.md)（View 接口边界）、[运行时架构说明书](../运行时架构说明书.md)（命令队列与 WorldState）、指南 [03](../../guidelines/03-architecture-patterns.md) / [04](../../guidelines/04-unity-scripting-rules.md) / [12](../../guidelines/12-odin-inspector.md)。
> **状态**：运行时、内容生成器、EditMode 用例与场景接线均已落地——Bootstrap 常驻件（对话界面 +
> runner + 音频 director + 字幕行）、章节触发器与错误分支序列由 `Wire Narrative Runtime` 生成器维护，
> 台词语音已逐句挂上。**花精灵模型、带路路线与演出资源尚未制作**，见 §7。

## 1. 这套系统解决什么

02 章的节点表里有四类此前工程完全没有的东西：带选项的对话、会带路的 NPC、三选一的终端，以及两条分支各自的结局演出。
`RadioSequenceSO` 只能单向播一串字幕，撑不住其中任何一件。

拆成三块，彼此不知道对方存在：

| 块 | 谁负责 | 产物 |
|---|---|---|
| 说什么 | 策划 | `DialogueSO` 资产（台词、选项、每个选项的回应与后续） |
| 谁在动 | 场景美术 | `GuideCompanion` 的路线点、`CueSequence` 的步骤表 |
| 怎么呈现 | 前端工程师 | `DialoguePresenter`（实现 `IDialogueView`） |

## 2. 运行时结构

```text
RootsDance.Dialogue
├── DialogueSO            # 一段对话：台词 + 选项 + 条件 + 完成时抬的旗
├── DialogueLine          # 一句话：说话人 + 中文 + 英文 + 录音 + 停留秒数
├── DialogueChoice        # 一个选项：文案 + 回应 + 可选的后续对话 + 抬的旗
├── DialogueSpeaker       # 主角 / 小花 / 设备
├── DialogueTiming        # 纯数学：一句话停多久——录音优先、其次手填、最后按字数（可单测）
├── IDialogueView         # 流程 → 界面 的唯一接口（只过字符串）
├── DialogueRunner        # 顺序与时序，挂在 Player 上
├── DialoguePresenter     # uGUI 实现：一句话 + 一列按钮
├── DialogueTrigger       # 进体积 / 抬旗 / 交互 / 手动，四种起手
└── DialogueEventChannelSO

RootsDance.Sequencing
├── CueStepKind           # 等待 / 抬旗 / 开关物体 / 放声音 / 起对话
├── CueStep               # 一步，Odin 按 kind 只显示相关字段
└── CueSequence           # 一段演出，挂在场景物件上

RootsDance.Companion
├── GuideCompanion        # 花精灵带路：到点等人、人到了就走、落太远就回头
├── FollowCompanion       # 花精灵跟随：听旗现身（站到玩家背后）、听第二面旗开始跟
└── CompanionFollowStep   # 纯数学：现身点、跟随环、切回身后的阈值（可单测）

RootsDance.Cameras
├── PanicViewShake        # Cinemachine 扩展：跑步起伏 + 惊慌抖动 + 快速回头
├── ShoulderCheckCurve    # 纯数学：回头的转出/停顿/转回形状与可读窗口（可单测）
├── FreeFallView          # Cinemachine 扩展：失重上浮 + 坠落风噪 + 落地下沉，看竖直速度自动触发
└── FreeFallResponse      # 纯数学：上浮瞬态 / 风噪随坠速 / 落地下沉恢复的形状（可单测）
```

### 2.1 没有节点图，是个决定

对话是「一串台词 + 一组选项，每个选项有短回应，其中一个可能再开一段」。
02 章全部对白都是这个形状。做一个节点图编辑器要一周，而它能买到的分支结构，剧本里并不存在。

选项默认**可重复**：回答完一个，剩下的重新弹出来，玩家能把话问全。中央循环终端把它关掉——那一问只给一次机会。

### 2.2 中央循环终端没有专门的组件

三选一就是三个 `DialogueChoice`，每个抬一面自己的旗（`flow.circulation_core` / `_ring` / `_outer`），
再由挂在盖娅雕像上的 `CueSequence` 按旗放对应的演出。**整章最核心的决策没有新增任何一个类。**

维护记录（培育周期 02–08，其中 06、07 缺失）是读物，不是交互，走既有的档案文档或世界空间文本，不进对话系统。

### 2.3 演出的步骤表长在组件上，不是资产上

`CueSequence` 的步骤要开某一盏灯、某一丛长出来的藤，**场景引用没法序列化进 ScriptableObject**。
演出里可复用的部分（声音、对话）本来就已经是步骤指向的资产。

序列**不等待对话结束**：起了就往下走，好让台词压在结局演出上而不是打断它。
需要「说完了再发生」的节拍，就让对话在 `FlagOnComplete` 抬一面旗，第二段序列听那面旗。

### 2.3b 桥上的相遇是三件事，顺序就是节拍

`ChapterHouseInterior_Gameplay` 桥中央那个体积上挂的是 `CueSequence` 而不是 `DialogueTrigger`：
第 0 秒抬 `flow.flower_sprite_appeared`，第 0.25 秒起 DLG-001。那面旗有两个听众——
小花身上的 `FollowCompanion`（把自己放到玩家背后 2.6 m 并显形）和第一人称相机上的
`PanicViewShake`（放一次快速回头）。**先看见，再听见**：延迟就是转头的时间。

回头复用的是追逐戏那一个 `LookBack`，本关把 panic 旗留空，抖动强度恒为 0，扩展在旗抬起来之前什么都不做。

跟随由对话自己的 `FlagOnComplete`（`flow.met_flower_sprite`）打开——说完话她才开始跟。

**跨关卡不靠常驻对象**：她出现的每个场景各放一份，各自在首帧读一次世界状态；第三章温室里两面旗都已经是抬着的，
所以她自己就在那儿了。和 `ChaseDirector` 的 resume 是同一套理由：旗只广播一次，后加载的场景听不到。

### 2.4 录音挂在台词行上

每句台词自带一个 `Voice` 字段。理由和 `RadioLine` 一样：一段对话里各句除了音频文件没有任何差别，
一句一份 cue 资产等于一个只差引用的文件夹。`DialogueRunner` 上接一次 `Voice Cue`（`VOX_Dialogue`）
和 `Audio Channel`，全部对话共用。完整接入方式见[无线电与对话语音接入](./无线电与对话语音接入.md)。

**有录音的台词不可跳过**：对象池没有"停掉某一个声部"的能力，跳字幕会让上一句的录音压在下一句上。
没有录音的照常可跳，所以在录音到位之前反复试玩不会难受。

### 2.5 阅读时间：两种语言是并读，不是相加

没写停留秒数、也没有录音的行，由 `DialogueTiming` 按字数算：中文默认 5 字/秒，英文 15 字符/秒，
取**两者较慢的那个**，再夹在 1.2–7 秒之间。英文是压在中文底下的字幕，不是接在后面念的，所以相加会让每一句都停得过久。

有录音时这条估算不参与：停留时间取录音长度加 0.35 s 尾巴，手填的秒数只有比它更长才生效。
一句读出来的台词已经由念它的人定过节奏了。

**选项也能有声音**：`DialogueChoice.Voice` 是玩家把那句话说出口，在选中之后、回应之前播——
选项列表这时已经从界面上撤掉，那一拍问题悬在空中正是它要的效果。

第三章已录的对白语音（女主 Mrs. David 与小花 Verity）按录音顺序入库，逐句映射写在
`Build Chapter 02 Dialogue` 生成器里，清单见
[第三章语音资产清单](../../design/assets/chapter03-语音清单.md)。

### 2.6 花精灵不用 NavMesh

剧本对它的要求只有一条：它知道温室在哪，而且比玩家快。一串路线点加一个「玩家靠近就往下走」的半径就够了。
NavMesh 会给每次关卡改动加一次烘焙，换不来任何东西——它是飞的，路线是条走廊。

它**同时**要求自己到位、玩家也到位才前进；只判其中一个，它要么在玩家端详雕像的时候把全程跑完，要么原地不动。
玩家落后超过 `Leash Distance` 就放弃当前点回头接人。

## 3. 报告分类扩展

`ReportCategory` 从两项加到七项：`UnconfirmedSpecies`、`AnomalousSpecies`、`AnomalyRecord`、
`FacilityRecord`、`AreaStructure`。**新值只能往末尾追加**——枚举按整数序列化，重排会把已经写好的每一份调查资产悄悄改档。

`ScannerReportContentBuilder` 相应多生成五个 fed section（04–08）。

温室结局那句「（未）发现立即威胁人员安全的环境因素」还没做：`ScannerReportSectionSO.RequiredFlag`
只能填一面旗，而「选错」有两面（core 与 ring）。要么给它加一个「任一旗」的字段，要么按结局各写一份结论 section。
这是个策划/程序的取舍，留给拍板，没有替它决定。

## 4.5 对话界面预制件

菜单 `RootsDance/UI/Build Dialogue Screen` 生成 `Prefabs/UI/DialogueScreen.prefab`，并把 `DialoguePresenter`
的全部控件引用接好。可重复执行：再跑一次是用新建的树覆盖旧预制件。

结构：

```text
DialogueScreen            # Canvas（Screen Space – Overlay, sortingOrder 10）+ Scaler 1920×1080 + Raycaster
└── Panel                 # CanvasGroup ← m_root，起始 alpha 0
    ├── LineBox           # 底部居中，1280 × 200
    │   ├── Speaker       # ← m_speakerLabel
    │   ├── Chinese       # ← m_chineseLabel
    │   └── English       # ← m_englishLabel，比中文小一号、浅一档
    └── Choices           # VerticalLayoutGroup + ContentSizeFitter
        ├── Choice0/1/2   # Button ← m_choiceButtons，各带中英两行标签
```

三个按钮：02 章剧本给出的最多选项数就是三个（中央循环终端）。

**不建在 Electronic UI Kit 上，是个决定。** 那套组件是给设备读屏用的——扫描仪报告、头盔 HUD——
而一段主角和花精灵的对话不是读数，套上终端皮会说错「谁在说话」这件事。
Kit 本身也还是旧规范的产物（见 `docs/effects/电子类UI组件库规范.md`），建在上面等于继承那份债。

**选项用布局组而不是固定位置**：presenter 用 `SetActive(false)` 藏掉多余按钮，而布局组会把失活的子物件折叠掉。
固定位置的话，两个选项的对话会在第三个按钮的位置留一个洞。

按钮的 `Image` 保持白色，颜色全部放在 `ColorBlock` 里——Button 是**乘**在 target graphic 上着色的，
两边都上色会让每个状态都比作者定的更暗。

字体指向 `Fonts/m5x7 SDF.asset`：m5x7 定拉丁字形，它的 fallback 表把自己没有的字形——剧本里的每一个汉字——
交给 Fusion Pixel。直接指 Fusion Pixel 会让英文也套上中文字面。

## 4.6 错误分支：用镜头演追逐

`PanicViewShake` 是一个 **Cinemachine 扩展**，挂在 `CinemachineCamera` 上。它不移动任何 transform：
`PlayerLook` 拥有根节点的 yaw 和头部的 pitch，`CameraBoneViewBob` 拥有头部的位置，本项目的规矩是**一个轴一个主人**。
扩展在管线的 `Finalize` 阶段往修正通道里加偏移，因此和上面两者都不冲突，
相机对头部的硬锁（`CinemachineHardLockToTarget` + `CinemachineRotateWithFollowTarget`）也不用改。

所有量都从 `Time.time` 直接求值，不逐帧累加——混合期间管线回调一帧可能被调用多次，累加式时钟会让跑步频率翻倍。

### 跑步 + 惊慌

| 参数 | 默认 | 依据 |
|---|---|---|
| 步频 | 2.9 步/秒 | 走廊里惊慌奔跑约 2.6–3.2；**上下起伏按步频，左右摇摆按步幅频率即一半**，因为身体是交替压在两只脚上 |
| 上下位移 | ±2.5 cm | 真人跑步头部上下 5–9 cm 峰峰值；第一人称取约三分之一——玩家自己的头并没有跟着动，全量还原会晕 |
| 左右位移 | ±1.8 cm | 与摇摆同相 |
| 滚转 | ±1.8° | **滚转是第一人称晕动的最大单一来源**，压在 3° 以内 |
| 俯仰 | ±1.0° | 与起伏差四分之一相位，让点头发生在两次落脚之间，否则两种运动读成一种 |
| 抖动 | 0.9° @ 7 Hz | Perlin。这一层才是「怕」，纯跑步循环太规整，不吓人 |
| 起/落 | 0.35 s / 1.2 s | 惊慌来得快、去得慢 |

### 快速回头

**决定「看不看得清」的不是转头速度，是停顿。** 认出「那里有东西」约需 100 ms，
但要找到它、判断它离多远，需要 300–500 ms。转出去又立刻转回来，无论多快多远，玩家什么也没看到。

`ShoulderCheckCurve` 把这条形状抽成纯函数并用 EditMode 守住：

| 参数组（转出/停顿/转回） | 总时长 | **可读窗口** | 峰值角速度 |
|---|---|---|---|
| **0.5 / 0.45 / 0.4（默认）** | 1.35 s | **0.572 s** | ≈ 450 °/s |
| 0.55 / 0.6 / 0.45（保守） | 1.60 s | 0.735 s | ≈ 409 °/s |
| 0.2 / 0.15 / 0.2（偏快） | 0.55 s | 0.205 s | ≈ 1125 °/s |
| 0.25 / 0 / 0.25（无停顿） | 0.50 s | **0.067 s** | ≈ 900 °/s |

可读窗口 = 停留在 95% 以上转角的总时长，比停顿本身长，因为缓动的两端会在满转角附近逗留——
smoothstep 的最后几度是整段运动最慢的部分，这也是转出用缓动而不是线性的原因：
线性会以全速撞到终点，图像还在糊的时候停顿就开始了。

转角默认 **150°**：180° 会丢掉全部前向参照、读成一次剪辑；低于约 120° 又不像在看身后。
回头时跑步抖动降到 45%——人要看清东西会稳住头，而在这个角速度下不稳住就是看不清。

测试里那条 `ReadableSeconds_WithNoHold_CollapsesBelowWhatCanBeRead` 就是把上表最后一行钉死。

### 触发与呼吸声

三个世界旗标：开始惊慌、结束惊慌、回头各一个，因此 `CueSequence` 的抬旗步骤就能驱动，
不需要谁持有相机的引用。

### 跌落：楼梯顶的一跳

错误分支的「震动 + **跌落** + 追逐」里的跌落（温室楼梯顶往下跳）不是脚本演出：
`FreeFallView` 盯着 `FirstPersonController` 的竖直速度，任何一次够快的离地都自动播完整段——

- **失重**：离地一瞬相机短暂上浮（胃部失重感是个瞬态，一秒内必须消失，否则整段坠落都像飘着）+
  缓入的向下俯角（人会看向落点）。
- **坠落**：风噪抖动、慢滚转、轻微 FOV 扩张，全部随坠速在阈值与满速之间平滑增强——
  「迈下台阶」到「坠落」之间不能有可见的开关点。
- **落地**：下沉 + 前倾，深度按触地瞬间的峰值坠速缩放，五分之一处触底、其余时间缓慢恢复——
  膝盖弯下去比站直快，对称的 dip 读起来是相机弹跳而不是身体落地。

形状全部在 `FreeFallResponse` 里作为纯函数被 EditMode 测试钉住。触发是纯物理的，
所以楼梯口不需要任何 Trigger 或序列接线；台阶和马路牙子被离地时长 + 坠速双阈值滤掉。

配套的手感前提在 `PlayerConfig.asset`：重力从 -19.6（两倍真实重力）调到 **-12**，
并新增 **Max Fall Speed = 11 m/s** 终端速度——重力决定坠落开始得多快，终端速度决定它最快落多快；
没有封顶的长坠落会一直加速，读起来是被砸向地面而不是坠落。

### 追逐的另一半：被追的东西

`RootsDance.Chase` 补上镜头之外的部分。Boss 不是对手，是道具：它回放玩家自己的足迹
（`ChaseTrail`，面包屑轨迹，纯逻辑可单测），所以不用 NavMesh 也能过门、绕货架——玩家走得通的路
它必然走得通。速度是一条橡皮筋（`ChasePacing`，同样纯逻辑）：落后加速、贴近减速，
永远吊在 `Desired Gap`（默认 9 m）上，每一次回头都刚好看得见它。**它永远追不上人**——
按 4.6 的设计，怕由镜头演，不设失败状态。

一段追逐跨两个关卡，各有一个 `ChaseDirector`：

| 段 | 场景 | 起手 | 收尾 |
|---|---|---|---|
| 温室段 | `GreenhouseInterior_Gameplay` | `flow.chase_started` 旗（错误分支的 `CueSequence` 抬，或 Dev Play 直接种） | 玩家转身穿过南入口的 `ChaseExitPortal`，请求加载 Main |

## 6. 关于水

**不开 HDRP Water System。** `HDRP_Desktop.asset` 里 `supportWater: 0`，打开它是全管线改动，
要全组重编着色器变体，而它做的是海面与河流的波浪模拟。温室要的是一条**停摆的水槽**加结局那几秒的雕像水流，
一张 Lit 表面把法线贴图滚起来就是全部效果——`WaterFlow` 干的就是这件事。

静止的残留积水（02-11 的采样对象）连滚动都不需要，把 `Is Flowing` 关掉即可；结局由 `CueSequence` 的
开关物体那一步把它打开。

## 8. 测试

EditMode 数组，全部是不依赖场景的纯逻辑。

`ShoulderCheckCurveTests`，10 条——起止都朝前、停顿期间满转角、转出单调不回头、
**转出必须减速抵达**（末四分之一的增量小于中段）、超时归零、负数时长不产生 NaN，
以及两条守住「看得清」的：默认参数的可读窗口 ≥ 0.3 s，且无停顿的参数组必定跌破 0.3 s。

`FreeFallResponseTests`，12 条——失重上浮是个瞬态（长坠落中途必须归零）、风噪随坠速单调增、
落地下沉五分之一处触底且恢复更慢、冲击强度按速度缩放，以及各自的退化区间不炸。

`ChaseTrailTests` 与 `ChasePacingTests`，11 条——足迹按最小间距落点、回放不越过玩家走过的路，
以及橡皮筋速度在落后时加速、贴近时减速且永远不追上。

`DialogueTimingTests`，13 条——
空行落到下限而不是 0、中文按字数线性、**两种语言取较慢者而不是相加**、超长行封顶、
上下限写反了也不会产生一句永远不翻页的台词、阅读速度填 0 不除零；
以及录音相关的五条：录音永远播完、更长的手填停顿仍然生效、有录音时忽略阅读估算、
无录音时回落到手填、两者都无时等价于按字数估算。
