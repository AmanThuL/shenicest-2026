# 音频管线

> **目标**：让"给某件事配一个声音"变成**填一份资产 + 拖一个组件**，而不是在 gameplay 脚本里加一行播放代码。
> **适用角色**：gameplay 程序（触发接线）、前端工程师（音量设置）、技术美术 / 音效（cue 参数与混音）、场景美术（环境床）。
> **上层规范**：[表现层驱动契约](../contracts/表现层驱动契约.md) D20（音频边界）、指南 [09](../../guidelines/09-packages-systems.md)（Audio 一节：唯一 Mixer、`SetFloat` 不能在 `Awake`）、指南 [05](../../guidelines/05-performance.md) §7（单声道、44.1 kHz、音乐流式）。
> **台词怎么接**：见 [无线电与对话语音接入](./无线电与对话语音接入.md)——录音挂在台词行上，本文只管它由哪条 cue 混出去。
> **状态**：运行时、导入管线、生成器与 EditMode 用例已落地；`Main.mixer` 已建好 `Master / Music / SFX / UI` 四组（`Voice` 组仍缺，VOX cue 暂回落到 SFX，见 §3）。2026-08-30 片段全部接入：49 份 cue 里 47 份有声（只剩两份 VOX 按设计不带片段），音乐也有了拍点——对照表见 §9，音乐的旗标表见 §10。

---

## 1. 这套系统解决什么

策划案里每个节点都带声音需求——门开、采样确认、报告更新、通道里的枝叶摩擦、温室的水与风、结局的音乐。
如果每个需求都落成一次 `AudioSource.Play()`，声音就散进了 gameplay 代码，混音时无从改起，
而且 gameplay 代码会开始依赖音频类型。

所以按"**一份 cue 资产 + 一个监听组件 + 一个发声导演**"拆：

| 层 | 谁负责 | 产物 |
|---|---|---|
| 内容 | 音效 / 技术美术 | `AudioCueSO` 资产（片段、混音组、音量音高抖动、循环、冷却、空间衰减） |
| 触发 | gameplay 程序 / 策划 | `FlagAudioCues`、`ChannelAudioCue`、`AudioCueEmitter`、`AmbienceZone` |
| 发声 | 程序（已完成） | `AudioDirector`（对象池）、`MusicDirector`（交叉淡入） |

新增一个声音 = 新增**一份 `.asset`**，再在已有的表里加一行。不写代码。

## 2. 运行时结构

```text
RootsDance.Audio
├── AudioCueSO               # 内容：一个声音的全部参数
├── AudioCueRequest          # struct：播什么、在哪播（频道载荷，零分配），可自带片段
├── AudioCueEventChannelSO   # 频道资产：AudioCueRequested / MusicRequested
├── AudioCuePlacement        # 平铺 / 定点 / 跟随
├── AudioDirector            # bootstrap 上的一次性声音发声端，AudioSource 对象池
├── MusicDirector            # bootstrap 上的音乐，两条 source 交叉淡入
├── AudioVolumeSettings      # 三个音量滑条 ↔ Mixer 暴露参数 ↔ PlayerPrefs
├── AmbienceZone             # 环境床（按地点）：自持 source，玩家进出体积时淡入淡出
├── FlagAudioBed             # 环境床（按剧情）：一面旗开始、另一面旗结束
├── AudioCueEmitter          # 通用发声点：手动 / OnEnable / 玩家进入触发器
├── FlagAudioCues            # 世界旗标 → cue 的对照表
├── FlagMusicCues            # 世界旗标 → 音乐的对照表：一次一首，空 cue 就是「这里不放」
├── ChannelAudioCue          # 文本 / 报告 / void 频道 → 界面音
├── FootstepAudio            # 读控制器的速度与着地，按走过的距离发脚步
├── AudioRouting             # 混音组路径与暴露参数名的唯一出处
├── AudioMath                # 纯数学：线性滑条 ↔ 分贝（可单测）
├── AudioBedFade             # 纯数学：床这一帧的音量（可单测）
├── FootstepCadence          # 纯逻辑：走多远算一步、位移突变不补账（可单测）
└── AudioCuePicker           # 纯逻辑：多片段变体不连播同一条（可单测）
```

### 2.1 为什么走频道，而不是一个静态入口

发声端在 `Bootstrap.unity`，发声的东西在内容场景里。序列化引用跨不过这条边界，频道资产可以。
项目里已有的静态门面只有 `WorldAccess`，它存在是因为世界状态必须有唯一写入口；音频没有这个需求，
所以不新增第二个静态入口——依赖方向保持单向：**gameplay 抛事件，音频监听，gameplay 不链接音频类型**。

载荷是 `struct`，频道是泛型委托，因此一次请求不产生装箱，脚步声这类逐帧可能触发的声音也能走同一条路。

### 2.2 一次性声音走对象池，循环床不走

`AudioDirector` 用 `UnityEngine.Pool.ObjectPool<AudioSource>` 管理声部。
不用 `AudioSource.PlayClipAtPoint`：它每次创建并销毁一个 GameObject（指南 05 禁止的逐帧分配），
而且**无法指定混音组**，等于每次调用都违反指南 09 第 13 条。

声部的回收按**算出来的结束时刻**（`clip.length / pitch + 余量`），不轮询 `isPlaying`：
两种都能用，但时钟在声部启动的那一帧没有边界情况，代价也只有一次比较。

循环的 cue 被一次性池**拒绝**并给出警告——池化声部靠结束回收，永不结束的声部就是泄漏的声部。
环境床与音乐各自持有自己的 source，但参数仍从同一份 `AudioCueSO` 读取，因此床和一次性声音在同一处混。

### 2.3 请求可以自带片段

台词是唯一"每一次播的都是不同文件、但混音完全一样"的声音。为它每句建一份 cue 资产，
`Data/Audio/` 会变成上百个只差一个引用的文件。所以 `AudioCueRequest.Voice(cue, clip)` 让请求带上片段，
cue 只提供混音组、音量和空间设置，导演优先播请求里的那一条。
片段挂在 `RadioLine` / `DialogueLine` 上，接入方式见[无线电与对话语音接入](./无线电与对话语音接入.md)。

## 3. 混音器：整条管线唯一的手工步骤

Unity 没有公开 API 创建 `AudioMixer`、添加组或暴露参数。因此 `Main.mixer` 由人工创建一次：

1. 右键 `Assets/RootsDance/Audio/Mixers` → Create → Audio Mixer，命名 `Main`。
2. 在 Audio Mixer 窗口里，于 `Master` 下新增四个组：`Music`、`SFX`、`UI`、`Voice`。
3. 逐个选中组，在 Inspector 里右键 Volume → Expose 'Volume (of \<group\>)' to script。
4. 在窗口的 Exposed Parameters 下拉里改名为 `MusicVolume`、`SfxVolume`、`UiVolume`、`VoiceVolume`。
5. 执行菜单 `RootsDance/Audio/Validate Mixer` 确认，再执行一次 `RootsDance/Audio/Build Audio Cue Library`。

两个菜单项的先后不重要：cue 库在混音器还不存在时也能生成，只是 output group 为空；混音器建好后再跑一次，
生成器会把**仅仅是没有 output group 的**既有 cue 补上组，其余字段一律不动。

`Voice` 单独成组，而不是并进 SFX：无线电和对话是全场唯一必须听懂的声音，
混在风声和脚步里就意味着让台词听清的唯一办法是把别的都调小；独立成组也是后面做"通讯压低环境"这类
snapshot 的前提。

**但它是可选的。** 混音器只能手工编辑，而 `Main.mixer` 在 `Voice` 出现之前就已经建好了。
所以 `AudioRouting.k_OptionalGroups` 把它标成可选：没有这个组时 VOX cue 回落到 SFX（`k_FallbackGroup`），
校验器给出上面第 2、3、4 步的具体做法而不是报错——一个没路由的 cue 是哑的，一个路由到 SFX 的 cue 只是混音待改。
组补上之后再跑一次 `Build Audio Cue Library` 并不会自动把它们搬过去（生成器只填空的组），需要手工改这两份 cue 的 Output Group。

代码通过 `AudioRouting` 里的常量寻址这些名字。改名或删组不会报编译错误，只会在运行时静默失效
（音量滑条什么也不做），所以 `AudioMixerValidator` 的存在意义是把这种沉默变成一条带修法的报错。

## 4. 导入设置由文件夹决定

`AudioClipPostprocessor` 在导入时按路径套用 `AudioImportProfile`，与贴图管线按后缀套用的做法同构：

| 文件夹 | 声道 | 加载方式 | 压缩 | 为什么 |
|---|---|---|---|---|
| `Audio/Music/` | 立体声 | Streaming | Vorbis 0.7 | 同时只有一首，不常驻内存 |
| `Audio/Ambience/` | 立体声 | Streaming | Vorbis 0.6 | 床要有宽度；整关都在放 |
| `Audio/SFX/` | 强制单声道 | Decompress On Load | Vorbis 0.5 | 定位音由引擎声像，立体声像本来就被丢弃；要解码才响的一次性音会迟到 |
| `Audio/Voice/` | 强制单声道 | Compressed In Memory | Vorbis 0.5 | 台词够长，全解码浪费；又不值得占一个文件句柄 |

统一重采样到 44.1 kHz。落在 `Audio/` 下但不在这四个文件夹里的文件会被**警告并原样保留**，
`Assets/ThirdParty/` 下的厂商音频不在管辖范围。

`preloadAudioData` 与 `loadInBackground` 保持 Unity 默认值：这两个字段在 6.x 的归属（importer 还是
sample settings）没有在本仓库的参考文档里得到确认，写错会引入过时 API 警告，而收益只是消除一次加载卡顿。

  因此有录音的台词不可跳过（见[语音接入](./无线电与对话语音接入.md) §1.1）。
- Mixer snapshot 切换（室内外、通讯压低环境、结局）与任何 DSP 效果；当前只有四个音量参数。
- 遮挡与混响分区。HDRP 与音频无关，这是纯 Unity Audio 侧的后续工作。

## 8. 测试

EditMode，全部是不依赖 Unity 运行时状态的纯逻辑：

- `AudioMathTests` —— 线性滑条到分贝的映射：满值即 0 dB、0 落到下限而不是负无穷、半程约 −6 dB、往返一致、单调。
- `AudioCuePickerTests` —— 多片段变体永不连播同一条、不会因为跳过上一条而让某条不可达、随机数越界与片段表变短都不抛。
- `AudioImportProfilesTests` —— 四个文件夹的归类、厂商目录不归本管线、SFX 单声道且解压加载、长音频流式且保留立体声。
- `AudioBedFadeTests` —— 床的淡入淡出：零秒即到、按时长走完、长帧不过冲、按自身音量范围计速、
  混到静音的床不卡住、暂停时保持不变。
- `AudioClipBinderTests` —— 片段表：一份 cue 不会被写两遍、每行都有片段、同一份 cue 里不重复列同一个文件、
  片段所在文件夹与 cue 前缀一致（否则 §4 的导入设置会套错一档）。
- `MusicWiringTests` —— 音乐拍点表：旗标必须是 `WorldFlags` 声明过的、一面旗标只有一个拍点、
  每个拍点指向的 cue 在片段表里确实有片段。
- `FootstepCadenceTests` —— 按距离计步：不足一步不响、跨帧累计与单帧等价、stride 填 0 不响（而不是每帧都响）、
  位移突变最多两步且不补账。

PlayMode 一组，因为要测的恰恰是帧的顺序：

- `FlagMusicCuesTests` —— 开场曲在第一帧之后确实在响（这就是它发在 `Start` 而不是 `OnEnable` 的理由：
  同一个物件上的两个组件之间没有保证的顺序，导演可能还没订阅）、一面旗标换一首、
  标了"停"的行真的把音乐停掉、没填完的行与表里没有的旗标都不动当前这首。

## 9. 片段从哪里来，落到哪份 cue

素材来自 2026-08-29 的试听库（完整 723 个文件在分支 `content/music-and-sounds` 的
`SourceArt/music and sounds/` 下），选择结果是 `roots-dance-audio-selections.json` 的 25 个场景条目。
`Assets/RootsDance/Audio/` 里只放选中的 46 个片段：整份试听库进 `Assets/` 会让每次导入多算七百个文件，
而其中绝大多数永远不会响。授权与制作人员表要求见 [第三方记录](../../third-party.md)——两条 CC BY 必须署名。

对照表写在代码里（`AudioClipBinder.k_Bindings`），不是靠 Inspector 拖：拖一次没有 diff、不能复核，
cue 资产重建后也就没了。换一个声音 = 改一行 + 跑一次菜单 `RootsDance/Audio/Bind Audio Clips`；
它是幂等的，只碰表里列出的 cue，找不到文件就报错并原样留下那份 cue，而不是把它清空。
批处理入口 `AudioClipBinder.BuildAndBindBatch` 先建 cue 再绑定，有一行绑不上就以非零退出。

### 9.1 与选择表不一致的六处，以及原因

1. **两条呼吸对调。** 选择表把跑动呼吸选为「头盔呼吸」主选，但 `AMB_HelmetBreath` 从章节第一帧一直响到
   摘盔，站着不动的人不喘气。跑动版因此给了 `AMB_PanicBreath`（错误分支的急促呼吸，§6），
   平静版给常驻床。
2. **一个选择 → 一族 cue。** 脚步和界面各只选了一个文件，而 cue 是按地面、按用途分开的。缺的几份
   从**同一个音源包**里取兄弟文件（Kenney Impact 的三套脚步、Kenney Interface 的确认 / 点击 / 错误 /
   提示），这样一族声音仍然像出自同一个库；换掉其中任何一条都是改 `k_Bindings` 的一行。
3. **脚步用整套五个变体。** 一条样本按走路频率重复会听成机器；`AudioCuePicker` 已经保证不连播同一条。
4. **`Pollution_Wind_Loop` 不在选择表里**，但它和被选中的两条污染床是同一次合成的产物，
   给了 `AMB_FacilityExterior`（研究设施外围），否则那张床没有素材。
5. **`MUS_` cue 的 pitch jitter 统一置 0。** cue 默认的 ±0.05 是给一次性道具音防「听成同一条样本」用的，
   落在整首曲子上接近半个音，交叉淡入时两条还会互相跑调。绑定时按前缀归零（`AudioClipBinder.BindOne`），
   §6 里既有的两份音乐 cue 也一并修正。
6. **两处选择没有进 `Assets/`。** 宣传片配乐（`Wildflowers.mp3`）与宣传片剪辑音效只用于视频剪辑，
   进构建只会白占体积；地下菌丝的 SFX 选择是一次性开合声，而 `AMB_UndergroundNetwork` 是循环床，
   接上会听见接缝，所以那份 cue 留空（见 §7）。

### 9.2 合成出来的那十三段

试听库里没有一段能循环的素材——它全是一次性音，接成床每次回绕都听得见接缝——也没有任何水声。
所以九张床和四段水声由 `Tools/audio/generate_beds.py` 合成，脚本进仓库，参数改一行就能重出。

做法是**在频域里造**：给一段随机相位的频谱做逆 FFT，长度正好是循环长度，出来的信号按定义就是周期的，
循环点逐样本连续，不需要交叉淡化去盖接缝。上面叠的每一层调制也都取 1/时长 的整数倍，理由相同。
床之间按 **RMS ≈ −24 dBFS** 对齐而不是按峰值：一张稀疏的沙沙床和一张连续的低频床峰值一样时，
前者在同一个 cue 音量下几乎听不见。

出品是 48 kHz 立体声 16 bit（床）与 48 kHz 单声道（水声），导入时按 §4 的文件夹规则重采样到 44.1 kHz。
它们是**占位**：长度、频谱和循环行为都对，音色是数学味的。换成真素材时保持文件名不变，
表和接线都不需要动。

## 10. 音乐的拍点

`MusicDirector` 只管交叉淡入，它等一个 `MusicRequested` 事件——在 2026-08-30 之前没有任何东西发这个事件，
所有音乐 cue 因此是"有片段、没人点播"。补上的是 `FlagMusicCues`：和 `FlagAudioCues` 同一个形状，
听同一条 `FlagRaised` 频道，但发到音乐频道。

**为什么不并进 `FlagAudioCues`**：音乐不是"多一个声音"。同一时刻只有一首、它交叉淡入而不是叠加、
永远不定位，而且"从这里开始什么都不放"是一个真实的剧情拍点——一次性表里的空行只能表示"这行还没填"。
两张表分开，每一行读起来才是它本来的意思：这边一行是一次转场，那边一行是一声响动。

表由 `RootsDance/Audio/Wire Music` 写入 `Bootstrap.unity`（幂等，只重写这一个组件的字段）：
