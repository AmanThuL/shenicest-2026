# 纸张折痕 —— 研究与参数推导

> **目的**：把"折痕"从"照着感觉调 shader 参数"变成**可推导、可复核的数字**，并说明为什么第一版
> 的做法在结构上就是错的。
> **适用角色**：程序（shader 与合成架构）、技术美术（贴图与参数）。
> **关联**：[旧档案：拾取与阅读](旧档案拾取与阅读.md) §2、指南 [07](../../guidelines/07-rendering-hdrp.md)。
> **状态**：结论已定，实现见 §5 的改造清单。

---

## 1. 第一版错在哪（两条，第一条是结构性的）

### 1.1 折痕只折了纸，没折纸上的东西

第一版把纸和纸上的内容做成**同一个 Canvas 上的不同图层**：纸在最底下由 `ArchivePaper` 打光，
洗白块、照片、印章、文字各自画在上面。于是折痕只改变了**纸那一层**的明暗，
上面的字、照片、印章**完全没有形变，也没有跟着折痕明暗变化**。

这在物理上讲不通：**墨是在纸上的**。纸被折，墨也被折 —— 折谷处的字会被压暗、被挤窄，
折肩处的字会被拉亮。少了这一层，画面读起来就是"一张纸的照片上面贴了一层字"。

外部资料也是同一个结论：表现明显褶皱的法线贴图
"应当主要与相应的顶点形变配合使用"（[Game Dev Bill, Paper Shader in Unity](https://gamedevbill.com/paper-shader-in-unity/)）
—— 只给明暗、不给形变，褶皱就假。

**所以这不是调参能解决的，是合成架构要改。** 见 §4。

### 1.2 折痕宽度差了一个数量级

第一版折痕用的是 Mexican-hat 剖面 `(d²-1)·e^(-d²/2)`，`width = 0.013`（纸高的比例）。
该剖面在 `d ≈ ±3.5` 之外才衰减到 0，所以**可见折痕总宽 ≈ 7 × 0.013 × 192 mm ≈ 17 mm** ——
一根手指那么宽。真实值见 §3，应该在 **2–4 mm**。

## 2. 折痕在物理上是什么

折纸是**塑性形变**：折线上的纤维被压溃、被拉断，不再回弹；折线两侧一小段是**弹性弯曲**，
松手后大致回平但留有弧度。所以一道折痕在光学上是三段，而不是一条线：

| 区段 | 成因 | 外观 |
|---|---|---|
| **折谷**（valley） | 纤维压溃，塑性，不回弹 | 一条**很窄**的暗线；积灰积油，比周围脏 |
| **折肩**（shoulder） | 弹性弯曲区，纸面在此转回平面 | 比纸面**亮**的一条带 —— 这才是"看起来像折痕"的主因 |
| **平面** | 未变形 | 纸本色 |

关键：**折肩的高光比折谷的暗线更重要**。只画暗线，读起来是一道脏印子，不是折痕。

另外，折谷处纸更粗糙（纤维断口）、折肩处纸更光滑（被指甲/桌面压光），所以
**粗糙度沿折痕是变化的**，不是常数。

---

## 3. 数字从哪来

工业压痕（creasing）有公开的规格，可以用来反推手折纸的量级。
Holmen 与 Metapaper 的压痕资料给出：

- 压痕**宽度约 1–1.2 mm，深度 0.4–0.8 mm**；
- 适用板材**厚度 0.17–0.6 mm**（决定因素是厚度而非克重）；
- 压痕"越深越窄越好"，宽而浅的压痕折不利索。

（[Holmen, Creasing and Folding Paperboard](https://www.holmen.com/en/board-and-paper/insights/paper-academy/paperboard-creasing-and-folding/)、
[Metapaper, Creasing and Scoring](https://www.metapaper.io/en/wiki-articles/creasing-and-scoring/)）

由此得到比例关系：**折痕宽度 ≈ 2–6 倍材料厚度**，取中值约 3 倍。

本作的纸是研究员随身携带的散页，按常见办公纸 80 g/m²：

| 量 | 值 | 推导 |
|---|---|---|
| 纸厚 | ≈ **0.10 mm** | 80 g/m² 办公纸的典型厚度 |
| 折谷宽 | ≈ **0.3 mm** | 3 × 纸厚 |
| 折肩宽（单侧） | ≈ **1.5 mm** | 手折并摊开后的弹性弯曲区，比机器压痕宽 |
| **可见折痕总宽** | ≈ **3.3 mm** | 0.3 + 2 × 1.5 |

换算到画布单位（纸宽 0.16 m = 1000 单位，即 **6.25 单位/mm**）：

| 量 | mm | 画布单位 | 占纸高(1200)的比例 |
|---|---|---|---|
| 折谷 σ | 0.15 | **0.94** | 0.0008 |
| 折肩 σ | 0.75 | **4.7** | 0.0039 |
| 可见总宽 | 3.3 | **20.6** | 0.017 |

**对照第一版：可见总宽 17 mm → 应为 3.3 mm，宽了约 5 倍。**

## 4. 剖面函数：两个高斯，不是一个 Mexican hat

Mexican hat 把折谷和折肩绑死成同一个宽度，而实测两者相差 5 倍。改成**两项独立的高斯**：

```
h(d) = -A_v · exp(-(d/σ_v)²)        // 折谷：窄、深
     + A_s · exp(-(d/σ_s)²) · sign-symmetric   // 折肩：宽、浅、正
```

取 `σ_v = 0.15 mm`、`σ_s = 0.75 mm`、`A_s / A_v ≈ 0.35`（折肩的抬升远小于折谷的下陷）。
这样折谷是一条细线，折肩是它两侧各约 1.5 mm 的亮带 —— 与 §2 的三段结构对上。

## 5. 架构改造：内容必须和纸一起被折

要让**字也跟着折**，可选方案与取舍：

| 方案 | 做法 | 为什么不行 / 行 |
|---|---|---|
| A. 每个图层各自在 shader 里做 UV 扭曲 | 每种材质都采样同一张折痕图 | ✗ **文字用 TextMeshPro 自己的 SDF 材质**，改不到；且每层要各自算一遍 |
| B. 顶点形变 | 按折痕位移顶点 | ✗ uGUI 一个 Graphic 只有 4 个顶点，没有可位移的密度 |
| C. **先合成到 RenderTexture，再整体折** | 纸+洗白块+照片+印章+文字画进一张 RT，然后**只对这张 RT** 做 UV 位移 + 光照 | ✓ 文字自然跟着折；一次 draw call；折痕对所有内容一致 |
| D. 离线烘进 base map | 把文字烘进纸的贴图 | ✗ 文案是数据驱动的，运行时才知道 |

**结论：走 C。** 内容在 `Bind` 时是静态的（读的时候文字不会变），所以合成**只需要做一次**，
之后每帧就是一张 RT 加一个 shader，比现在的多图层还便宜。

改造后的结构：

```text
Sheet (world-space canvas)
├── Composite (RawImage, 材质 = ArchivePaperFold)   ← 运行时唯一可见的那一层
│     _MainTex      = 合成好的 RT（纸 + 全部内容）
│     _FoldTex      = 折痕场（R: 高度  GB: 梯度）
│     位移: uv -= 折痕梯度 × _WarpStrength
│     着色: 折谷压暗、折肩打高光，用 §4 的剖面
└── Content (Bind 时渲染进 RT，之后 SetActive(false))
      └── 纸 / 洗白块 / 照片 / 印章 / 胶带 / 文字 …
```

`ArchivePageStage` 已经在做"把一页渲进 RT 再读出来"这件事，合成这一步可以复用它的相机设置。

## 6. 验收标准（写成测试，不靠看）

现有 `ArchivePageRenderTests` 的 A/B 手法（同一页渲两遍，关掉某一层，比较像素）正好能验这两条：

1. **折痕宽度**：沿垂直于折线的方向取一条像素线，量"偏离纸面均值超过阈值"的连续区间宽度，
   断言其 **≤ 5 mm 对应的像素数**。第一版会直接失败。
2. **内容跟着折**：渲两遍 —— 一遍开折痕、一遍关折痕 —— 断言**文字区域的像素也发生了变化**。
   只折纸不折字的实现，在文字区域两张图会一模一样。

第 2 条正是第一版漏掉的东西，把它写成测试就不会再漏第二次。

## 7. 折痕的**走向** —— 第一版研究漏掉的那一半

### 7.1 研究方法上的错误

§3 的数字来自**工业压痕**（creasing rule 压进 groove 的模切工艺）。截面尺寸拿来用没问题，
但那套工艺的另一个属性被**不声不响地一起继承了：笔直**。

压痕之所以笔直，是因为它是一条钢刀压出来的。而本作的纸是研究员在野外用手对折的散页 ——
**没有任何东西保证它是直的**。更讽刺的是：机器压痕的存在意义，恰恰是为了消除手工折叠会产生的
那种粗糙不齐的折痕。也就是说，第一版查的是"如何避免我本该做出来的效果"。

### 7.2 手工折痕为什么不是直线

纸有**纤维方向（grain）**，这决定了折痕的性格：

- **顺纹折**：折线与纤维平行，压断的纤维少，折痕**干净、连续、结实**；
- **逆纹折**：折线横切纤维，大量纤维被**撕断**，折痕**粗糙、发白、断续，容易裂**。

（[iBookBinding](https://www.ibookbinding.com/blog/paper-grain-direction-and-cardboard-grain-direction/)、
[The Natural Paper Company](https://thenaturalpapercompany.com/en-us/blogs/news/guide-to-paper-grain-direction)）

再加上手工折叠本身的三个特征：

| 特征 | 成因 | 建模 |
|---|---|---|
| **中线游走** | 对齐靠目测，指甲从某点起沿着走，走到哪算哪 | 沿折痕方向的低频噪声，幅度 **±1–2 mm** |
| **整体偏斜** | 两边没对齐，折线与纸边不垂直 | 沿长度方向的线性偏移，**±1 mm** 量级 |
| **深浅不均** | 手指压力不匀，起手处最重，末端最轻 | 沿长度的中频噪声（0.55–1.0）× 两端衰减 |
| **断裂/白痕** | 逆纹处纤维成段撕断，不是连续压溃 | 高频噪声过阈值处**局部近乎消失**，形成断续 |

关键一点：**折痕的深浅沿它自己的长度是变化的，而且会断。** 一条从头到尾等深的线，
无论截面多准，读起来都是印上去的，不是折出来的。

### 7.3 验收

现有的宽度测量只在一处取样，等深直线也能通过。补一条：**沿折痕长度多点取样，
断言折痕中心位置的偏差 ≥ 0.5 mm，且深度的变异系数 ≥ 0.15** —— 完美直线两项都会是 0。

## 8. 重做：折痕**不是纸上的一条线**

前面 §1–§7 全部建立在一个没被质疑过的前提上：**纸是平的，折痕是画在上面的一条线**。
所以无论截面多准、走向多歪、内容跟不跟着变形，做出来的东西都还是"一张平纸 + 一道印子"。
**这个前提本身是错的。**

### 8.1 折过又摊开的纸，眼睛实际看到的是什么

一张对折过再摊开的纸**不会回到平面**。折痕两侧是两个**夹角不等于 180° 的面板（panel）**——
折叠状态由 crease angle 唯一决定，完全摊平时各二面角才等于 π，而现实里它永远回不到 π。
（[Misseroni et al., *Nature Reviews Methods Primers* 2024](https://www.daraio.caltech.edu/publications/Misseroni_et_at_2024.pdf)）

于是：

| 看到的 | 来自 |
|---|---|
| **每块面板亮度不同、各自带一条缓慢的渐变** | 面板法线不同 → 受光不同。**这是折痕最主要的视觉特征** |
| 折痕处亮度**突变** | 两块朝向不同的面板在此相接 |
| 一条很细的线，常常是**发白**的 | 纤维被压裂、被压光，比周围亮，不是暗 |
| 折缝附近的阴影 | 面板翘起处的遮蔽 |

折纸产生的阴影与渐变正是由纸面各处的起伏造成的，最亮的部分出现在纸层之间抬起的空隙处
（[ITSLIQUID, Folded Light](https://www.itsliquid.com/folded-light-art-design.html)）。

**结论：折痕的主体是"面板"，不是"线"。** 一道线只是两块面板的交界，是附属细节。
只画线不画面板，做出来必然读成"印上去的印子" —— 这正是前七节反复调参也调不出来的原因。

### 8.2 量级

散页对折后摊在桌上，每道折的二面角偏离平面通常 **2–8°**。
本作纸宽 160 mm，若分三栏，每块面板约 53 mm；**4° 的倾斜意味着面板远端离开平面约 3.7 mm**。
朗伯着色下，两块相差 4° 的面板亮度差可达 **5–15%** —— 一眼就能看见，
而这正是前面版本里完全不存在的东西。

### 8.3 正确的建模方式

高度场不该是"若干条细缝之和"，而应该是**分段线性的面板**：

```
slope(t)  = Σ_k  Δslope_k · step(t − fold_k)      // 每道折改变一次斜率
height(t) = ∫ slope = Σ_k  Δslope_k · ramp(t − fold_k)   // ramp 在折线处按 bend 宽度圆滑
```

这样得到的就是：**几块各自倾斜的平面板 + 在折线处圆滑过渡**。
§4 推导的那条 valley/shoulder 截面依然有用，但它降级成**叠加在交界处的一道细节**，
而不再是折痕的全部。

### 8.4 验收

- **面板亮度差**：取相邻两块面板中心，断言渲染亮度差 **≥ 3%**。只画线的实现两块一模一样。
- 原有的细线宽度、内容形变两条继续保留。
