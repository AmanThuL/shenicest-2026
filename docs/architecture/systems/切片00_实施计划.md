## 2. 第一人称移动

**D4**：用 `CharacterController`，**不用** Rigidbody（`guidelines/09` 第 9 条）。同一物体上绝不同时挂两者。已知性质：CC 不响应外力、不会自动推开 Rigidbody、查询用的胶囊会略微收缩（贴边 raycast 可能落空）——本切片都不构成问题。

**D5**：相机走 Cinemachine 3.1，全项目只有一个 `Camera` + 一个 `CinemachineBrain`，放在 `Bootstrap.unity`；每个镜头是一个 `CinemachineCamera`，切镜头靠激活/关闭 GameObject（`guidelines/09` 第 6 条）。
第一人称 = 一个跟随 `Head` transform 的 `CinemachineCamera`，视角旋转由 `PlayerLook` 直接写 `Head`。**不要让 Cinemachine 和自写代码同时控制同一个旋转轴**——这是第一人称接 CM3 最常见的翻车点，那台 `CinemachineCamera` 的 Rotation Control 必须设成 Do Nothing。

**移动与视角是两个独立组件、两条独立输入**：`FirstPersonController` 读 `Player/Move`（WASD）只管位移，从不碰旋转；`PlayerLook` 读 `Player/Look`（鼠标 delta）只管旋转，从不碰位移。唯一的联动是 `PlayerLook` 把 yaw 写在玩家根节点上，于是 WASD 沿视线方向走——标准第一人称行为。

参数起点：`Step Offset` 按 2m 角色取 **0.1 ~ 0.4**；`Slope Limit` 与移动加减速全部是**手感参数**，进 `PlayerConfigSO`，不写死在组件上（`guidelines/11` 第 7 条）。

规模确认：D4+D5 约 250~350 行，1~2 天到「能走」。**别在这里花时间做架构。**

> 已知缺口：`PlayerLook` 不乘 `deltaTime`，这对鼠标 delta 是正确的，但同一条 `Look` 也绑了手柄右摇杆，走那条路会变成帧率相关。切片 00 是 PC 鼠标，不影响验收；要支持手柄时需按设备分开处理。

## 3. 交互与 Trigger

**D10 — 交互用射线，不用碰撞体**：`InteractionRaycaster` 挂在 `Head` 上，每帧从屏幕中心发一条 `Physics.Raycast`（返回最近命中且不分配；`RaycastNonAlloc` 配一元素缓冲会返回**任意**命中，不是最近的），命中层由序列化的 `LayerMask` 指定（`guidelines/09` 第 10 条要求每个物理查询显式给 LayerMask 和 `QueryTriggerInteraction`）。
- 命中变化才调 `IInteractableView.SetFocused`，不每帧调；
- 交互距离、层遮罩进 `InteractionConfigSO`；
- **一帧只允许一次交互确认**，且确认后进入 `ToolUseController.IsBusy` 直到 `IToolView.UseFinished` 回来——这条堵死"事件重入 / 双触发"的主要来源。

**D11 — Trigger 用专用探针，不依赖 CharacterController**：
`CharacterController` 本身是能收到 `OnTrigger*` 的（Unity 手册自己的警告写着「在 Inspector 里改 CC 属性会重建控制器、丢失已有 trigger 接触，直到再次移动才会收到 `OnTriggerEnter`」），但社区对此长期有分歧，且那条重建行为本身就是个坑。
定案：玩家 prefab 下挂一个子物体 `PlayerTriggerProbe`——`CapsuleCollider` + `Rigidbody(isKinematic = true)`，单独一层，与除 `TriggerVolume` 层外的所有层都不碰撞。所有区域触发由它负责。
这既绕开 CC 的歧义，也不违反「同一物体上不同时挂 CC 和 Rigidbody」（探针是**子**物体）。

Trigger 收到之后怎么处理 → [运行时架构 D12](../运行时架构说明书.md)：只登记，不执行。

## 4. 开工顺序（对齐策划第九节）

策划的顺序是「灰盒 → 试玩 → 定路径 → 换资产 → 加功能」，gameplay 程序侧要**先于灰盒**把 T0 做完，否则美术搭完没法试玩。

下表按开工顺序排，不按人分——T0~T2 全部是 gameplay 程序的工作，T3 起需要前端工程师（UI owner）交付界面 prefab，见各行「卡谁」列。

| 阶段 | 工程做什么 | 卡谁 |
|---|---|---|
| **T0（灰盒之前，1.5 天）** | `GameBootstrap` + `SceneLoader`；第一人称控制器 | 不卡任何人；**做完立刻交给场景美术**，让场景美术能在自己搭的灰盒里走 |
| **T1（灰盒期间，2 天）** | 真相层 + EditMode 测试；Trigger 系统；交互射线 | 需要美术给出 `Level00_Environment` 第一版灰盒 |
| **T2（第一次试玩后，2 天）** | `InvestigationService` + 调查对象资产；报告条目 | 需要主策划把 SO-001 / FL-001 的文本填进 SO 资产 |
| **T3（1.5 天）** | 报告 UI presenter；无线电序列；头盔 ON/OFF | 需要 UI owner 给界面 prefab；给不出就先用纯文本占位 |
| **T4（P1）** | 无线电渐弱、污染数值、调查特效、完整报告 UI | — |

**D21 — 一切依赖美术的东西先做占位。** 摘头盔（00-05）先做「HUD 淡出 + 短暂黑屏 + 呼吸声切换」，正式演出走 Timeline 后补；生态渐变（00-02）gameplay 程序只提供 `ZoneProgress`，表现全归技术美术。
**不允许**任何美术资产阻塞「从开场到调查完成可以完整运行」这条验收标准。

## 6. 明确不做的事

- 不写 tick 循环、不写帧结算规范（本作无连续数值推进）。
- 不导入 Starter Assets / Chop Chop 工程本体。
- 不用 Addressables、不建 `Resources/`（`guidelines/09` 第 14 条）。
- 不上 NavMesh（本切片无 NPC）。
- 不用 `MaterialPropertyBlock`、不加 renderer feature（P1 再议）。
- 不做 world-space UI。
- 不做存档（切片 00 是单次连续流程；`WorldState` 的 JSON 序列化留到有存档需求时再加，纯 C# 结构已经为此留好了口子）。
