# 无线电与对话语音接入

> **目标**：让"给一句台词配上录音"变成**在一行台词旁边拖一个文件**，不需要再命名、建表、写脚本或改场景。
> **适用角色**：文案（写台词）、音频（切录音并接入）、gameplay 程序（触发接线）、技术美术（混音）。
> **上层规范**：[音频管线](./音频管线.md)、[对话与场景序列](./对话与场景序列.md)、
> [表现层驱动契约](../contracts/表现层驱动契约.md) D20、指南 [09](../../guidelines/09-packages-systems.md)。
> **状态**：运行时、内容资产、场景接线与 EditMode 用例已落地。**录音文件尚未录制**，见 §7。

## 1. 一句台词由三样东西组成

| 东西 | 谁填 | 在哪 |
|---|---|---|
| 中文 / 英文字幕 | 文案 | 台词那一行的 `Text` / `English` 字段 |
| 录音 | 音频 | 同一行的 `Voice` 字段（`AudioClip`） |
| 怎么响 | 技术美术 | 整段共用的一份 `AudioCueSO`（`VOX_Radio` / `VOX_Dialogue`） |

**录音挂在台词上，不是挂在 cue 资产上。** 一段通讯有十句话，十句话之间除了音频文件本身没有任何差别；
如果每句话一份 cue 资产，`Data/Audio/` 会变成上百个只差一个引用的文件，而且序列还得再说一次哪份归哪句。
所以请求可以自带片段（`AudioCueRequest.Voice(cue, clip)`），cue 只负责混音组、音量和空间设置，
片段从台词那一行直接过去。发声端仍然是同一个 `AudioDirector` 对象池，声部上限、混音组约束一个不少。

### 1.1 一句台词停多久

`DialogueTiming.HoldSecondsForLine` 一个函数决定，三条规则按优先级：

1. **有录音就播完**——停留时间至少是片段长度加 0.35 s 尾巴。文案填的秒数不会把一句话切在半个词上。
2. **手填的停留更长时按手填的来**——刻意的停顿就是这样写出来的。
3. **两样都没有就按字数估**——中文 5 字/秒、英文 15 字符/秒**取较慢者**（两种语言是并读，不是相加）。

有录音的台词**不能用交互键跳过**：对象池目前没有"停掉某一个声部"的能力，跳字幕会让上一句的录音压在下一句上。
没有录音的台词照常可跳，这样在录音到位之前反复试玩不会难受。

## 2. 无线电

```text
RootsDance.Narrative
├── RadioLine            # 一句：中文 + 英文 + 录音 + 停留秒数
├── RadioSequenceSO      # 一段通讯：编号、标题、台词表、起始延迟、语音 cue
├── RadioEventChannelSO  # 频道：任何触发器都能点播一段通讯
└── RadioSequencePlayer  # 一台无线电：旗→通讯 表、排队、字幕、语音、开关音、结束抬旗
```

**一个关卡只有一个 `RadioSequencePlayer`**，它持一张「哪面旗放哪段通讯、播完抬哪面旗」的表。
不是一段通讯一个组件：头盔里只有一台无线电，而两个组件互相看不见。00 章的实际布局就会让它们打架——
出发简报约十四秒，而它覆盖的那段路走完只要五秒，所以任何按距离触发的第二段都会压在第一段上。
播放中到达的通讯**排队而不是丢弃**：丢掉它会让等它结束旗的东西一直等下去，00-04 等的正是载波底噪本身。

一段通讯**不是对话**：没有选项，玩家也答不了话——指挥部在对着头盔说话。
它有的是对话没有的东西：一个会衰减、然后失效的信号，而这正是它服务的那个节拍。

每一行起手有两种：表里那面 `Start On Flag`，或者听 `RadioRequested` 频道由代码点播。播完抬该行的 `Flag On Finished`。

**必须保序的用旗串，只有必须发生在某个地点的才用体积。** 00 章的链是：

```
RadioBriefing 触发体积 → flow.radio_briefing_started → 简报
     → flow.radio_briefing_finished → 接近通讯
RadioSignalFading 触发体积 → flow.radio_signal_fading → 信号中断通讯
     → flow.radio_signal_lost → 载波底噪停
```

信号失效**分两面旗**：体积抬的是「正在失去」，通讯播完才抬「已经失去」。
只用一面旗，底噪会在最后几句话开口的那一帧就断掉，而没有载波的人声听起来是 bug，不是渐弱。

**底噪不在这个组件里。** 通讯底下的载波噪声是一条循环床，循环床归 `FlagAudioBed`，
键在这个播放器本来就会抬的那两面旗上（开始 / 结束）。这样底噪在 checkpoint 跳到节拍中间时也对，
而播放器只做一件事。`Open Cue` / `Close Cue` 是两个可选的一次性音（接通的咔哒、断线的静噪），
和台词无关，所以留在播放器上。

## 3. 对话与独白

00 章的"对话"实际上是主角独白和设备提示，用的仍是 02 章那套 `DialogueSO`——
一段台词，可选几个选项。00 章的十七个节拍都没有选项，所以每份资产就是一串台词。

`DialogueRunner` 上多了两个字段：`Audio Channel`（`AudioCueRequested`）和 `Voice Cue`（`VOX_Dialogue`）。
一个 runner 播全部对话，所以混音只接一次，不用往每份资产上接。

`Data/Dialogue/` 里 00 章的骨架资产为 `DLG-100` 至 `DLG-111`，
每份带编号、标题、以及该节拍的 `Required Flag`。**台词是空的**：正文在飞书流程文档里，
手抄第二遍正是 02 章那套生成器要避免的错误来源（漏行、编号对不上、中英说的不是一件事）。
文案往里加一行，音频那一行旁边就出现一个 `Voice` 槽。

## 4. 环境、设备与脚步

不是台词的声音有三种接法，都不用写代码：

| 想要 | 用什么 | 说明 |
|---|---|---|
| 某个**地方**的底噪 | `AmbienceZone` | 触发体积，玩家进出淡入淡出；勾 Always On 作整场底噪 |
| 某个**剧情阶段**的底噪 | `FlagAudioBed` | 抬某面旗开始、抬另一面旗结束；`Start` 里读一次世界状态，checkpoint 跳进来也对 |
| 某个**事件**的一次性音 | `FlagAudioCues` / `AudioCueEmitter` / `ChannelAudioCue` | 分别对应旗标、场景物件、界面频道 |
| 脚步 | `FootstepAudio` | 挂在 Player 上，读控制器的速度和着地状态，按**走过的距离**每一步一响 |

脚步按距离而不是按时间计数，所以走、跑、蹲不用各配一个频率。
一帧里位置突变（传送、checkpoint）最多响两步，不会把欠下的步数在后面几帧还完——那听起来像有人正在走开。

## 6. 音频文件放哪

导入设置由文件夹决定（`AudioClipPostprocessor`，见[音频管线](./音频管线.md) §4）：

| 内容 | 放进 |
|---|---|
| 无线电台词、对话录音 | `Assets/RootsDance/Audio/Voice/` |
| 一次性音效、脚步、设备 | `Assets/RootsDance/Audio/SFX/` |
| 循环环境床 | `Assets/RootsDance/Audio/Ambience/` |
| 音乐 | `Assets/RootsDance/Audio/Music/` |

放进 `Audio/` 但不在这四个文件夹里的文件会被警告并原样保留——不会被静默套上错误的压缩设置。

混音器有四个组：`Master > Music / SFX / UI / Voice`。
**`Voice` 是台词专用的组**：无线电和对话是全场唯一必须听懂的声音，混在 SFX 里就意味着让台词听清的唯一办法是把别的都调小。

`Main.mixer` 已经建好，但**还没有 `Voice` 组**——混音器只能手工编辑。缺它不报错：`VOX_Radio` / `VOX_Dialogue`
当前回落到 SFX，校验器给出补法。想要独立的台词音量时，在 Audio Mixer 窗口里 Master 下新增子组 `Voice`、
把它的 Volume 暴露成 `VoiceVolume`，再把这两份 cue 的 Output Group 手工指过去。

## 7. 尚未做的

- **全部录音**。台词没有片段时字幕照常走，流程可玩，这是刻意的顺序：接线不等录音。
- **混音器的 `Voice` 组**（§6）。缺它不报错，只是台词和音效同组。
- **大部分台词正文**。流程文档里成文的只有四处，已经填进资产：00-02 的催促（`RAD-001_IdleNudge`）、
  00-03 的出发简报（`RadioBriefing`，中文原有、英文本次补齐）、00-05 的解除隔离提示（`DLG-103`）、
  00-07 的两句内心描写（`DLG-107`）。其余节点在文档里是画面与声音而不是台词，资产留空，没有替文案编。
- **`RadioSignalFading` 体积的位置是推导值**，落在简报体积与头盔解除体积之间 75% 处（当前 z≈11.25）。
  路线还是灰盒，改了之后重跑一次 `Wire Chapter 00 Radio Flow` 即可跟上；要换节奏就调
  `Chapter00RadioFlowBuilder.k_FadingFraction`。
- **这段路太短，装不下这些通讯**。简报十四秒，而简报体积到头盔解除体积只有约 10 m。
  排队保证了不叠音，但代价是信号中断可能在玩家已经走到草带之后才播完。
  真要按策划案的节奏走，需要把 `HelmetUnlock` 往外挪，或者把简报剪短。这是关卡与文案的取舍，没有替它决定。
- **打断一段正在播的录音**。`AudioDirector` 没有按 cue 停声部的接口，所以有录音的台词不可跳过（§1.1）。
  真要跳，需要给对象池加一个"停掉这条 cue 的声部"的入口。
- **信号逐句衰减**。策划案里列为 P1。当前只有"有信号 / 无信号"两态，由底噪床的开始与结束旗表达。
- **脚步与地面材质关联**。契约 D20 已列为 P1；目前一个 cue 走全程，换地面靠再挂一个组件。
