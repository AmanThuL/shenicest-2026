## 1. 规则

1. **艺术家的原始 `.blend` 永不被写。** 管线只读打开，`asset_prepare` 只写 `--out` 指定的派生文件，且拒绝 `--out` 等于输入路径。
2. **低模只导出一次**，落到 `Assets/RootsDance/Meshes/<Category>/`。Painter 和 Unity 用**同一个** FBX。只有专供烘焙的高模才另放 `SourceArt/Export/`。
3. **贴图命名沿用 [guidelines/02](../../guidelines/02-project-structure.md)**：`<Asset>_<Map>.png`，不另起一套（§3）。
4. **不写一个大脚本。** 每段是独立进程，有显式输入输出，失败即非零退出（§4）。
5. **Painter 必须以 `--enable-remote-scripting` 启动**，管线走它的 JSON 服务，**不做任何 GUI 自动化**（§6）。
6. **Unity 导入设置不靠手点**，由 `TexturePipelinePostprocessor` 自动套（§7）。
7. **应用变换前必须先剥离 action。** 被动画驱动的 transform 即使 apply 了也会在下一次求值时弹回原值——`asset_prepare` 因此先 `strip_animation` 再 apply rotation/scale。
8. **任何修复都要显式 flag。** 诊断段只读、只报告；修复段只做被明确要求的事，不静默改资产。

## 3. 贴图命名约定

```
<Asset>_<Map>.png        Map ∈ BaseMap | Normal | Mask | Emission | Height
例：Crate_BaseMap.png    Crate_Normal.png    Crate_Mask.png
```

PascalCase；不加 `T_` / `M_` / `SM_` 类型前缀；下划线只留给 map 后缀。Map 名就是 **HDRP Lit 着色器自己的槽位名**，这是 Blender 和 Unity 能自动认出哪张图是哪张的原因。

**`Mask` 是通道打包图**（HDRP 的 mask map）：`HDRP/Lit` 读 R metallic、G ambient occlusion、B detail mask、A smoothness；地形层（`HDRP/TerrainLit`）读 R metallic、G ambient occlusion、B height、A smoothness——B 通道是 height-based blend 的输入。HDRP 没有独立的 smoothness 槽位，所以 **`Mask` 必须带 alpha**。原 URP 时代的 `Metallic` / `Specular` / `Occlusion` 三个 map 已取消（详见 [guidelines/07-rendering-hdrp §9](../../guidelines/07-rendering-hdrp.md)）。

**多材质槽**（本文新增，**[项目决策]**，待技术美术确认后写回 guidelines/02）：

```
<Asset><Part>_<Map>      例：HelmetShell_BaseMap.png、HelmetVisor_Normal.png
```

始终**只有一个下划线**且紧邻 map 后缀，解析无歧义。一个材质槽 = 一个 Painter texture set = 一组贴图。

不合规范的文件名会被管线拒绝，`TextureMapNamingTests` 有对应负例。

## 4. 分段

| # | 段 | 跑在哪 | 输入 → 输出 | 机器校验 |
|---|---|---|---|---|
| 1 | `asset_inspect` | Blender 无头 | `.blend` → 报告 | **只读** |
| 2 | `asset_prepare` | Blender 无头 | 源 `.blend` → 派生 `.blend` | 每项修复显式 flag；保存前复验 |
| 3 | `uv_prepare` | Blender 无头 | `.blend` → `.blend` | 前后覆盖率 / texel density 对比 |
| 4 | `asset_inspect`（复检） | Blender 无头 | 派生 `.blend` → 报告 | **必须零 error** |
| 5 | `export_mesh` | Blender 无头 | `.blend` → `.fbx` | 导出后立刻再导回比对 |
| 6 | `painter_texture` | Painter 远程 | `.fbx` → 贴图 + `.spp` | 报告逐文件记 size + sha256 |
| 7 | `import_material` | Blender 无头 | 贴图 → 接好节点的 `.blend` | 复查 BSDF 输入与色彩空间 |
| 8 | `validate_final_asset` | 系统 Python | 贴图 + fbx → 报告 | 读 PNG 字节头，无第三方依赖 |
| 9 | Unity 导入 | Unity Editor | 贴图 → 导入设置 | `AssetPostprocessor` 自动套（§7） |

跑全链（Painter 需已启动）：

```bash
python3 Tools/pipeline/run_asset.py Tools/pipeline/assets/Helmet.json
```

单跑一段：`--only asset_inspect`。任一段非零退出即停——**红的段不会被后面绿的段盖过去**。例外：第 1 段是诊断性的（在原始美术上报错本属正常，它的作用是告诉第 2 段要修什么），标为允许失败。

**报告格式**：每段同时输出人读文本和机读 JSON（`Build/pipeline/<Asset>/<stage>.json`）。每条 finding 有稳定的 `code`（如 `uv.overlap`）、`severity`、`subject`、`data`，输出文件带 sha256。`ERROR` = 该段没达成产物或资产违反硬规则 → 退出码 1，**从不自动修复**；`WARN` = 产物有了但要人看一眼。

## 5. 预设

`Tools/pipeline/presets/*.json`。用 **JSON 不用 YAML**：Blender 4.5 不带 PyYAML，管线必须能在 Blender 解释器里跑且不能 `pip install`。支持 `extends` 单继承。

| 预设 | 分辨率 | maps | padding | 说明 |
|---|---|---|---|---|
| `psx_prop` | 256 | BaseMap | 4 px | 低分辨率复古道具 |
| `psx_character` | 512 | BaseMap | 6 px | 对齐现有 `arms_01.png` 的 512 图幅 |
| `realistic_prop` | 1024 | BaseMap/Normal/Mask | 8 px | 上限见 guidelines/05 §7.1 |

**padding 与分辨率解耦**：padding 以「参考分辨率下的像素数」存储，换分辨率时按比例换算，归一化边距不变（256 下 4 px 与 1024 下 16 px 都是 0.0156 UV）。提高分辨率不会悄悄把实际留边减半。

**PSX 预设尚未获批**（§10）：仓库里没有成文的全项目美术方向，这两个预设的参数是从现有第三方占位资产反推的，文件里标了 `"status": "unratified"`。它刻意不堆分辨率和物理真实细节。`Filter Mode` 保持 Bilinear 而非强制 Point——那是逐材质的观感选择，不该由贴图管线替所有资产决定。

## 6. Substance Painter 段

### 6.1 启动与连接

Painter 必须这样启动，否则没有服务可连：

```bash
"<Painter 安装目录>/Adobe Substance 3D Painter.app/Contents/MacOS/Adobe Substance 3D Painter" \
  --enable-remote-scripting
```

服务是 HTTP JSON 端点，默认 `127.0.0.1:60041`：

```text
POST /run.json
Content-Type: application/json

{"python": "<base64 编码的单个 Python 表达式>"}
{"js":     "<base64 编码的 JavaScript>"}
```

三条约束（Painter 自带手册未收录）：

1. **载荷必须 base64。** 发明文会被服务端再做一次 base64 解码。
2. **Python 通道只求值单个表达式。** 多行脚本会执行但返回 `null`。用 `painter_remote.run_python()`，它把脚本包进 `exec(...)` 并取回脚本写进 `RESULT` 的值。
3. **`Content-Type` 必须是 `application/json`**，否则 415。

客户端：`Tools/pipeline/painter/painter_remote.py`。脚本异常会带完整 traceback 抛成 `PainterError`。

### 6.2 升级 Painter 后必须重跑探针

```bash
python3 Tools/pipeline/painter/painter_probe.py --out Build/pipeline/painter_probe.json
```

**Painter 的 Python API 在版本间改名**，不要假设某个调用存在。12.1.2 上管线依赖的 32 个调用全部存在，但这三个名字与旧资料不同：

| 旧资料里的名字 | 12.1.2 实际 |
|---|---|
| `project.MeshCreationSettings` | 不存在，用 `project.Settings` |
| `layerstack.get_root_layer_stack` | 改名 `get_root_layer_nodes` |
| `layerstack.add_mask` | 不是模块函数，是图层节点方法 `LayerNode.add_mask` |

12.1.2 可用烘焙器：`AO` `BentNormals` `Curvature` `Height` `ID` `Normal` `Opacity` `Position` `Thickness` `WorldSpaceNormal`。遮罩/贴花需要的节点方法（`add_mask` / `remove_mask` / `enable_mask` / `set_mask_background` / `mask_effects` / `content_effects` / `set_geometry_mask`）全部具备。

### 6.3 段的行为与三条硬约束

`Tools/pipeline/stages/painter_texture.py`：建工程 → 按预设烘图 → 按 Painter 导出预设导出 → 改名成项目约定 → 存 `.spp`。

1. **`project.create()` 是异步的**，返回时贴图集还没建好。必须等贴图集出现（`wait_for_texture_sets()`），只等 `is_busy()` 不够——对空贴图集列表烘焙会**静默什么都不烘**。
2. **导出必须显式给 `paddingAlgorithm`**，否则报 `padding algorithm could not be resolved`。管线固定用 `infinite`（无限膨胀），防止 mipmap 把 island 外的背景色吸进边缘。
3. **Painter 内部的工作目录不是仓库根**，传进去的路径一律由客户端侧转成绝对路径。

### 6.4 导出名到项目命名的翻译

内置 `Unity HD Render Pipeline (Metallic Standard)` 预设产出 `<mesh>_<textureset>_MaskMap` 等，**不符合** guidelines/02。段内 `MAP_ALIASES` 负责翻译：

| Painter 导出名 | 项目命名 |
|---|---|
| `BaseMap` / `BaseColor` / `AlbedoTransparency` | `BaseMap` |
| `Normal` | `Normal` |
| `MaskMap` | `Mask`（R metallic / G AO / B detail / A smoothness） |
| `Emissive` | `Emission` |
| `Height` | `Height` |

URP 时代的 `MetallicSmoothness` 与 `AmbientOcclusion` 两个别名已删除——HDRP 预设不再单独导出它们，项目侧也没有对应的 map 名可落。**Painter 升级后必须重跑 `painter_probe.py` 核对预设名**：导出预设名不属于稳定 API，对不上时该段会以 `export preset not found` 直接失败。

预设里没列出的图会被丢弃并记进报告（`export.dropped`），不会混进 `Textures/`。

## 7. Unity 侧

Color Space = **Linear**，HDRP **17.3**，着色器 **HDRP/Lit**（metallic 工作流）。

导入设置由 `Assets/RootsDance/Scripts/Editor/Pipeline/TexturePipelinePostprocessor.cs` 自动套：

| map | Texture Type | sRGB | Alpha Is Transparency |
|---|---|---|---|
| `BaseMap` | Default | ✅ | ✅ |
| `Normal` | **Normal map** | ❌ | ❌ |
| `Mask` | Default | ❌ | ❌ **（alpha 是 smoothness 数据，不是透明度）** |
| `Height` | Default | ❌ | ❌ |
| `Emission` | Default | ✅ | ❌ |

统一还会设：Mipmaps 开、Read/Write 关、NPOT Scale = None、Compression = Compressed(Normal)、Wrap = Repeat、Filter = Bilinear（依据 [guidelines/05 §7.1](../../guidelines/05-performance.md) 与 [guidelines/07 §10](../../guidelines/07-rendering-hdrp.md)）。

三条设计约束：

- **Max Size 从 PNG 字节头读实际宽度**，不另存一份「这个资产用哪个预设」的配置。分辨率在导出时已由预设决定，从文件本身反推就不会有第二份配置漂移。
- **`Mask` 的 `alphaIsTransparency` 必须是 false**，否则 Unity 的 alpha dilation 会改写 alpha 里的 smoothness 数值。HDRP 只从 mask map 的 alpha 读 smoothness，没有第二个来源。
- **名字不合规范的文件不套设置**，只报 warning 并原样放过，避免静默覆盖美术手调过的设置。

纯逻辑部分（`TextureMapNaming`）有 EditMode 测试，28/28 通过。

## 9. 验收（2026-08-26 实测）

> **这一轮实测跑在 URP 上，早于 HDRP 迁移。** 表中的 Painter 段用的是 `Unity Universal Render Pipeline (Metallic Standard)` 预设与 `Metallic` 命名；改成 `Unity HD Render Pipeline (Metallic Standard)` + `MaskMap → Mask` 之后，**Painter 段尚未重跑，未验证**（见 §10）。Blender 段、Unity 段与命名逻辑已随迁移重跑：EditMode 28/28 通过。

资产：`Helmet`（占位球，482 verts / 960 tris）。

| 段 | 结果 |
|---|---|
| `asset_inspect`（源，只读） | 5 error / 1 warn——未 apply 的 scale 与 rotation、transform 被 action 驱动、Child Of 约束、零材质槽。跑完源文件 md5 未变 ✅ |
| `asset_prepare` | 剥离 action + 约束、apply rotation/scale、移到原点、加两个材质槽，写入派生 `.blend`；源文件未被写 ✅ |
| `uv_prepare` | 保留原 UV，按 4 px（0.0156 UV）重排，覆盖率 93.2% ✅ |
| `asset_inspect`（复检） | **0 error** ✅ |
| `export_mesh` | 导出后立刻导回比对：根 transform `0/0/1`、960 三角形、UV、两个材质槽全部一致 ✅ |
| `painter_texture` | Painter 12.1.2：建工程得贴图集 `HelmetShell`；按 `psx_prop` 烘 AO + Curvature；用 Unity URP 预设导出后改名 `HelmetShell_BaseMap.png`（256²，sRGB）；`.spp` 已存盘。**0 error** ✅ |
| `import_material` | 材质接上 Principled BSDF，色彩空间正确；连跑三次幂等 ✅ |
| `validate_final_asset` | 尺寸 / POT / 位深 / 命名 / alpha 全过；负例（错分辨率、错命名）正确退出码 1 ✅ |
| Unity 导入 | `BaseMap` → sRGB 开、alphaIsTransparency 开、256 平台覆写 ✅ |
| EditMode 测试 | 22/22 ✅（迁移后重跑为 28/28 ✅） |

`realistic_prop` 的多图路径当时以 URP 的 Normal / Metallic / Occlusion 验过：`Metallic.alpha → Invert → Roughness` 链路正确（存 smoothness，Blender 要 roughness，中间必须取反）。迁移后该路径改为 `Mask` 单图：`Mask.R → Metallic`、`Mask.G → 乘进 Base Color`、`Mask.A → Invert → Roughness`，**未重跑验证**。

## 10. 未闭环

1. **Painter 段只有骨架。** 建工程 / 烘图 / 导出已跑通，但**材质创作本身还没做**——图层、遮罩、生成器、边缘磨损、脏渍、贴花全部没有落成代码。API 已确认具备（§6.2），是工作量问题不是可行性问题。**这是本管线目前最大的缺口。**
2. **贴花工作流未实现。** 目标结构是：基础材质 → 大尺度色彩/材质变化 → 表面磨损 → 脏渍 → 贴花 → 细节。贴花应做成 Painter 内可独立编辑的图层，而不是烘死进 BaseMap。
3. **§3 的多材质槽命名规则**是本文新增的项目决策，待技术美术确认后写回 guidelines/02。
4. **PSX 预设未获批**（§5），待美术负责人拍板。
5. **guidelines/02 §12 需更新**——那里写「preset 可选，`AssetPostprocessor` 以后再说」，本管线已采用 `AssetPostprocessor`。
6. **`.spp` 入库策略待定**（§8）。
7. **头盔仍是占位球，且 `Visor` 槽是空的**——512 个面全部指派给 `HelmetShell`，`Visor` 槽零面，Painter 因此只建出一个贴图集。`Helmet.json` 里写的 `texture_sets: [HelmetShell, HelmetVisor]` 在真模型进来前不可能达成；段内以 `painter.texture_set_mismatch` 警告，不会假装成功。
8. **texel density 偏离预设目标**（实测 433 px/m vs `psx_prop` 目标 128）——占位球的 UV 不代表真资产，真模型进来后再评估是调 UV 还是调预设目标值。
9. **`Tools/pipeline/stages/export_mesh.py` 与 `Tools/blender/export_fbx.py` 功能重叠**，应合并为一个导出实现。
10. **HDRP 迁移后 Painter 段未重跑。** `Unity HD Render Pipeline (Metallic Standard)` 这个内置预设名、以及它实际导出的 map 文件名（`MaskMap` / `BaseMap` / `Emissive` / `Height`），都还没在装机的 Painter 12.1.2 上核对过；`import_material` 的 `Mask` 节点图（SeparateColor → Metallic / AO / Invert → Roughness）同样未在 Blender 里跑过。下一次有 Painter 的机器上跑 `painter_probe.py` + `realistic_prop` 全链，把 §9 的结论补齐。
