# 电子类 UI 组件库规范

一套**可拼装**的电子/仪器风 UI 组件库：主题、抖动着色器、一组预制件，以及把它们组合成一屏而不失控的规则。

与 [低保真终端式 UI 规范](低保真终端式UI规范.md) 的关系：那份文档描述**两块具体的屏**（暖色标题卡、冷色数据屏），
目标是复刻；这份文档描述**一套零件**，目标是让同一套零件长出许多块互不相同的屏。两者可以共存于一个项目，
但不共用渲染路径——原因见 §1。

代码实现：主题 [`ElectronicUITheme`](../../Assets/RootsDance/Scripts/Runtime/UI/Kit/ElectronicUITheme.cs)、
着色器 [`Dither`](../../Assets/RootsDance/Shaders/UI/Dither.shader)、
组件在 `Assets/RootsDance/Scripts/Runtime/UI/Kit/`，预制件在 `Assets/RootsDance/Prefabs/UI/ElectronicKit/`。

---

## 0. 这套库要解决的问题

三张参考图（警用档案屏、生物档案屏、终端浏览器）**配色不同、内容不同、族不同**，
却一眼看得出是同一种东西。让它们成为同一种东西的是下面五条：

1. **整屏是一个被切满的矩形。** 先立一个外框，再用规则把它切成分区；分区**共用边线**、逐层再切，
   直到每一块底都被指派给某个内容。参考图里几乎不存在"分区之间的空地"。
2. 一切都是**矩形 + 发丝描边**。没有渐变、没有阴影、没有描边以外的装饰。
   圆角只在终端族的交互件（按钮/标签页/输入框）上出现，半径小且固定，永不出现在面板和框上。
3. 颜色全部来自**一条 6 级灰阶坡道 + 一个强调色**。强调色只用于报警，不用于装饰。
4. 图像**一律抖动**，且抖动的颗粒明显大于像素——图像是"打印出来的"，不是"贴上去的"。
5. 文字是**像素/打字机等宽字**（本库统一用 VT323）。标签靠左、数值靠右；
   档案族全大写，终端族允许小写正文与斜体标题。

**规范的目标不是让人照着画一张图，是让人拼出一张没见过的图而它仍然对。**
但布局不是自由发挥出来的——三张参考图各给了一个**可以直接抄的切分模板**（§5B）。
先抄模板，再换内容；令牌（§2）与组件（§4）保证换出来的仍然对。
§7 是一份"拼出来的东西还算不算数"的判据。

## 1. 渲染路径：清晰的 uGUI，不是低分辨率缓冲

低保真终端规范把**整屏**渲进 640 × 360 缓冲再合成，因为那两块屏的文字本身就该是糊的。
**这套库反过来**：

| | 终端规范 | 本库 |
|---|---|---|
| 文字 | 点阵，画进低分缓冲，靠辉光糊开 | **原生分辨率的等宽字，锐利** |
| 描边 | 只画 1 px 芯，宽度由辉光生成 | **1 px 实描边，就是 1 px** |
| 抖动 | 作用于整屏 | **只作用于图像内容**，chrome 不抖 |
| 合成 | 全屏一条信号链 | 无全屏 pass |

三张参考图里，文字和描边都是**锐的**，只有眼睛、指纹、电路这些**图像**是抖动的。
把整屏丢进低分缓冲会同时毁掉两件事：标签读不清，描边糊成灰带。

> **这条最容易做反**：抖动很好看，于是很容易顺手给整屏加一层。加完之后画面立刻从"仪器"
> 掉进"做旧滤镜"。抖动是**图像的呈现方式**，不是屏幕的属性——它出现在哪里，就等于在说
> "这块地方是一张被采集回来的图"。给 chrome 加抖动，等于说边框也是采集回来的，那没有意义。

## 2. 令牌

组件**不允许写死任何颜色或尺寸**，一律向主题取值。这是"换一个主题就换一整套配色"的唯一前提。

### 2A · 坡道

主题是**六级坡道 + 一个强调色**。坡道从底色走到最亮的主文字色，中间四级承担全部层级。

| 令牌 | 用途 |
|---|---|
| `Ink0` | 屏底 / 面板底 |
| `Ink1` | 次级面板底、禁用态填充 |
| `Ink2` | 分隔线、网格、弱描边 |
| `Ink3` | 次要文字、标签、图标 |
| `Ink4` | 主描边、边框、按钮描边 |
| `Ink5` | 主文字、数值、标题 |
| `Accent` | **仅**报警 / 错误 / 超限 |

三套实测主题（2026-08-27 对参考图逐像素重采样修正；取 bloom 顶部百分位作墨色）：

| 主题 | Ink0 | Ink1 | Ink2 | Ink3 | Ink4 | Ink5 | Accent | AccentAlt |
|---|---|---|---|---|---|---|---|---|
| **Precinct**（冷蓝灰） | `#020809` | `#0D1519` | `#22343A` | `#4E626B` | `#84949C` | `#C6D2D8` | `#A83428` | `#4E7A80` |
| **Violet**（紫） | `#131117` | `#201E26` | `#3A3862` | `#7478AC` | `#9BA0D8` | `#E8ECFF` | `#9BA0D8` | `#9BA0D8` |
| **Phosphor**（绿） | `#040F04` | `#32422F` | `#598E47` | `#8DB081` | `#B9D4A0` | `#D7EFA0` | `#EDFA4F` | `#598E47` |

> **坡道顶部必须够亮。** 初版把 Precinct 的 Ink5 定在 `#8597A5`，整块屏立刻读成"关着的仪器"——
> 重测发现警用屏的描边和数值其实顶到近白（`#C6D2D8`+bloom）。"仪器感"一半来自亮线压在近黑底上。
> 屏亮不亮由 `Ink0` 决定,线亮不亮由 `Ink4/Ink5` 决定,两头都不能软。
>
> `AccentAlt` 是第二强调色：警用屏芯片块与采样条里的**青色**。它只用于数据纹理
> （ChipMosaic / BarcodeRows），不用于报警。没有它的主题设成 Ink2。
> Violet 的 `Accent`/`AccentAlt` 都等于 Ink4，因为那张参考图没有强调色——允许，不要硬塞红色。

主题除了颜色还携带一个**族**枚举（`Archive` / `Terminal`），组件据此决定圆角与大小写（§2C、§5C）：
Precinct 与 Violet 是 `Archive`，Phosphor 是 `Terminal`。

### 2B · 度量

一切尺寸是**基准单位 `u` 的整数倍**。`u = 4 px`（1080p 下）。

| 令牌 | 值 | 说明 |
|---|---|---|
| `Rule` | 1 px | 描边宽。**恒为 1 px，不随组件大小变** |
| `RuleStrong` | 2 px | 外框、当前项 |
| `Pad` | 3u = 12 | 面板内缩 |
| `Gutter` | 4u = 16 | 格内小件之间；骨架层只用于唯一的那条竖缝（§5C） |
| `Row` | 10u = 40 | 数据行高（实测 39–41） |
| `Inset` | 16u = 64 | 外框距屏边（实测占宽 7–8%） |
| `Corner` | 4u = 16 | 角标长度 |

> **`Rule` 恒为 1 px 是这套库最反直觉的一条。** 把边框按面板大小放粗，是现代 UI 的做法，
> 在这里会立刻读成卡片。参考图里 736 px 宽的画面上，最粗的一条线也只有 3 px，而绝大多数是 1–2 px。
> 一块 800 px 宽的面板和一块 80 px 宽的芯片，描边一样粗——**"仪器感"来自线宽与画面尺寸脱钩。**

### 2C · 字

字族是 **VT323**（OFL 授权，已入库：`Assets/RootsDance/Fonts/VT323-Regular.ttf`，
许可证 `VT323-OFL.txt` 同目录）。这是一个像素终端等宽字——粗细不匀的方块笔画、点阵味的字形，
与警用档案屏的字几乎一致，也能覆盖生物档案屏的加粗像素字与终端浏览器的打字机字。

> **绝不允许用普通 sans-serif 加 `mspace` 假装等宽。** 那是这套 UI 出错时最刺眼的一种错法：
> 字间距对了，但字形是现代的、笔画是均匀的、拐角是圆的，一眼就穿帮。
> "电子感"有一半在字形本身——像素栅格上的直角拐点和不均匀笔画。
>
> Unity 落地：从该 ttf 生成一个 TextMeshPro Font Asset（SDF，采样字号 ≥ 90），
> 所有 Kit 组件的 `TMP_Text` 只引用它。VT323 只有一个字重；需要斜体时用 TMP 的假斜体
> （仅限终端族 `Display` 标题），不允许假粗体。

三档字号是**每套主题的实测值**，不是全库常量（VT323 大写高 ≈ 0.55 em，
从参考图量出大写高再除回去）：

| 主题 | Micro | Body | Display | 依据（实测大写高） |
|---|---|---|---|---|
| Precinct | 24 | 40 | 56 | 数据行 ~22 px / 40.7 px 行距；标题 ~34 px |
| Violet | 18 | 36 | 46 | 数据行 ~20 px / 38 px 行距；标题 ~25 px |
| Phosphor | 16 | 24 | 40 | 浏览器屏文字整体更小 |

> 初版全库统一 16/24/40，出来的字比参考图小一半——参考图的字几乎**填满行高**
> （大写高 ≈ 行高的 55%），这是"仪器读数"和"网页表格"的区别之一。

大小写与字重是**族/主题**的属性，不是随手的选择：

| 族 | 参考 | 规则 |
|---|---|---|
| 档案族 | 警用档案屏、生物档案屏 | **全大写**，无斜体 |
| 终端族 | 终端浏览器 | 标签/按钮混排（`Home` `Block`），正文与 URL **小写**，`Display` 标题可粗斜体 |

生物档案屏的字是**重磅板状像素字**，VT323 本身没有这个重量：Violet 主题开
`BoldText`（TMP 合成粗体）作为最近似。要完全对上还需要入库一款真正的粗像素字
（加字体是团队决定 + 单独 commit）。警用屏的字形与 VT323 几乎一致，不加粗。

数据行**标签靠左 `Ink3`、数值靠右 `Ink5`**，中间是空的——不要点线引导，参考图里一条都没有。

## 3. 抖动

三张参考图用了**三个不同的抖动族**，这是它们看起来不像同一张图的主要原因之一。
一个着色器覆盖全部三族，靠 `_Mode` 切换。

| 族 | 参考图 | 特征 | 适合 |
|---|---|---|---|
| **Ordered / Bayer** | 警用档案屏 | 规则的棋盘与斜点，每一个色阶有自己的固定花纹 | 多级灰度图，"扫描件" |
| **Clustered / 半调** | 终端浏览器 | 菱形网点在固定格子里长大缩小 | 1 bit 高反差图，"印刷件" |
| **Blue noise** | 生物档案屏 | 无周期、散点，亮处密暗处疏 | 1 bit 低反差图，"噪声采集" |

### 参数

| 参数 | 说明 |
|---|---|
| `_Mode` | `0` Bayer2 · `1` Bayer4 · `2` Bayer8 · `3` 半调（圆）· `4` 半调（菱形）· `5` 半调（线）· `6` Blue noise |
| `_Levels` | 量化级数。`2` = 1 bit。参考图分别是 6 / 2 / 2 级 |
| `_PixelSize` | **抖动格的边长（屏幕像素）**。参考图实测 2–3 px |
| `_Angle` | 半调网屏角度。仅 `_Mode` 3–5 有效 |
| `_Contrast` `_Brightness` | 抖动**之前**的调整。抖动之后再调会毁掉花纹 |
| `_ColorLow` `_ColorHigh` | 量化结果映射到的两端颜色。取主题坡道的两级 |

> **`_PixelSize` 比 `_Levels` 重要得多。** 抖动格必须**明显大于屏幕像素**，2–3 px 是实测值。
> 等于 1 px 时花纹在 1080p 上看不见，图像只是变脏；等于 6 px 以上就成了马赛克装饰。
> 调这套效果时先把 `_PixelSize` 调对，再碰别的。

> **抖动前必须先压对比度。** 抖动是把连续色阶换成花纹，输入若是一张正常曝光的照片，
> 中间调占绝大多数，出来的就是一整片均匀花纹、看不出内容。参考图三张都做了强对比压缩：
> 亮部推到纯白、暗部压到纯黑，只留一小段中间调给花纹去表现。这一步在 `_Contrast` 里，不在图片里。

> **不要在抖动结果上再做双线性缩放。** RawImage 用 `Point` 采样，或者让 `_PixelSize` 跟着
> RectTransform 走。缩放会把花纹糊成灰，那正是抖动要避免的东西。

## 4. 组件

每个组件必须满足三条，否则它不属于这套库：

1. **两轴可拉伸**且不失真——描边仍是 1 px，内缩仍是 `Pad`。
2. **不含任何字面颜色**，全部向 `ElectronicUITheme` 取。
3. **可作为竖排或横排里的一项**被塞进任意容器。

### 4A · 结构件

| 组件 | 说明 |
|---|---|
| `Frame` | 外框。`RuleStrong` 描边 + 四角 `Corner` 长角标。整屏只有一个 |
| `Split` | **切分容器**：把父矩形按权重横切或竖切成若干格，相邻格**共用一条 `Rule` 描边**（不是各画各的边再留空）。这是搭骨架的主力件，嵌套 `Split` 就是嵌套切分。`EndDots` 开关在每条缝两端画 `Ink5` 节点点——两张档案参考图把**每个线交界**都钉了一颗 |
| `Panel` | 面板。`Rule` 描边 + `Ink0`/`Ink1` 底，可选左上角标签舌。只用于**确实独立**于格子的块（如生物档案屏里带角括号的指纹框） |
| `Rule` | 单条分隔线，横或竖 |
| `Stack` | 格内内容的竖排/横排，按 `Gutter` 分隔（uGUI LayoutGroup 的主题化封装）。只排**格内小件**，不用来搭屏骨架 |

> 之前版本用"`Stack`/`Grid` + `Gutter`"搭骨架，产出的是**浮在空底上的卡片**——和参考图完全不像。
> 参考图的骨架是**切分**：所有分区通过共用边线连成一个整体，`Gutter` 在骨架层只出现一次（见 §5C）。

三张参考图的骨架各做成一个 **Template 预制件**（`Prefabs/UI/ElectronicKit/Templates/`）：
`Template_Archive`（警用档案屏）、`Template_Dossier`（生物档案屏）、`Template_Browser`（终端浏览器）。
**新屏从抄一个 Template 开始**，把格子里的内容件换掉，而不是从空 `Frame` 拼起。

### 4B · 内容件

| 组件 | 说明 |
|---|---|
| `TitleBar` | 左标题 + 右状态。高 `Row` |
| `DataRow` | 标签靠左 / 数值靠右。高 `Row`。`Alarm` 开关把整行切到 `Accent` |
| `DataTable` | `DataRow` 的竖排，行间可选 `Ink2` 分隔线 |
| `ImagePlate` | 抖动图。可选：网格叠加、四角括号、引线标注 |
| `SegmentBar` | 分段条（电量、强度）。给定 `Value` 与 `Segments` |
| `BarcodeRows` | 多行不等宽竖条，带左侧行名——"频谱/条码"块 |
| `Waveform` | 网格 + 折线。给定采样数组 |
| `ChipMosaic` | 小色块矩阵，从坡道随机取色，可指定若干高亮格 |
| `Button` | 按钮。`Ghost`（透明底描边）与 `Solid`（`Ink4` 底 `Ink0` 字）两态；终端族主题下带固定小圆角（`u` 到 `1.5u`），档案族主题下直角 |
| `TabStrip` | 横排标签，当前项 `RuleStrong` + `Ink5` |
| `Readout` | `Display` 字号的大数值，可带单位后缀 |
| `TextBlock` | 正文段落，`Body` 字号 `Ink3` |

### 4C · 标注件

| 组件 | 说明 |
|---|---|
| `CornerMarks` | 四角括号，套在任意 RectTransform 外 |
| `NodeDots` | 矩形角点（可选边中点）的小方块。重测修正：参考图的点在**线的交界处**，不在边中点——骨架上的点由 `Split.EndDots` 负责，`NodeDots` 只钉外框四角 |
| `Leader` | 从图上一点引出的折线：起点实心方块 + 终点开口方框。警用屏用它的**红色**从采样芯片指进眼睛——全库唯一被许可的斜线，也是 Accent 的两处之一 |
| `Caption` | `Micro` 字号的贴边小标签，四个方位可选 |

## 5. 组合规则

### 5A · 一屏的骨架：切分树，不是卡片流

一屏是**一棵切分树**：外框先横切出通栏的横带（Header、若干 Zone、Footer），
每个 Zone 内再竖切一次（窄+宽或宽+窄），格内还可以继续横切。深度不超过三层。

```
Frame                       ← 唯一外框
├── Header       通栏，高 ~1.3 Row，左标题右状态，底边一条共用 Rule
├── ZoneA        通栏横带
│   ├── 左列 ┐
│   └── 右列 ┘  一次竖切；列内继续横切成共用边线的格
├── ZoneB        通栏横带（竖切位置沿用 ZoneA，让左右列上下贯通）
└── Footer       通栏横带（数据行组 / 署名条）
```

**相邻格共用边线**：格与格之间是**一条** `Rule`，不是两条描边夹一条缝。
横带之间的分隔线从左框画到右框；列内的横线画满整列宽。
整棵树切完，**每一块底都属于某个格**——参考图里不存在"分区之间的空地"。

三张参考图各给出一个实测切分模板。**新屏从抄一个模板开始**，换掉格子里的内容件；
不要从空 `Frame` 自由拼装——上一版这么写，产出的全是浮卡片。

### 5C · 硬规则

- **一屏只有一个 `Frame`，只有一个 Header。**
- **骨架自上而下切**：先通栏横带，带内一次竖切，格内再切。深度 ≤ 3。
- **相邻格共用一条描边。** 各画各的边、中间留缝的是卡片流，不是仪器——上一版规则与此相反，作废。
- **骨架层的竖缝一屏最多一条走向**，且上下 Zone 沿用同一条，让左右两列贯通（Template_Archive 的 26px 缝）。格内小件之间的 `Gutter` 不受此限。
- **没有未分配的底。** 每块像素属于某个格；留白只存在于格内（`Pad`），不存在于格之间。窗外的底也要指派（终端族铺字符流壁纸）。
- **一屏最多一张"主图"。** 其余图像件必须明显更小。两张同样大的图会争。
- **`Accent` 一屏不超过两处**，且必须表达同一件事（都是报警，或都是超限）。
- **圆角只属于终端族的交互件**（按钮/标签页/输入框，半径 `u`–`1.5u` 固定）。档案族全屏直角；任何族的面板和框都不允许圆角。
- **控件层不允许阴影、发光、渐变、半透明叠层。** 深度只能来自坡道。生物档案屏那种辉光是相机后期 bloom 的事，加在 Volume 上，不加在控件上。

### 5D · 密度

一屏的信息密度按"**几块**"算，不按"几个控件"算：

| 尺寸 | 块数 | 例 |
|---|---|---|
| 小（≤ 480 宽） | 3–4 | 一个 TitleBar + 一张图 + 一张表 |
| 中（≈ 720 宽） | 6–9 | 三张参考图都在这一档 |
| 大（≥ 1280 宽） | 9–14 | 超过 14 块就该拆成两屏 |

> **块数上限比什么都实用。** 这套零件很容易越拼越多，而拼到十几块之后，
> 再正确的令牌也救不回来——画面从"仪器"变成"控制面板截图"。

## 6. Unity 落地

### 6A · 目录

```
Assets/RootsDance/
├── Prefabs/UI/ElectronicKit/     拖拽用的预制件，按 §4 分三组
│   └── Templates/                三个骨架模板（§5B），新屏从这里抄
├── Data/Config/UIThemes/         ElectronicUITheme 资产，一个主题一个
├── Fonts/                        VT323-Regular.ttf + OFL 许可证 + TMP Font Asset
├── Scripts/Runtime/UI/Kit/       组件脚本，命名空间 RootsDance.UI.Kit
└── Shaders/UI/Dither.shader
```

### 6B · 主题怎么生效

`ElectronicUITheme` 是 ScriptableObject。每个组件挂 `ThemedGraphic`，声明自己用坡道的哪一级；
`ElectronicUIRoot` 挂在屏根上、持有主题引用，在 `OnEnable` 与 `OnValidate` 时向下刷一遍。

**换主题 = 换 `ElectronicUIRoot` 上的一个引用。** 不需要动任何预制件。
这是 §2 "组件不许写死颜色"那条规则唯一的兑现方式。

### 6C · 拖拽流程

1. 从 `Templates/` 拖一个骨架模板进场景（自带 `ElectronicUIRoot` + 切分树），指一个主题。
2. 把格子里的占位内容件换成自己的。每个内容件都是自足的，拖进格子就有正确的描边、内缩和颜色。
3. 需要改骨架时，调 `Split` 的权重或在格内再切一刀——不要把格拆成浮动卡片。
4. 图像件在 Inspector 里指定贴图与 `_Mode` / `_PixelSize` / `_Levels`。
5. 需要报警时，勾 `DataRow` 的 `Alarm`。

**没有第 6 步。** 不需要写代码就能拼出一屏静态界面；要让它动，再挂 presenter。

### 6D · 与低保真终端规范共存

两套可以在同一个项目里，但**不要在同一块画布上**。终端屏走它自己的低分缓冲 + 合成，
本库走原生分辨率。要让两者出现在同一个场景，做成两个 Canvas，各自独立。

理由在 §1：一套的前提是"信号是糊的"，另一套的前提是"仪器是锐的"。混在一起两个前提都不成立。

## 7. 判据：拼出来的东西还算不算数

不是复刻清单——这套库的产物本来就该各不相同。这是**否决项**，命中任何一条就不算数：

- [ ] 分区各画各的边、靠缝隙漂浮——屏读成了"卡片流"而不是一块被切开的整屏
- [ ] 存在未分配的底：分区之间露出空地，或窗外是纯色死底
- [ ] 骨架层出现了多条竖缝，或上下 Zone 的竖切位置各切各的、左右列不贯通
- [ ] 档案族出现了圆角，或任何族把圆角用在了面板/框上
- [ ] 控件上出现了阴影、发光、渐变或半透明叠层（整屏后期 bloom 不算）
- [ ] 有颜色不是从坡道或 Accent 取的
- [ ] `Accent` 用在了报警以外的地方，或一屏超过两处
- [ ] 描边宽度随组件大小变化，或超过 2 px
- [ ] 抖动作用到了 chrome 上，或者整屏加了一层
- [ ] 抖动格等于 1 屏幕像素（花纹看不见），或大于 6 px（成了马赛克）
- [ ] 抖动前没压对比度，图像是一片均匀花纹
- [ ] 一屏有两张尺寸相当的主图
- [ ] 数据行用点线引导，或数值不是右对齐
- [ ] 字不是 VT323（用了现代 sans/serif，或普通等宽字加 `mspace` 硬凑）
- [ ] 字号超过三档，出现了第二个字族或假粗体，或档案族出现了小写
- [ ] 块数超过 §5D 给的上限

**通过判据但看起来不对**，通常是这三处之一：骨架没从模板抄、切分不够密（屏读着"松"），
坡道被压扁了（`Ink0` 与 `Ink5` 差距不够，整屏一片灰），
或者 `_PixelSize` 没调（图像没有"被打印出来"的质感）。先查这三个。
