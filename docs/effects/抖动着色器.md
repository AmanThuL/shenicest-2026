# 抖动着色器(RootsDance/UI/Dither)

电子类 UI 组件库的图像呈现层:把任意灰度源图量化成**硬边像素网点**。
着色器在 [`Assets/RootsDance/Shaders/UI/Dither.shader`](../../Assets/RootsDance/Shaders/UI/Dither.shader),
由 [`KitDitherPlate`](../../Assets/RootsDance/Scripts/Runtime/UI/Kit/KitDitherPlate.cs) 驱动。
本文档回答三件事:抖动是什么、参数怎么调、**怎么验证它真的在工作**——
渲染管线的问题(材质缺失、静默回退双线性放大)会让画面呈现得跟着色器出错一模一样,
必须能把"着色器错了"和"着色器前后的管线错了"分开判断(见 §4、§5)。

---

## 1. 原理:阈值图,不是模糊

抖动(dithering)把连续灰阶换成有限色阶的**空间花纹**。本库用的都是"有序抖动"家族:
对每个屏幕像素,取源图亮度 `L`(0..1),与一张平铺的**阈值图** `T` 比较,
`L + T` 落进哪一级就量化到哪一级。阈值图不同,花纹就不同:

| `_Mode` | 阈值图 | 花纹 | 对应参考图 |
|---|---|---|---|
| 0/1/2 | Bayer 2×2 / 4×4 / 8×8 矩阵 | 规则棋盘/斜点,每个色阶有固定纹样 | 警用档案屏(眼睛,6 级) |
| 3/4/5 | 聚簇网点(圆/菱形/线),spot function 距离场 | 网点在固定格里长大缩小,印刷感 | 终端浏览器(1 bit) |
| 6 | Interleaved gradient noise(近蓝噪声) | 无周期散点,亮密暗疏 | 生物档案屏(1 bit) |

Bayer 矩阵是递归构造的 2^n 方阵,把 0..1 阈值均匀打散在空间里——这是它花纹"规则"的原因;
蓝噪声则刻意无周期,散点不成团。参考资料:
[Ordered dithering (Wikipedia)](https://en.wikipedia.org/wiki/Ordered_dithering)、
[The Art of Dithering and Retro Shading (Maxime Heckel)](https://blog.maximeheckel.com/posts/the-art-of-dithering-and-retro-shading-web/)、
[Building a Real-Time Dithering Shader (Codrops)](https://tympanus.net/codrops/2025/06/04/building-a-real-time-dithering-shader/)、
[GLSL 8x8 Bayer matrix dithering (martins upitis)](http://devlog-martinsh.blogspot.com/2011/03/glsl-8x8-bayer-matrix-dithering.html)、
[glsl-dither (hughsk)](https://github.com/hughsk/glsl-dither)。

**判断输出对不对只有一条标准:结果里不允许存在任何平滑渐变。**
每个像素要么是 N 级色阶中的一级,过渡全部由花纹密度表达。
输出里还看得到渐变 = 抖动没有生效,像"高斯模糊"= 源图被默认材质直接双线性放大了。

## 2. 关键实现点(为什么长这样)

- **花纹活在屏幕空间**:阈值按 `positionCS.xy / _PixelSize` 取,不随 RectTransform 缩放,
  网点永远是整颗屏幕像素。源图按网点格中心采样(`floor(uv/lattice)+0.5`,用 ddx/ddy 求
  每屏幕像素的 UV 步长),让图像和花纹落在同一格点上——否则一个网点跨两个源色调,边缘发糊。
- **`_PixelSize`(2–3)比 `_Levels` 重要**:= 1 时花纹小于视网膜分辨率,图像只是"变脏";
  ≥ 6 时变马赛克装饰。参考图实测 2–3 px。
- **抖动前先压对比**(`_Contrast`,抖动后再调会毁花纹):正常曝光的照片中间调占绝大多数,
  不压的话整块板子是一片均匀花纹。参考图三张都把亮部推到纯白、暗部压到纯黑。
- **量化结果映射到主题坡道两级**(`_ColorLow`/`_ColorHigh`,由 `KitDitherPlate.Apply`
  从 `ElectronicUITheme` 写入),板件因此跟整屏一起换肤。
- **源图本身必须高对比、有结构**。第一版程序纹理是平滑 Perlin 团,任何抖动都救不回
  "源图里没有边缘"——现在的 `T_PlateIris/Finger/Circuit/Figure` 都按线稿/硬掩膜生成。

## 3. 参数速查

| 参数 | 值域 | 说明 |
|---|---|---|
| `_Mode` | 0–6 | 见 §1 表 |
| `_Levels` | 2–16 | 量化级数;2 = 1 bit。警用眼睛 6,其余参考图 2 |
| `_PixelSize` | 1–12 | 网点格边长(屏幕像素),**先调这个**,实测 2–3 |
| `_Angle` | 0–90 | 网屏角度,仅半调 3–5 生效 |
| `_Contrast` / `_Brightness` | — | 抖动**之前**的曝光压缩 |
| `_ColorLow` / `_ColorHigh` | — | 量化两端映射色,来自主题坡道 |

## 4. 验证管线(改着色器后必跑)

`RootsDance.EditorTools.KitDiagnostics.Run`(批处理可用)会:

1. 生成一张**测试卡**(线性渐变 + 8 级硬阶 + 软球体 + 噪声)存到
   `Logs/UIKitShots/Diag_TestCard.png`;
2. 用 `Graphics.Blit` 把 7 个 `_Mode` 各跑一遍存 `Diag_Dither_Mode0..6.png`——
   这条路径**不经过 Canvas / 主题 / 预制件**,输出只由着色器决定;
3. 把每个 Kit 自绘组件单独摆进最小捕获场景渲一张 `Diag_Primitives.png`;
4. 打印三个主题资产的实际序列化颜色。

读法:测试卡的"线性渐变"条在输出里必须变成纯花纹密度过渡;"软球体"必须没有任何
平滑边。若 Blit 输出正确而画面里仍是糊的,问题在管线不在着色器(见 §5)。

## 5. 已踩过的坑(症状 → 根因)

| 症状 | 根因 | 修复 |
|---|---|---|
| 板件是平滑灰度,像高斯模糊 | RawImage 没拿到抖动材质,静默回退默认 UI 材质双线性放大 | `KitDitherPlate.EnsureMaterial` 在材质缺失时直接从 `Shader.Find` 自建实例并告警 |
| 所有自绘描边/规则线不可见 | `AddComponent<KitElement子类>` 没有自动补 `CanvasRenderer`(基类 `RequireComponent` 未生效),无 CanvasRenderer 的 Graphic 静默不画 | `KitElement` 显式 `[RequireComponent(typeof(CanvasRenderer))]`,builder 的 `NewRect` 一律预挂 |
| 批处理截图第一张全黑、后几张正常 | HDRP 自动曝光逐帧适应,冷启动第一帧压暗数档 | 捕获前提交 8 次 warm-up render request |
| 截图整体偏暗 | RenderTexture 未显式 sRGB | `RenderTextureReadWrite.sRGB` |
